Rater: glm-5.3-flash

Score: 8/10

## Reasons
Cold USE rating of nova-update at source snapshot 0c5803c2de406c1b0b2b0841f579c9bf73406b1c (the staged HEAD equals the rated sha; every binary built from that checkout with `go build -o <rater bin> ./cmd/...`). All commands ran in the rater's own scratch directory against hand-written or example-written manifests; nothing real was touched: no store, no remote, no bus, no network source, no provider credentials in the process environment, and every apply was `--dry-run` except the one whose apply argv was a two-line script inside the scratch directory.

What carries the score to 8: the local story works end to end and names the next step at every turn. `nova-update example --out versions.tsv` writes a one-tool manifest and prints `EXAMPLE NOTE next: nova-update report --file versions.tsv`; report, status and check on that manifest answer in one line each with the counts the help promises, and `apply --file versions.tsv go --dry-run` prints the plan and provably writes nothing (the version file still read v2.0 after a later dry-run). Refusal quality is the best part: a missing --file, an unknown flag, an unknown verb, a bad --max value, a manifest with two bad lines, an adoption ledger with a wrong state word, apply on an entry whose apply column is none, --version on an apply argv without {version}, and `release cut --dry-run` with no flags each name their problem; the two-bad-line manifest and `release cut` name EVERY problem at once, each line with its line number, and every refusal ends with the exact next command (`run: nova-update check -h`, `run: nova-update help`). --json is on every verb but watch and release exactly as the help says, and the JSON mirrors the lines: the same facts object, the same items, plus remedy and why arrays a program can act on without guessing. A local fake upgrade completes and rechecks: status says STALE exit 1, apply runs the entry's argv, re-reads the version, and exits 0 when the box sits on target; the following status says EQUAL exit 0. Watch without a bus is a pure local pass: one ADOPT OK line per check and an ADOPT DONE summary with a sha and counts, everything on stdout, stderr empty. Exit codes match the help byte for byte: 0 current or plan printed, 1 the tool said NO, 2 refused with a remedy.

What keeps it from 9 and 10: the pin reader silently mis-parses a pattern the help itself advertises. A pin whose installed column is `go version` and whose latest is `local:go version` reports installed=version latest=version -- the second token of the version line is taken as the version -- and counts the entry CURRENT with exit 0, so an AI pinning that way is told a lie with a green exit. The binary also cannot vouch for its own build: built from 0c5803c2de406c1b0b2b0841f579c9bf73406b1c, `nova-update version` prints v1.1.0-dev.2ced4eea, a stamp that matches no checkout an AI can see, so provenance of the running binary cannot be confirmed from the tool alone. Smaller: latest refuses a bare literal version, the natural way to name a fixed target, and its remedy names only the four locators rather than the two routes that work (apply --version, or a local: wrapper that prints the version); and two bad flags surface one at a time, the unknown flag masking a missing --file until the next run.

A 10 needs: a pin read that takes a version-shaped token or refuses loudly when the token is not version-shaped; a version stamp that identifies its own build; a bare version in latest accepted as a literal target or a refusal remedy that names the --version and local: routes; and flag refusals that list every problem at once, as the manifest reader already does.

Not tried, so not rated: `report --store <host:port>` (needs a store; no disposable container was assigned to this rating, so core store coverage is untested), watch's delivery path (--bus with --remote, --branch, --as and --to; needs a bus checkout and a remote) and report --draft/--send/--snapshot (same), the release verbs beyond the refusal probe (they act on the project's own release pipeline, its forge and ssh machines), and every network latest source (github:, npm:, brew:, ollama:): every read this rating made was local: on this host.

## Good, keep
- The refusal discipline: every refusal names its problem, the valid vocabulary, and the exact next command; manifest refusals and release refusals name every problem at once, each with its line.
- `example` writes a working manifest and prints the next command; `--dry-run` prints the plan and provably writes nothing; `--json` mirrors the line output with remedy and why arrays on every verb but watch and release.
- The local apply loop (status STALE exit 1, apply runs the named entry only, recheck EQUAL exit 0) and watch's bus-less local pass, all on stdout, with exit codes exactly as the help documents them.
