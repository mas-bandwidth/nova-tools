## Reasons
Cold USE rating of the binary alone, built at this snapshot (`nova-self-talk version` prints v1.0.1-0.20261003234940-0c5803c2de40, so binary and rated source agree). Everything ran in a job-local scratch directory; the tool touches no service, store, remote or credential anywhere, so nothing was unavailable. The advertised first run works as written: `nova-self-talk example ./pages` wrote the two example pages, printed the remedy command `nova-self-talk pages/journal.md`, and that scan exited 1 with one STANDING and one INSTALLATION finding, a DATED line and the NOTE, exactly as the help promises. Two own jobs then exercised the whole local subset: a mixed page holding a standing claim, an installation, a dated claim, and one line that joins a quotation with an imperative sentence (the dated line passed as licensed and the two standing claims flagged as expected; the quotation-plus-imperative line was flagged too, which became finding 1 — probed alone on separate lines, the quotation and the imperative each pass as licensed), and a flag job over `--rule-doc` (banner above that file's findings, wording as documented), `--skip` (SKIP line, skipped file not counted in files=), `--max 1` (one MORE line with its remedy), stdin via `-`, and a dash-named file after `--`. All four refusals were provoked and each names the problem, the valid alternatives and the next command: a missing argument to example, an unknown flag on the positional path, an unknown first word that is also a plausible file name (the refusal adds that it is not a verb, lists the verbs and says a file of that name is given as ./name), and a bad flag value. Unreadable files and a directory passed as a file refuse the same way, and every such refusal ends with the second line "NOTHING was scanned, which is not a green", which stops the classic misread. `--json` was tried on scan, shapes and example and matches the help's field list (result, facts, items, notes) each time; `--dry-run`, offered only on example, printed the would-be writes and wrote nothing, and its JSON remedy was directly runnable. The closing line carries the totals on every run, findings name file, line, shape and matched words, and `shapes` publishes every pattern with a sentence it finds and a near miss it passes, so an AI can predict a match without opening the code. What keeps this below 9.5 is one undocumented behavior and two uneven edges. The sentence unit around quotation marks is nowhere described, and an AI must probe to predict what one finding will quote: a line ending with `."` swallows the following line into a single sentence attributed to the first line, so an imperative the shapes table licenses gets flagged, and a writer's own sentence after a quotation on one line is flagged although the QUOTED row documents "after an opening one in its paragraph" as a licence. A file of random bytes with no readable sentence gets a bare green, indistinguishable from a clean page. Two refusal paths keep a different voice from the rest. Where I had to guess: the exact span and line number of a finding's quoted text around quotations (probed with three throwaway files; the help says only "sentence by sentence, line numbers kept"). A 10 needs one documented sentence unit that licenses what the shapes table says it licenses, no vacuous green over non-text content, and one refusal voice on every path.
