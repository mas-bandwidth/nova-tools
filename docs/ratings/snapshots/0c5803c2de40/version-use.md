## Reasons
Ran cold from the binaries and their help; the first run is real: all four example lines ran as printed (exit 0) and the example's NOTE names the next command. The banner answers the three questions, states the exit table, and each verb's `-h` matches `help <verb>`. The refusal grammar held in every probe: a missing flag reports both missing flags at once; a bad manifest reports each line's problem with its fix; an unknown verb lists the verbs; an unknown flag lists the flags; an unknown revision names the checkout and suggests git fetch; an UNKNOWN tool exits 1 and names the command to install and the PATH searched. `--json` renders the same value on example, snapshot, diff, moved and version, and even refusals render as JSON (status, why, remedy). `--dry-run` on snapshot and moved wrote nothing (verified on disk) and says so in a NOTE; MORE keeps shown and total with the widening hint; `--max 0` lists all. Costs that keep it from 10: listing under `--dry-run` still requires `--out`, so the first dry-run guess was refused and a dummy path had to be tried; the promise that one run reports EVERY problem of a manifest at once missed the duplicate name on line 4 while lines 2, 3 and 5 were named (that same duplicate is named when the file holds only it); report and send take no `--json`; moved's counts (`verbs=205` beside `added=0 deleted=0 renamed=0`) are unexplained; the invalid-latest remedy omits the `-` the help allows; files without the nova- prefix are skipped silently in `--bin` mode. Not tried: send, report `--send` and `--snapshot` recovery (they need a real bus checkout and a remote), and the github, npm, brew and ollama lookups (network); send is judged from its help, which states its required flags and its delivery effect. A 10 needs: a dry-run listing without a dummy `--out`, cross-entry problems named with the rest, `--json` on report and send, self-explaining counts, and remedies that name every option the help states.
