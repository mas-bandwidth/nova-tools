## Reasons

The source under review is exactly 0c5803c2de406c1b0b2b0841f579c9bf73406b1c; the staged checkout's HEAD is that commit, and `nova-swarm version` prints `nova-swarm v1.0.1-0.20261003234940-0c5803c2de40 linux/amd64 go1.26.6`, so the binary's provenance matches the rated snapshot. Everything below comes from the binaries and their help in one job-local scratch directory: no model call, no real child, no store on the network, no remote, no gh, no key of anyone's; provider and store credentials were unset in the environment before the first command. The two spend verbs (native, member) are judged from help alone, and member is not tried at all: its advertised example contacts a server address and there is no dry-run to make the attempt safe.

The supported local subset is close to exemplary for an AI. The advertised first run (`template --name read-pr`, `template --name worker`, `lint --rules`) runs exactly as the help promises, with no setup. Refusals name the problem: a missing required flag prints every missing one at once with what each wants; an unknown flag and an unknown verb name the bad input, list the legal set, and end with the next command to run (`run: nova-swarm help lint`); bad values say wants with an example (`--for wants a positive duration such as 30m, got "5x"`). `lint --rules` documents every rule token with its remedy, and the `--fleet` remedies carry the incidents that earned them. `worker check` refused a real hazard (a key file inside `worker_dir`, copied into every job) with the fix spelled out. Lint drifts name line numbers and arrive all at once.

What costs the points: `verify`, the verb every finish is judged by, accepts any line 1 whose text equals `--contract` — the result template's unfilled `# <task>` heading passes as `RESULT OK` while the required `--label` appears nowhere, so an AI that trusts the exit code is not trusting what it thinks it is. The spend verbs offer no `--dry-run` or `--json` anywhere in their help, and native's own example fails as written. `slots take --kind sweep` silently asks for 4 seats per slot (want=8 for --n 2) and no help text or refusal says so; the release path prints the help's two outcome words in the wrong situations (a live holder gets `SLOTS RELEASED released=0`, and the `--force` release prints `SLOTS KEPT` first). `profile` answers `jobs=0` with exit 0 for any input, including a real file path whose timeline format the help never states. Small ones: `worker -h` prints no flag list though its usage line shows --env and --max; an entirely unfilled template card passes `lint --child-rules` with exit 0 (placeholders are NOTE advice only); `slots list`'s `stranded=` field is undocumented; `--base-check`'s deadline-p95 line claims no DEADLINE: line on a card whose `Deadline: finish within 30 minutes.` passes the same lint, and never says the missing `--p95` table is the actual cause.

A 10 would: enforce the `RESULT: <label> sha=<sha12>` shape and the label in `verify`'s verdict line; say which evidence (`--p95`, `--legs`) is absent, not just which line; state the per-kind slot cost in `slots take`'s help and refusal; emit the outcome words the help promises; fail loudly when profile parses zero of the files it was handed; add a parse-and-exit path to native and member that touches nothing; and list worker check's flags in its help.
