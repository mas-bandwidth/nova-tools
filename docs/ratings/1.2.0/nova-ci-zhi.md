# nova-ci READ and USE rating, nova-tools 1.2.0

Rater: deepseek/deepseek-v4 in dsh, the DeepSeek Harness headless runner, a sprint worker on a friend's re-rate card
Build: 9c9b2ebc49fd
READ: 7.5/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of the `sprint/mechanical-2026-10-02` branch. `nova-ci version` prints `nova-ci v1.0.1-0.20261007202756-9c9b2ebc49fd linux/amd64 go1.26.6`. The binary was built from a cold clone and run on a Linux bench; the banner and every verb's `-h` were read cold, then the verbs were used for real on a throwaway Go module made only for the trial (a fast test, a slow test, a test skipped with the SLEEPS marker, a functional-tagged test, and a directory whose only Go file is functional-tagged) and on a scratch checkout for `local --dry-run`, `new-rule --dry-run` and `new-verb --dry-run`. `github receipt` was used only through `--dry-run`, so no store was dialled; the real `local` run and the real scaffold writes were not made, and no server was started.

## Reasons

READ. The banner is about one screen: line 1 says what the tool does, the `how it works:` paragraph names its nouns (a `go test -json` stream on stdin, a per-package budget, this repository's own CI steps) and where state does not live, `first run:` needs nothing, and every verb is listed with its flags and its effect word (inspection, local write, delivery, store write). Each verb's `-h` quotes its own banner excerpt, its flags with what each wants, its own exit paragraph and its effect; the exit paragraphs for slowtests, local, functional, new-rule, new-verb, version and github receipt are the right ones, and `github -h`/`github receipt -h` route through the same grammar. Refusals name every problem at once with a remedy that runs: `nova-ci github receipt` with no flags named the six missing fields, the store requirement and the `--dry-run` alternative in one line, and a near-miss flag gets `did you mean --budget?`.

What keeps READ at 7.5. `nova-ci bench -h` prints 114 lines and `nova-ci bench run -h` prints 130, because `exitTable` returns the whole banner (head and tail kept) instead of the exit paragraph, so bench is the one verb whose help an AI must wade through (finding 1). The `--allowlist` and `--sleeps` row grammar is gated to package columns beginning `cmd/`, `internal/` or `tools/`, so the ledgers cannot be written in any other Go module the banner promises to serve (finding 2). The banner still says slowtests reads "the events of the packages you name", though the verb takes no package names and reads stdin (finding 6). The CI-SLEEPS reason is rendered through the field escaper, so it escapes every blank as `\x20` (finding 4). `nova-ci version` prints a pseudo-version that names neither 1.1 nor 1.2 (finding 13), the CLI section has no `### First run` while its siblings do (finding 12), and `docs/TESTS.md` states two things the binary contradicts (findings 10 and 11). Only slowtests and bench sit on `internal/tool`'s one value, and no verb but slowtests takes `--json` (finding 14).

USE. The first run is a real transcript from the binary alone (`slowtests --example`), and the trial module showed the verbs doing their jobs: a 1.5 s test was reported both as `CI-SLOW package=... slowest=TestSlow:1.5s` and as `CI-SLOW test=TestSlow ...`; an unledgered `t.Skip("SLEEPS: ...")` was a CI-SLEEPS line and exit 1 on every leg; the empty stream was `CI-SLOW FAILED packages=0 slowest=none: looked at nothing; run: nova-ci slowtests --allow-empty` at exit 1, and `--allow-empty` made it OK at exit 0; a truncated stream named both packages "started and never ended"; `--max 3` printed three findings and one `CI-SLOW MORE kind=finding shown=3 total=30` line naming the flag that widens it. `functional ./...` printed `./` (a go test argument) and a `-run` pattern; `local --dry-run` printed the base, the merge base, the two selected packages and the exact `make test` line; `new-rule --dry-run` and `new-verb --dry-run` listed their files and wrote nothing; `github receipt --dry-run` printed the receipt line with `ev=-` and a note that nothing was dialled.

What keeps USE at 7. In a module that is not this repository the ledgers refuse every row (finding 2), and a package whose only Go file is a functional-tagged `_test.go` is dropped from the selection, so the functional tier runs nothing for it in silence (finding 3). `nova-ci functional ./...` in this checkout prints one `-run` argument of 28,679 characters naming 688 tests, with no bound and no file to read it from (finding 5). The bench refusals leave the house grammar (`CI REFUSED:`, `BENCH-RUN REFUSED:`) where the tool's own verbs print `nova-ci <verb> REFUSED:` (finding 8), and an unknown verb names no nearest while an unknown flag does (finding 9). The `sleeps` item and the facts drift from the lines in `--json` (finding 7). A 10 would fix bench's help, the ledger gate, the functional-only package, the single unbounded run pattern and the JSON drift, and would put every verb on the one value with `--json`.

## Good, keep

The first run runs from the binary alone: `slowtests --example` reads a built-in stream and prints a CI-SLOW finding and a CI-LOAD line with nothing installed, and the transcript in `docs/TESTS.md` is executed, not written. The status grammar is one line per event with exact totals: CI-SLOW, CI-SLEEPS and CI-LOAD, and a `--max` cut always ends in a `CI-SLOW MORE shown=<n> total=<n>` line naming the flag that widens it. The empty stream is a loud FAILED with the remedy `run: nova-ci slowtests --allow-empty`, a truncated stream names every package started and never ended, and a refusal renders as the same value in `--json`. The refusals name every problem at once with a command that runs, and every write verb offers `--dry-run` whose output is the plan: `local --dry-run` prints the base, the merge base, the packages and the exact `make test` line, and `new-rule`/`new-verb --dry-run` list their files and write nothing.
