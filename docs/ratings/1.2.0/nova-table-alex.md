# nova-table READ and USE rating, nova-tools 1.2.0

Rater: deepseek-v4.1-flash in opencode, a sprint worker on a friend's re-rate card
Build: c76fcb249cc1
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-table version` prints `nova-table v1.0.1-0.20261007015429-c76fcb249cc1 linux/amd64 go1.26.6`. Built and run on a Linux bench machine. The root help, `help <verb>` and all 35 verb and subverb `-h` pages were read cold, and the guide and spec were read with them. The tool was then used for real on a throwaway directory under the job, store-less: the banner's `--dry-run` example, every write verb under `--dry-run`, every argument and flag refusal, `batch` plans, `shell` from a pipe, and the read verbs' no-store refusals. No live store was touched and no server was started on this machine, so the reads, `watch`, `shell` and the stateful write paths were judged from help, source and the store-less forms rather than run end to end.

## Reasons

READ. The banner says in one line what the tool is, then in five lines how it works, then what a first run needs and a store-less `--dry-run` example. Each `-h` page carries usage, an example, its flags grouped as flags / connection / write epoch and receipt, exit codes and an `effect:` line. Every help form answers with no store: `help cell`, `cell -h`, `help cell add`, `--version`. An unknown verb, subverb, flag or argument count is refused with the full verb list or the verb's flags and a `run:` line. The column grammar, the fold rules and the formulas are stated once in the banner and once in the spec, and the argument checks are exact: a duplicate column, a formula naming a missing column and a non-numeric `--score` are each refused before anything is sent.

What keeps READ at 7. The banner is 127 lines, and the column grammar, fold table, epoch rules and shell rules still come before the `example:` block, which is the reader's actual first run. The same 385-character `effect:` sentence is repeated on 22 write pages, and on the three view verbs it promises what "only the store can check (the table, its epoch, its rows and columns, a bound cell)" — none of which a view has. `--score` and `--at-epoch` print as `<string>` where they take numbers. `check -h` says only that it "reads the store, writes nothing" and never names what it checks or what a failure looks like. `--json` reaches only `batch` and `member read`, so a program parsing `show`, `list` or `cell members` reads drawn text. The dated quotations of the owner still open comments in the general renderer and the order verbs. The guide now opens with a statement of the design (`docs/nova-table/README.md:3`), which is the improvement the last rating asked for.

USE. Cold use with no store permitted and no server started: `--dry-run` is real enough to run jobs end to end. The banner's example ran, and every write verb's plan printed the exact call it would send with `dialled=0 written=0`, refusing exactly where the real run refuses before sending (a duplicate column, a `pct` naming a missing column, a bad `--score`, a bad `--every`). `batch --dry-run` prints a typed plan and `--json` a single object. `member read --json` prints a refusal as one JSON object. Every refusal met (missing flag, unknown flag, unknown verb, bad value, bad address, unreachable address, read with no store) names the problem and one runnable next command; the read-with-no-store refusal prints the whole throwaway-store recipe with the `redis-server` path it resolved.

What keeps USE at 7. A read verb cannot be tried at all without a daemon: `--redis mem:` is refused ("not an address: its port is not a number"), so `list`, `show`, `render`, `check`, `cell members`, `member find`, `watch` and `shell` were judged from help and source. `shell --dry-run` is refused `--redis <addr> is required` before it plans anything, so the one verb whose help promises every write line is planned cannot be planned store-less. Some outputs claim more than happened: `cell remove` of a member that is not in the cell prints the same `TABLE CELL ... n=` line and exit 0 as a real remove; `cell move` from a column to itself prints `TABLE MOVE ... from=a to=a` as if it moved; `watch --out` succeeds with no line at all, so a caller cannot tell a written frame from nothing; a view's summary line prints a literal `-> ETA` with no value. A malformed `batch` manifest exits 1 (code=OPERATION) where usage is 2, and names only the first missing key. Member records are shared by every table on the default `--member-prefix`, and the help never says so, so a `member find` in one table can call a member placed in another `unplaced`. A new epoch starts with no rows and the banner's epoch paragraph does not say rows are per epoch.

A ten: the banner cut to its three answers and its example; the grammar written once and pointed at; `--json` on every verb from the value it already renders; `check -h` naming the invariants; no-op writes that say they did nothing; `watch --out` printing the frame it wrote; a store-less or embedded store so the reads run end to end; member identity scoped the way the help describes.

## Good, keep

The store-less `--dry-run`: every write verb prints the exact call it would send with `dialled=0 written=0`, and refuses a duplicate column, a `pct` naming a missing column, a bad `--score` and a bad `--every` exactly where the real run would. The refusal grammar: one line, every problem, a remedy that runs, and the whole throwaway-store recipe with the resolved `redis-server` path on a read with no store. Layered help (`help cell`, `cell -h`, `help cell add`) that answers with no store, and the shared command list (cmd/nova-table/help.go:20) that keeps help and the dispatcher from drifting. `batch --dry-run` with `--json` printing one typed plan object, and `member read --json` printing a refusal as one JSON object. The column grammar stated once in the banner and once in the spec, with exact argument checks before any send.
