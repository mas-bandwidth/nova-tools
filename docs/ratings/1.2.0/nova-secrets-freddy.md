# nova-secrets READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: c7257c468a7a
READ: 6/10
USE: 6/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-secrets version` prints `nova-secrets v1.0.1-0.20261006145440-c7257c468a7a linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch directory made for the trial with HOME pointed into it, against the real `sops` 3.13.3 and `age-keygen`; no live store, no server, no network. The banner's setup ran as printed, then every verb: keygen (three seats and a recovery key), names (lines and `--json`), check (green, and red on a plaintext file, a commit ahead of upstream and an uncommitted rule), exec (with `--only`, `--only all`, `--require`, a failing command, a missing command, a wrong key, a detached HEAD and a 0644 key), seal (`--dry-run`, `--no-pr`, and its value guards), seat add, seat inject (`--dry-run`, `--no-pr`), gate, place (`--dry-run`, and a real run through a stand-in `ssh` that only reads its stdin) and placed. The pull request road of seal and seat inject (`gh`, push, wait, merge) was not run, because it needs a forge.

## Reasons

READ. The banner says what the tool is in one line and how the store is shaped in five, then gives a setup a stranger can paste into an empty directory: it ran here as printed and made a store with a recovery key, a seat rule and a tracked upstream. Every verb answers `-h` with its banner lines, an `effect:` line that says what it reads, writes and never prints, its flags with `(required)` and defaults, and the exit table. exec's and check's `-h` carry the store prerequisite, why it exists, and the three repair commands, so the most common refusal is answered before it happens. Unknown verbs and flags list what exists and name the `-h` to read.

What keeps READ at 6. The help leads a stranger into a circle. The banner's `first value:` (cmd/nova-secrets/main.go:114) seals into a store that has no seat file yet, and seal refuses that by design (`a new seat is given its first values by seat add, never by seal`); seat add in turn needs a `--from` seat this machine can open, which a new store does not have. Meanwhile check and names, on the same empty store, say the opposite: `seal writes a seat's first value: run: nova-secrets seal ...` (internal/secrets/seatfile.go:190 and :193). Nothing the tool prints says that the first file is a hand `sops -e`; the spec's own first run (docs/SPEC-SECRETS.md:1122) assumes a store somebody else already filled. check's `effect:` says it decrypts this seat's file with `--key` to prove it opens (cmd/nova-secrets/main.go:161); it does not (USE, below). The first value and every example still name `/opt/homebrew/bin/sops` and `/opt/homebrew/bin/age-keygen`, while setup and the flag text say `command -v`; and an absent sops is refused with `run: brew install sops` on Linux too (internal/secrets/sops.go:46). `seat -h` prints the whole banner instead of the seat subverbs (cmd/nova-secrets/seat.go:26). place's `--dry-run` line talks about seal and seat inject (cmd/nova-secrets/main.go:186). Every verb's `-h`, version's and names' included, ends on an exit table about check, exec and 125. The spec still says "Five verbs" (docs/SPEC-SECRETS.md:10), "about two hundred lines of Go" (docs/SPEC-SECRETS.md:34) over a 5,162-line package, and "Ten rules" (docs/SPEC-SECRETS.md:1161) above thirteen; the package doc still names four verbs (internal/secrets/secret.go:2).

USE. Once a seat file exists, the tool is good to use. exec put exactly the `--only` names in the child's environment and nothing of sops, passed the child's exit 1 through, and refused at 125 with a next command for an unknown name, a missing `--require`, a missing program, a detached HEAD, a commit ahead of upstream and a 0644 key (`run: chmod 600 <key>`). names read the names with no key, and `--json` printed the same result as one object. check went red, exit 1, on an untracked plaintext `leak.yaml` without printing its value, and on an unpushed commit with `run: git -C ./secrets pull --ff-only`. seal refused a lower-case name, an empty value, a multi-line value and a missing terminal, each with why; `--no-pr` left the value on a `seal/` branch and said in a NOTE that exec does not see it yet. seat add wrote the rule before the encrypt, and the new seat's key opened its file while the source seat's key could not (`sops failed: exit 128 (transcript withheld ...)`). It refused an existing seat file and a public key that already belongs to another seat. place sent the value on ssh's stdin (9 bytes, no argument) and wrote a 0600 receipt that placed lists back.

What keeps USE at 6. A fresh store cannot get its first value from the tool: the seal the banner prints refuses, and the two refusals point at each other. check is green when the key opens nothing: `check --as ada --key <a key on no rule>` is `SECRETS CHECK OK ... mine=0 foreign=2`, exit 0, and the exec that follows fails; with another seat's key, `check --as bo` is green `mine=1`, counting ada's file. `recipients=3` on that line counts the whole store, not the seat. place still reads gate's seven-field registry as its own three-field one and plans `path=linux/amd64/.config/nova-secrets/GH_TOKEN.env`, exit 0. gate still refuses outside the house grammar, `GATE REFUSE rule=0 file=: --base nonesuch does not name a commit ...` with no `run:`, and its registry rows (seven fields, four roles) are only learned from refusals. `--json` is still names only. Progress lines (`seal: reading ada.yaml`, `seat add: writing the rule ...`) still sit outside the grammar on stderr. `placed` for a machine with no receipts, or with a receipts directory that does not exist, is `SECRETS PLACED OK count=0`, exit 0. place's unknown-machine refusal ends `add it there` with no `run:`. keygen without `--store` prints a rule for `recovery.yaml` with `<recovery key>` in it, and its NEXT line says "these two lines" over three. exec still carries a refusal for another tool's table column (cmd/nova-secrets/exec.go:52).

A 10 would give a fresh store its first value with one printed command (or make seat add take a first file from the operator's own key), make every refusal for an absent seat file name that same command, make check red when `<as>.yaml` exists and `--key` does not open it, make the examples run as printed on any OS, refuse a registry row of the wrong shape in place, put gate's refusals in the house grammar with a remedy, and bring the spec's counts and the package doc up to the code.

## Good, keep

The store prerequisite in exec's and check's `-h`, with the why and the three repair commands, and refusals that name them: the ahead-of-upstream refusal is a paste-ready `git -C ./secrets pull --ff-only`, the key-mode refusal a paste-ready `chmod 600`. exec gives the child exactly the `--only` names and passes its exit through, and keeps its own refusals at 125 so a caller can tell them apart. No verb printed a value anywhere, a wrong-key sops failure included. seal's value guards (empty, multi-line, lower-case name, no terminal) each say why. seat add writes the rule before the encrypt and refuses to overwrite a seat file or to reuse another seat's key. place sends the value on stdin and keeps a receipt that names the sealed blob and never a hash of the value. `names --json` prints refusals as the same object.
