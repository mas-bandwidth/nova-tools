# nova-bus READ and USE rating, nova-tools 1.2.0

Rater: a cold rater, deepseek/deepseek-v4.1-flash under dsh
Build: bc9ee29ed2b0
READ: 8/10
USE: 7/10

No v1.2.0 tag is on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02, commit `bc9ee29ed2b0`; `nova-bus version` prints `nova-bus v1.0.1-0.20261007214711-bc9ee29ed2b0 linux/amd64 go1.26.6`. It was built with go1.26.6 on a Linux bench and read cold, then used for real against a throwaway Redis store bound to a high loopback port and, in a second sitting, to a Unix socket in the job's scratch directory: the `friends` and `machines` sets were seeded, a push proof was written for each name, every verb was run, its refusals included, and the store was stopped with `SHUTDOWN NOSAVE`. No live store was touched and no server ran on the workstation. A second throwaway store held the roster with no push proof, to see what a first run meets.

## Reasons

READ. The banner answers the three questions before its usage lines: line 1 says what the tool is, `how it works` names the stream, the consumer group, the log and the push gate in five lines, and `first run` names the store and the environment variable. Every verb answers `-h` with the banner excerpt, a `flags:` table, an `exit codes:` line and, for the verbs that need it, an `effect:` line; `help <verb>` prints the same page. `docs/SPEC-BUS.md` is the strongest writing in the tree: the data, the semantics, the deliveries, the token, and each rule's model are stated in the present tense, and every claim I checked in the binary was in the spec and true: the token retry printed the first `SEND OK` byte for byte and refused other arguments naming the message that went; `recv --exec` acked on exit 0 and left the message pending on exit 1 with `exec_exit=1`; `log` bounded its listing with `LOG MORE kind=message shown=20 total=27`. The refusals are the shape an AI wants: an unknown verb lists the verbs, an unknown flag lists that flag's verb's flags, a bad address names the loopback-tailnet rule, and the `deaf:` refusal names every unheard name in one run with the friend-daemon command to fix it. What keeps READ at 8: the first-run line and the `--max` line in the banner are not true of the binary, two effects are the wrong kind, the exit table for `overdue` names a word the tool never prints, and several shapes (`--re`, `--id`, a subject with a newline) are accepted without a check.

USE. The loop works end to end on a throwaway store: `wait` arms on an empty stream and prints `WAIT ARMED after=0-0` then `WAIT NONE` at the timeout; `send` writes one entry per recipient and the log; `peek` shows the message new before delivery and pending after; `recv` prints the header, a blank line and the body; `--exec true` acks it; `ack` on an unknown id is `acked=false` at exit 0; `log`, `names`, `receipts` and `overdue` read back every state the tool writes. The token retry, `--dry-run` on send/recv/ack, the kind filter, `--stdin` with its trailing newline kept, the 1 MiB body bound and the `MORE` line all behaved as the help says. The store, the address rule and the push gate are the right design for a bus an AI runs beside a session. What keeps USE at 7: the store the banner's first run describes is not enough to run a single real line, and even `--dry-run` refuses there, so there is no store-free way to meet the tool; `peek` and `ack` answer a name no roster holds; `recv --all --json` and `wait --json` leave the one output shape; and a plain `recv` hides the message it holds from the next `recv` for fifteen minutes without saying so. A 10 would make the first run runnable, close the roster and shape gaps, and make every `--json` one envelope whose status word matches its exit.

## Good, keep

- The `how it works` block and the exit table in the banner, and `docs/SPEC-BUS.md` under them: the design is written once, in the present tense, and the binary matches it on every path I exercised.
- The refusal grammar: one line, the problem, the wanted value and a `run:` remedy. The `deaf:` line names every unheard name in one run and the friend-daemon command that fixes each; the bad-address line names the loopback-tailnet rule; the unknown-flag line lists that verb's flags.
- `--json` on every verb but `help` and `version`, rendered from the same value as the lines, and `MORE`/`totals` on every bounded listing (`log --max 1` -> `LOG MORE kind=message shown=1 total=4`).
- The token retry: the same token and arguments printed the first `SEND OK` line again byte for byte with `id` and `at`, and the same token with other arguments was refused naming the message that went; the store, not the process, holds the record.
- `--dry-run` on `send`, `recv` and `ack` prints the plan the real run would take (`dry_run=true`) and writes nothing.
- `recv --exec` acks on exit 0 and leaves the message pending on exit 1 with `exec_exit=<n>` in the line, so a delivery command's failure never loses the message.
- `names` states each name's push as proven, stale, down or none with its age and harness, so the gate's inputs are readable before a send.
- The `wait` cursor design: `WAIT ARMED` prints the cursor first, `WAIT NONE` and `WAIT OK` print the id to re-arm with, and the wait reads past the cursor with `XREAD`, never the consumer group, so a later `recv` still gets what the wait saw.
