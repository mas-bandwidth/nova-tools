# nova-tokens READ and USE rating, nova-tools 1.2.0

Rater: deepseek/deepseek-v4 under dsh, a cold reader on a friend's re-rate card
Build: 9c9b2ebc49fd
READ: 7/10
USE: 7.5/10

No 1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of `sprint/mechanical-2026-10-02`. `nova-tokens version` prints `nova-tokens v1.0.1-0.20261007202756-9c9b2ebc49fd linux/amd64 go1.26.6`. It was built and run on a Linux bench, in throwaway directories made for the trial; no live store was dialled and no server was started. Every verb was exercised: `fold`, `check`, `sum`, `sources`, `report` (local mode, with and without `--note` and `--dry-run`), `session`, `profiles`, and `ledger --dry-run`; the Claude, OpenCode, provider (CSV and JSON) and swarm readers all folded a real fixture, a bus note folded through `sources` and `fold`, and the two Redis verbs were run against a closed port to see their failure. Nothing was removed outside the trial directories.

## Reasons

READ. The first line is the README's own sentence for the tool, and the banner answers the three questions in order: what it does, how it works, and a `setup:`/`example:` block a stranger can paste. Every verb has its own file now, and every verb answers `-h` with its usage excerpt, its example, an `effect:` line saying what it writes, its flags and the exit table. `check`'s paragraph is the best thing here: a gap is counted, a person's `README.md` is a note and not a stray, and both counts stay on the line so neither door can lie. The dash rule, the shrink refusal and the same-provider overlap refusal are stated where a reader meets them.

What keeps READ at 7. The normative documents disagree with the binary and with each other on the one rule the tool is built around. The banner (cmd/nova-tokens/main.go:127-131) says "Two declared sources of one provider that feed the same message ids are refused before any day file is written ... so check and sum never see a doubled day"; `docs/CLI.md:1937` says a fold that sees two sources feed one id "is a warning, not a correction: the numbers are still doubled and `check` and `sum` are all green about it"; and `docs/SPEC-TOKENS.md:1055` says flatly "It does not detect overlap between sources", repeated at `docs/SPEC-TOKENS.md:443`. The binary refuses two `--claude` flags that share an id (`TOKENS REFUSED: two declared sources fed the same 1 message ids (claude:a and claude:b)`, exit 2), so the spec's own "what it deliberately does not do" is stale and the CLI guide describes the behaviour the code removed. The provider flag has the same three-way drift: `docs/SPEC-TOKENS.md:756` and its `sources` usage block at `docs/SPEC-TOKENS.md:411-413` and its demanded test at `docs/SPEC-TOKENS.md:1271` all write `--provider <label>=<file>`, while the binary only accepts `--provider <kind>:<label>=<file>` and refuses a bare label. The banner says "`--timeout` is the one flag with a default" (main.go:105) while `--weights` defaults to `1,1.25,0.1,5` (session.go, `docs/SPEC-TOKENS.md:424`) and session's `--day` defaults to every stamped day; `docs/USAGE.md:186` still says "there are no defaults and no environment variables are consulted"; and `docs/CLI.md:1928` says the help names "two exceptions" where the banner names three environment reads. The banner's `report` usage line and the spec's report block omit `--bus` and `--swarm`, which `report -h` lists and `report --swarm p=./pool` accepts; the spec's `check` usage omits `--allow-empty`; every verb's `-h` ends with the whole seven-line exit paragraph, including `version -h`, whose verb can fail none of those ways and whose `--json` refusal does not even name the flag; and `main.go:50` says "first run" a hundred and twenty lines before the lines it points at.

USE. The machine interface is much better than 1.1.0. Every verb but `version` takes `--json`, and the JSON is one envelope with one type per fact (`sum --json` prints `"input":812` and `"reasoning":null` beside `"days":1`, not strings). `--dry-run` is the real run's own plan, refusals included (`TOKENS DAY ... written=false would_write=true`, `TOKENS OK ... dry_run=true`). A missing input is named with what it wants and every problem at once; an unknown flag names the verb's own flags and `-h`; a repeated label, a missing file, a malformed export, a wrong swarm header, a no-id transcript and a day that would shrink each get a named line and the right exit. The overlap refusal now fires between two declared Claude sources sharing message ids, and it fires before any file is written. The banner's setup and all seven example lines ran as printed and exited 0. `check` counts the lock file as neither a day file nor a stray, `--through` names the stale end, `--strict` and `--no-spend` are two answers to one question and are refused together, and `sum --max` prints `SUM MORE kind=pair shown=1 total=2` with the command that widens it. A minimal OpenCode database, a Google CSV, a `grok usage` JSON, a swarm usage file and a bus note all folded to the rows the spec names.

What keeps USE at 7.5. The banner's own first run is wrong. The setup copies the transcript to `./session.jsonl`, the first example folds it into `./out`, and the `session` example adds the same message id `example-1` a second time as a `claude-session` row on `unattributed`, so `check` says `CHECK OK` and `sum` prints `input=1624` for a day that spent 812, against main.go:131's promise. The same-provider overlap rule does not cover `session --out` against a source already in the day file. `sum` over an `--out` with no day file is `SUM OK days=0` exit 0 and `profiles` over an empty root is `PROFILES OK models=0` exit 0, while `check` calls the same emptiness `CHECK FAILED` exit 1. `report`'s body goes to stdout and its `REPORT OK ... dry_run=true` goes to stderr, so a caller capturing stdout never sees the dry-run marker the help promises. `sources` prints `SOURCES OK ... unparsed=1` at exit 0 while every verb's `-h` exit table says exit 1 for "an unparsed bus line or note". `fold`, `report` and `session --out` refuse when `--out` is not there, and the `--out` help does not say the directory must exist. A `--role w` run books the row as `claude-fable-5-1/w` with the role in the repo cell, which only the spec's `:489` says; the verb's own `-h` does not. The dry `TOKENS SHRANK` line names the field `date=` where every `TOKENS DAY` line names it `day=`. A repeated `--month` is silently taken as the last value. A ten needs: the overlap rule to cover `session --out` so the banner's own example cannot double a day; one status word per exit; one field name per fact; every refusal pointing at the verb's `-h`; and docs that say what the binary does.

## Good, keep

The banner's first line is the README's sentence for the tool, word for word.

The same-provider overlap refusal fires before any day file is written and names both labels and the duplicate count; a repeated label across two kinds is refused before anything is read.

`check` cannot go green over an empty directory, counts a calendar gap without calling it a finding, counts a person's note without calling it a stray, and keeps both counts on the line so `--strict` and `--no-spend` are the only doors that turn them into findings.

A dash is never a zero, in the day file, in `sum`, and in `report`'s `usd=`; a day that would shrink is left byte-identical and the types that moved are named with both numbers.

`--dry-run` is the real run's plan with the real refusals, and `--json` renders the same one value with the same types as the lines.

Every source kind folded a real fixture: Claude, OpenCode through a minimal database, Google CSV, `grok usage` JSON with its `costUsdTicks`, a swarm usage file with its sixteen columns, and a bus note.
