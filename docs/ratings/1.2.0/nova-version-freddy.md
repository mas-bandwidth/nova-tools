# nova-version READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: ba3d867c0e31
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-version version` prints `nova-version v1.0.1-0.20261006133824-ba3d867c0e31 linux/amd64 go1.26.6`. Built and run on a Linux bench machine in a scratch directory made for the trial: hand-made bins of copied and stub `nova-*` executables, hand-written manifests and snapshots, and `moved` against two revisions of a scratch clone. No live store, no bus, no `send` that could deliver, no server.

## Reasons

READ. `nova-version help` is a good first screen: one purpose line, a five-line "how it works" that names every verb and says which half of the tool belongs to nova-update, one usage line per verb, the exit table by verb, and a four-line first run that works with the binary alone. Every verb's `-h` carries its banner excerpt, its flags, and an `effect:` line that says before the run what it touches (inspection, local write, delivery). The spec states each rule numbered and names its tests. The thirty-second bound is argued in place (internal/update/snapverb.go:21-39).

What keeps READ at 7. Most of the 1.1.0 READ findings are still there. The tool still lives inside its sibling's package, and `moved` with its helpers still fills the last 340 lines of cli.go (internal/update/cli.go:766-1109). The reference still speaks in counts the tool does not own ("the adopted 16", "the 32 `nova-*` executables", docs/CLI.md:1967,2008), and still argues the bound from one bench's timings and an issue link (docs/CLI.md:1987-1993). The source-gate comments still cite SPEC-VERSION item 6 for a rule that sits in item 4 (internal/update/snapverb.go:71,123,241). The entry comment and the reference still name two different contracts (cmd/nova-version/main.go:3, docs/CLI.md:1942). The help text adds new noise. Every verb's `-h` repeats the whole five-verb exit table, the banner states THE MANIFEST twice, and `moved -h` never says what `added`, `deleted`, `renamed` and `verbs` count, or what its default `--timeout` and `--budget` are.

USE. The first run works as printed: `example --out versions.tsv`, `snapshot --file versions.tsv` and `report --file versions.tsv` each exit 0, `example` never overwrites (`unchanged=true` on the second run), and each success suggests the next command. Refusals are strong. Bare `moved` names all four missing flags at once. A manifest with three bad lines names lines 2, 3 and 4 in one refusal. Two unreadable snapshots are named in one `diff` refusal. A `--repo` that is not a checkout and a revision that is not a commit are each named with a remedy. Every refusal ends `run:`. `diff` reports changed, removed (`to=-`) and identical sets correctly, and its `--json` carries facts and items. A symlinked `nova-*` is noted and not silently dropped. `--version` and `version` agree, and a stray argument is refused.

What keeps USE at 7. `moved`, the verb with the most work behind it, misleads in three ways. Across a revision that added `nova-bus wait`, it printed `added=0 deleted=0 renamed=0 verbs=288` while the note it wrote says `added=wait tool=nova-bus`, and `--json` carries the zero and no items. With its default bounds it refused with "repair the package at that revision" when the build simply ran out of time. With the bench's scratch filesystem out of inodes it refused with "supply a --repo this revision resolves in" and dropped git's own error. `snapshot --bin` is all or nothing. One unreadable `nova-*` file stops the run at exit 2 naming only the first bad binary, while the help's exit table promises exit 1 for an UNKNOWN tool. Three 1.1.0 findings are unchanged: snapshot's `--dry-run` still demands an `--out` it never writes, `send -h` still lists a `--draft` the verb refuses, and report and send still take no `--json`. Bad values still stop at the first one.

A 10 needs `moved`'s counts and JSON to match its note, a refusal that names the real cause (time, disk, git's words), a snapshot that records every readable binary and names every bad one together under the exit code the help promises, a `--dry-run` that needs no invented path, no flag the verb refuses, and a machine form for report.

## Good, keep
The refusal grammar: every missing flag of `moved` named in one run, every bad manifest line named with its line number, both bad snapshots named in one `diff` refusal, and every refusal ends with `run:` and the next command. The `effect:` line on every verb's `-h`, which says before the run whether the verb inspects, writes locally or delivers. `example`'s never-overwrite with `unchanged=true` and the suggested next command after every success. `diff`'s `to=-` for a removed tool and its matching `--json`. The symlink note on `snapshot --bin`, so an omitted binary is never silent. `moved`'s refusal of a revision it does not hold, naming `git fetch`.
