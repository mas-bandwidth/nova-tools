# nova-check READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: e26adab23ab1
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-check version` prints `nova-check v1.0.1-0.20261006143828-e26adab23ab1 linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch directory made for the trial: a hand-made self tree, the shipped `example-self` and `example-dogfood` fixtures copied out, a throwaway git repository for hygiene, and a stand-in `gh` script for convergence, so nothing reached the network, a live store or a server. Every verb was run, its refusals included.

## Reasons

READ. The banner says what the tool is in one line, names the two verbs that write and the one that reads the network, gives a setup block and three example lines that pass as printed, and states the exit codes once. Every verb answers `-h` and `help <verb>` with its banner excerpt, its flags, an `effect:` line and the exit codes. `--max` is now the one cap flag across the listings, with `--fail-max` kept as a named old spelling, which closes the 1.1.0 complaint about two names for one idea. An unknown verb lists the verbs; an unknown flag lists that verb's flags.

What keeps READ at 7. The spec has fallen behind the binary in the places a reader checks first: it still says every listing takes `--fail-max` (docs/SPEC.md:353), that refusals read `nova-check <verb>: <what was wrong>` (docs/SPEC.md:344) where the binary prints `nova-check links REFUSED: ...`, that failures print `LINKS FAIL` (docs/SPEC.md:96, docs/SPEC.md:458) where the binary prints `LINKS FAILED`, and "Ten record-layer checks" (docs/SPEC.md:317) beside a verb list of eleven. docs/SPEC-CHECK.md is titled and specified as `nova-dev convergence` and says `help` prints that line byte for byte (docs/SPEC-CHECK.md:13); the binary is `nova-check convergence`. README.md:54 still says these are the 1.0.0 commands and installs v1.0.0. The `-h` excerpts reflow the banner's right-hand column to the left margin, so description text reads as more usage lines, and `dogfood -h` and `dogfood record -h` carry a stray line, `nova-check dogfood record the finding`, cut from the middle of convergence's text (cmd/nova-check/main.go:126). hygiene's `--identity` is required and refused when absent, but its `-h` line does not say "(required)" (cmd/nova-check/hygiene.go:41). dogfood gate's banner says it exits 1 "with the verbs no non-author has run"; it does that only under `--require-all`, as the spec says (docs/SPEC.md:1599). `--authors` prints `<<tool> <verb> = <who wrote it>>` as its type, and repeatable flags print `<value>`. The vocabulary is still private: door, seed, floors, pit-stop ledger, the pool's identity, card kinds, gate rounds; floors only passes on the seed's own charter, so a stranger can run it only against the test fixtures.

USE. The first run is clean: the setup block and the three example lines exit 0, `quickstart` names the four next checks and what each wants, and a failing quickstart names the next command. Refusals are the best part: a bare `convergence` names all five missing flags at once, each with a line saying what it wants and why there is no default; kernel refuses a budget with no unit, a token budget with no divisor, and both units at once, in one run. corpus is exact: a malformed row, a shrunken ledger, a lost fragment and a home outside the root each get their own line with the repair, and `--json` carries the same items. hygiene found all four kinds on a seeded branch (identity, out-of-path, stray `*.orig`, two secret shapes without printing them), and its MORE line carries a runnable rerun. dogfood record refuses an undeclared verb with a "did you mean", writes a receipt, and gate closes the loop with the receipt id and both ways to clear it.

What keeps USE at 7. Some numbers are wrong and some greens are over nothing. convergence counts a ledger table's header as a row unless its last cell is the word `result` (internal/converge/sources.go:394): a two-row table, both PASS, under a `| row | status |` header reads `LEDGER now=1 rows=3 open=1`, so the stream can never reach zero. A second widening tick exits 1 and its last line is `CONVERGENCE WARN ...`, the same line the exit-0 tick printed (internal/converge/converge.go:223). `convergence --dry-run` still reads the forge through gh; only the new `--gh` flag lets an offline run point at a stand-in. dogfood gate names a verb's only receipt-writer "the author" when no author is known (pkg/dogfood/ledger.go:510). `spelling --write --dry-run` over two misspellings ends `SPELLING OK ... misspellings=2 written=0 dry_run=true`, exit 0, and `--dry-run` without `--write` is silently ignored. links and spelling over an empty directory, spelling over a glob that matches nothing, and convergence over a ledger with no table are all green with `files=0` or `rows=0`. `links --exclude ./self/sub` excludes nothing and says `excluded=0`. On a failure every line, the count line included, goes to stderr, so `2>/dev/null` shows nothing at all. A missing `--file` is a finding (exit 1) to links and a refusal (exit 2) to spelling. An empty receipt set is a third line shape, `nova-check dogfood gate FAIL:`, at exit 1, which the gate's own `-h` calls a refusal. Refusals still point at the whole `nova-check help`, and two unknown flags name only the first.

## Good, keep

Refusals name every missing flag in one run, each with a line saying what it wants and why it is never guessed. kernel will not pick a unit for the caller. corpus treats a shrinking ledger as a loss and says how to repair each finding. hygiene never prints the secret it found and its MORE line is a command to paste. dogfood gate prints the receipt id and both ways to clear an edge. `--max` is one flag across the listings, and the MORE line says how to see the rest. Every verb's `-h` has an `effect:` line.
