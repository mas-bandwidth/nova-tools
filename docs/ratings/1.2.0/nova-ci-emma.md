# nova-ci READ and USE rating, nova-tools 1.2.0

Rater: Zhi, running deepseek/deepseek-v4.1-flash in dsh (the DeepSeek Harness headless runner), a sprint worker on a friend's re-rate card; the rating is this worker's, and the file name carries the card's friend slot.

Build: a9fe2a7fd927

No v1.2.0 tag exists yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. Built and run on a Linux bench host reached over ssh, with a private GOCACHE and a scratch Go module; no live store was dialled and no server was started. `nova-ci version` prints `nova-ci v1.0.1-0.20261007223734-a9fe2a7fd927 linux/amd64 go1.26.6`.

READ: 8.5/10

USE: 8/10

## Reasons

READ. The cold read is the strong half. `nova-ci help` opens with the README's own sentence (`cmd/nova-ci/main.go:26` is `README.md:43` word for word), a five-line `how it works:` block that names the nouns and says which verbs keep state, a `first run:` line, and an `example:` block of three commands that run as printed. Every verb answers `-h` with its own usage paragraph, its flags with their units and roles, its own exit row and an `effect:` line; `slowtests -h` states the allowlist row shape and the 3x headroom bound in the help (`cmd/nova-ci/main.go:49-53`), the gap the 1.1.0 read named. Refusals are one line and name every independent problem at once with a runnable remedy: `nova-ci` alone names the verbs, `nova-ci frobnicate` names the unknown verb and the nearest, `nova-ci slowtests --budg 5` answers `unknown flag --budg; ... did you mean --budget?`, and `nova-ci github receipt` names all seven missing fields and the store need in one line. `docs/SPEC-CI.md` is normative and the class tests pin the promises.

What costs the score. `--json` is on `slowtests` alone: `functional`, `local`, `new-rule`, `new-verb`, `github receipt` and `version` all refuse it, against `docs/STANDARD.md` section 2 ("Every verb accepts --json"). `docs/CLI.md:2371` opens the nova-ci section with a summary and a three-line `sh` block and has no `### First run`, while siblings at `docs/CLI.md:1972`, `:2159` and `:2546` have one; the transcript lives only in `docs/TESTS.md:934`. That transcript says at `docs/TESTS.md:958` "only `--enforce` makes it exit 2", while the banner's own table at `cmd/nova-ci/main.go:129` and the binary say a CI-SLOW line under `--enforce` exits 1. `nova-ci bench run -h` prints the whole 130-line banner as its exit-codes block because `cmd/nova-ci/bench.go:35,40` hands the one-line `ExitTable` field the multi-line banner, and the `bench` group has its own refusal grammar (`BENCH-RUN REFUSED:` once per problem with remedy `nova-ci help`, `CI REFUSED:` for the group). The banner also says "slowtests reads the events of the packages you name" (`cmd/nova-ci/main.go:34-35`), but slowtests takes no package names; they are named to `go test -json`, whose stream it reads. `nova-ci version` answers a `v1.0.1-...` pseudo-version naming neither 1.1 nor 1.2. And `cmd/nova-ci/timing.go:1` is still a `//go:build ignore` second `main` in the command directory, reached by no shipped verb and named by neither the banner nor `docs/CLI.md`; the 1.1.0 read named it.

USE. The first run needs nothing: `nova-ci slowtests --example --budget 60 --load 4 --cpus 16` prints the CI-SLOW and CI-LOAD lines at exit 0, `--budget 120` prints OK, and `--json` renders the same run as one `{result, facts, items}` object. Real work lands in a minute: in a scratch module, `go test -json -count=1 ./slow` piped to `nova-ci slowtests --budget 1 --enforce` caught `CI-SLOW package=example.com/scratch/slow seconds=2.0s budget=1s slowest=TestSlow:2.0s` at exit 1, the same stream without `--enforce` was a measurement at exit 0, and `--test-budget 1` named the single slow test. Empty stdin is `CI-SLOW FAILED packages=0 ...; run: nova-ci slowtests --allow-empty` at exit 1, and `--allow-empty` answers OK at exit 0. `--dry-run` on `local`, `new-rule`, `new-verb` and `github receipt` prints the plan and writes nothing, and `github receipt --dry-run` prints the row with `ev=-` without dialling. Near-miss flags and unknown verbs are answered with the names there are.

What costs the score. `nova-ci functional ./...` in the checkout prints one `-run` pattern of 28,679 characters with 689 alternatives, whole, with no `--max`, no total and no file, so the output is unbounded where the standard says it is bounded and keeps its totals. A package whose only Go file is a functional-tagged `_test.go` is invisible: `go list -tags functional ./...` lists it, but `nova-ci functional ./...` answers `CI FUNCTIONAL OK packages=0 reason=no-functional-tag-in-4-dirs` (`internal/ci/functional/functional.go:49-51` continues before it reads the tagged set), so a new test-only package would silently run no functional test. A SLEEPS skip renders its reason with the field escape, so the line reads `not on the\x20SLEEPS\x20ledger\x20(no\x20--sleeps\x20given)` (`internal/ci/slowtests/slowtests.go:607-608`): prose an AI must un-escape by hand. The slowtests `--json` facts carry `load` and `cpus` but not the `per-cpu` figure the CI-LOAD line prints (`cmd/nova-ci/slowtests.go:386-392` against `internal/ci/slowtests/slowtests.go:644`), so the two renderings of one run drift. And `nova-ci version` names v1.0.1, not the release under rating.

A 10 is `--json` on every verb from the one output value; a bounded `functional` pattern with its total and a file or note for the rest; a functional selection that finds a test-only package; one refusal grammar and one line for `bench`; the field escape kept out of prose reasons; `per-cpu` in the JSON facts; the `### First run` block in `docs/CLI.md` and the right exit in `docs/TESTS.md`; the `timing.go` script gone or wired to a verb; and a version line that names the release.

## Good, keep

The banner answers what the tool does, how it works and how to use it before the usage lines, and its line 1 is the README's sentence word for word.

The one refusal line names every problem at once with a remedy that runs, and the near-miss hint is real: `--budg` answers `did you mean --budget?`, and a missing `github receipt` field lists all seven plus the store need in one run.

`slowtests --example` is a true zero-setup first run, and its line and `--json` renderings carry the same verdict; `--allow-empty`, `--max` with its `MORE` line, and the allowlist with the stated 3x bound are the standard's bounded, honest shape.

`functional` now prints `./`-prefixed directories that paste into `go test`, fixing the 1.1.0 finding, and `--dry-run` on every write verb prints the plan and writes nothing.
