# nova-ci READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 361d4451bcd8
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-ci version` prints `nova-ci v1.0.1-0.20261006144651-361d4451bcd8 linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch directory made for the trial; no live store, no server, no network. Read cold: `nova-ci help`, every verb's `-h`, `help <verb>`, docs/CLI.md's section and docs/SPEC-CI.md's bench run section. Used for real: `slowtests` over the built-in stream and over the `go test -json` events of a scratch module (`example.com/mymod`) with a fast package, a 2.5-second test, a `t.Skip("SLEEPS: ...")` test, a failing test and a functional-tagged package; `functional` over that module and over this checkout; `local --dry-run`, `new-rule` and `new-verb` (dry run in this checkout, a real write in the scratch module); `github receipt --dry-run` only (no store dialled); `bench run` only as far as its refusals, since that bench reaches no second bench by ssh (localhost fails host-key verification, the other bench name does not resolve).

## Reasons

READ. The banner's opening still answers the three questions in nine lines: what it measures, which verbs need nothing (slowtests, functional) and which need a nova-tools checkout or a store, and the first run (`slowtests --example`). It splits usage into "in any Go module" and "in a nova-tools checkout", says each verb's effect in parentheses, and gives a per-verb exit table; docs/CLI.md now carries the caveat the 1.1.0 read asked for, that slowtests checks timing and not whether the tests passed. The refusals read as well as any tool in the set: missing fields are all named at once with what each wants, and a close flag typo gets `did you mean --budget?`.

What keeps READ at 7. `nova-ci bench -h`, `nova-ci help bench` and `nova-ci bench run -h` print `exit codes:` followed by the whole 123-line banner, so `help bench` is the banner twice over: the bench tool's ExitTable is `exitTable("bench run")` (cmd/nova-ci/bench.go:35,40), and exitTable returns the banner with only that verb's rows kept (cmd/nova-ci/main.go:191), which the group help prints whole (internal/tool/tool.go:290). The slowtests paragraph states `--max` twice in a row (cmd/nova-ci/main.go:65-68 and 70-72). Every verb's `-h` says `usage: nova-ci <verb> [flags]`, dropping `<package-dir>...`, `<rule-name>`, `<tool> <verb>` and `-- <go command>`, then quotes the banner excerpt with its indentation flattened, and opens its exit lines with the whole tool's `0 done, 1 the verb said no (slowtests, local, github receipt)` before its own. The banner still says "the SLEEPS marker" without the form `t.Skip("SLEEPS: ...")`, which only docs/CLI.md gives, and still offers no word that a piped `go test` loses its own exit status. Three refusal prefixes (`nova-ci slowtests REFUSED`, `CI REFUSED`, `BENCH-RUN REFUSED`) and two effect words for one verb (`(store write)` in the banner, `effect: delivery` in `github receipt -h`; `(runs tests, writes only a temp dir)` beside `effect: local write` for local) make the vocabulary harder to learn than it needs to be.

USE. The first run is one command with no setup and both its lines are right. Over the scratch module, `go test -count=1 -json ./... | nova-ci slowtests --budget 1` named the slow package with its slowest test and a CI-SLEEPS line for the unledgered skip, exit 1; `--package-budget 0.5 --test-budget 2 --max 1` printed one finding and a MORE line naming `--max 0`; `--json` carried the same items and the why. Garbage, random bytes and `/usr/bin/ls` on stdin are each refused at exit 2 with the command that makes good input. `functional ./store ./fast` printed `./store` and a pattern that ran green under `go test -tags functional`. `local --dry-run` printed the merge base, the packages and the exact make line. `new-rule --dry-run` and `new-verb --dry-run` listed the files; a second real `new-rule foo` refused to overwrite. `github receipt` with no flags named all seven missing fields at once.

What keeps USE at 7. `--allowlist` and `--sleeps`, which the banner presents under "in any Go module", refuse every row in a module that is not laid out like this one: `example.com/mymod/slow` and `slow` are each refused with `package "slow" must be the full module-relative path`, though `slow` is exactly that; the check accepts only `cmd/`, `internal/` and `tools/` prefixes (internal/ci/slowtests/slowtests.go:404). So in my own module the unledgered SLEEPS skip could not be ledgered at all, and the run stays at exit 1. A run with a failing test prints `CI-SLOW OK packages=1`, exit 0, with no word that a test failed. The CI-SLEEPS line prints its prose reason with `\x20` between every word (`not on the\x20SLEEPS\x20ledger\x20(no\x20--sleeps\x20given)`), because the ledger text is escaped as a field (internal/ci/slowtests/slowtests.go:559). `functional ./...` still prints bare `store` where `./store` was given (the 1.1.0 defect), and in this checkout a single 28,038-character run pattern. `new-rule` and `new-verb` take any directory with a go.mod as "a nova-tools checkout": in the scratch module `new-rule foo` wrote three files, a test calling a `repoRoot` that module does not have. Refusals still name one problem when there are several: `--budget abc --max -1 --bogus` names only `--budget`. `version --json` says `got 1` without saying what it got. An unknown verb gets no nearest name, though an unknown flag does. `bench run go version` (no `--`) is refused as `takes no positional arguments, got "go"` where the fix is a missing `--`; its refusals point at `nova-ci help` where every other verb points at its own `-h`; and a host it skips is printed as `CI BENCH PASSED`, a word that reads as a green.

A 10 would print each verb's own help (its real usage line, its own exit lines, the banner excerpt with its indent) and never the banner inside an exit table, let the allowlist and the SLEEPS ledger name a package by its import path in any module, say in the OK line when the events carry a failed test, print reasons as prose, keep `./` on functional's paths, check that `new-rule` and `new-verb` are in a nova-tools checkout, and name every invocation problem in one refusal.

## Good, keep

- The refusal that names every missing field at once, each with what it wants (`github receipt` with no flags names seven), and the near-miss hint for a flag typo.
- `slowtests --example`: a first run from the binary alone, with both lines a reader will see on real input.
- Input that is not TestEvents (garbage, random bytes, a binary) is refused at exit 2 with the pipeline that makes good input, never read as an empty green.
- `--dry-run` on every write verb prints the plan exactly (`local` its merge base, package list and make line; `new-rule` and `new-verb` their files), and scaffolding never overwrites.
- The CI-LOAD line says "measured, not a verdict", and the help explains why a cached run never trips a package budget.
