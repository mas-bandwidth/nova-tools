# nova-ci READ and USE rating, nova-tools 1.2.0

Rater: Zhi, running deepseek/deepseek-v4 in dsh (the DeepSeek Harness headless runner), a sprint worker on a friend's re-rate card; the rating is this worker's, not the friend's, and the file name carries the card's friend slot.

Build: de86d1a499ea

No v1.2.0 tag exists yet. The build rated is the head of sprint/mechanical-2026-10-02, built and run on a Linux bench with a private GOCACHE, on a scratch Go module and a scratch directory: no live store, and no server started anywhere. The checkout-bound verbs (`local`, `new-rule`, `new-verb`) were run only with `--dry-run`, and `github receipt` only with `--dry-run`, so no file and no store row was written.

READ: 8.5/10

USE: 8/10

## Reasons

READ. The cold read is the best part of this tool. The banner opens with the README's own sentence (`cmd/nova-ci/main.go:26` is `README.md:43` word for word), then a `how it works:` paragraph that names the nouns and says where state lives in five lines, then a `first run:` line, an `example:` block of three commands that run, and one exit table with a row per verb. The prose is honest about the boundary: `slowtests` and `functional` are store-free, the other verbs need a checkout or a store. Every verb answers `-h` with its own usage paragraph quoted from the banner, its flags with what each wants, its own exit row, and an `effect:` line; `slowtests -h` states the allowlist row shape and now states the 3x headroom bound in the help (`cmd/nova-ci/main.go:49-53`), the gap the 1.1.0 read named. The refusal grammar is one line naming every problem at once with a runnable remedy, and the near-miss hint works: `nova-ci slowtests --example --budg 5` answers `unknown flag --budg; ... did you mean --budget?` at exit 2, and `nova-ci github receipt` names all seven missing fields and the store need in one run. The spec (`docs/SPEC-CI.md`) is normative and the tests pin the promises.

What costs the score. `docs/CLI.md:2366` opens the nova-ci section with a summary and a three-line `sh` block and has no `### First run`, while its siblings at `docs/CLI.md:1967`, `:2154`, `:2541` and `:2741` all have one; the first-run transcript lives only in `docs/TESTS.md:934`. That transcript's prose says `docs/TESTS.md:958` "only `--enforce` makes it exit 2", and the banner's own table (`cmd/nova-ci/main.go:129`) and the binary say a CI-SLOW line under `--enforce` exits 1, so the document a stranger copies names the wrong exit. `nova-ci bench run -h` and `nova-ci bench -h` print the whole 130-line and 114-line banner as their exit-codes block because `cmd/nova-ci/bench.go:39,48` hands internal/tool's one-line `ExitTable` field `exitTable("bench run")`, a multi-line banner. The banner also says "In your own module, slowtests reads the events of the packages you name" (`cmd/nova-ci/main.go:34-35`), but slowtests takes no package names at all; they are named to `go test -json`, whose stream it reads. `nova-ci version` answers `v1.0.1-0.20261007202437-de86d1a499ea`, a pseudo-version naming neither 1.1 nor 1.2, the release identity the verb's own comment claims. And `cmd/nova-ci/timing.go:1` is still a `//go:build ignore` second `main` inside the command directory, reached by no shipped verb and named by neither the banner nor `docs/CLI.md`; the 1.1.0 read named it.

USE. The first run needs nothing. `nova-ci slowtests --example --budget 60 --load 4 --cpus 16` prints the CI-SLOW and CI-LOAD lines exactly as the README shows and exits 0, and `--budget 120` prints `CI-SLOW OK packages=2`; the JSON rendering is one `{result, facts, items}` object with the same verdict. Real work lands in a minute: in a scratch module, `go test -json -count=1 ./slow | nova-ci slowtests --budget 1 --enforce` caught `CI-SLOW package=example.com/scratch/slow seconds=2.0s budget=1s slowest=TestSlow:2.0s` at exit 1, the same stream without `--enforce` was a measurement at exit 0, and `--test-budget 1` named the single slow test. `functional ./...` printed `./f/` with a leading `./` and a runnable `-run` pattern, so the 1.1.0 defect "prints a path the test runner rejects" is fixed. Empty stdin is `CI-SLOW FAILED packages=0 ...; run: nova-ci slowtests --allow-empty` at exit 1, and `--allow-empty` answers OK at exit 0. Refusals are the house style for the tool's own verbs: `nova-ci`, `nova-ci frobnicate`, `nova-ci version extra`, `nova-ci slowtests --budget 0`, a bad allowlist row and a bad receipt field each name the problem and the next command in one line at exit 2. `--dry-run` on `local`, `new-rule`, `new-verb` and `github receipt` prints the plan and writes nothing.

What costs the score. Only `slowtests` takes `--json`: `functional`, `local`, `new-rule`, `new-verb`, `github receipt` and `version` all refuse it (for example `nova-ci functional --json ./cmd/nova-ci` answers `unknown flag "--json"` at exit 2), so an AI consuming this tool programmatically gets one JSON verb in eight, against `docs/STANDARD.md` section 2 ("Every verb accepts `--json`"). `nova-ci functional ./...` in this checkout prints one `-run` pattern of 28,680 characters with 689 alternatives, whole, with no `--max`, no total and no file to read it from, so the output is unbounded where the standard says it is bounded and keeps its totals. A package whose only Go file is a functional-tagged `_test.go` is invisible: `go list -tags functional ./...` lists it, but `nova-ci functional ./...` answers `CI FUNCTIONAL OK packages=0 reason=no-functional-tag-in-3-dirs`, so a new test-only package would silently run no functional test. When a test skips with the `SLEEPS:` marker the finding renders the ledger with the field escape, so the line reads `not on the\x20SLEEPS\x20ledger\x20(no\x20--sleeps\x20given)` (`internal/ci/slowtests/slowtests.go:607-608`): a reason an AI has to un-escape by hand. And the slowtests JSON facts carry `load` and `cpus` but not the `per-cpu` figure the CI-LOAD line prints (`cmd/nova-ci/slowtests.go:386-392`), so the two renderings of one run drift. The `bench` group on internal/tool uses a second refusal grammar and one line per problem: `nova-ci bench run` prints two `BENCH-RUN REFUSED:` lines with the remedy `nova-ci help`, and `nova-ci bench bogus` prints `CI REFUSED:`, not the `nova-ci bench run REFUSED: ...; run: nova-ci bench run -h` the tool's own verbs use. `nova-ci version` names v1.0.1, not the release under rating.

A 10 is `--json` on every verb from the one output value; a bounded `functional` pattern with its total and a file or note for the rest; a functional selection that finds a test-only package; one refusal grammar and one line for bench; the field escape kept out of prose reasons; `per-cpu` in the JSON facts; the `### First run` in `docs/CLI.md` and the right exit in `docs/TESTS.md`; the `timing.go` script gone or wired to a verb; and a version line that names the release.

## Good, keep

The banner answers what it does, how it works and how to use it before the usage lines, and its line 1 is the README's sentence word for word.

The one refusal line names every problem at once with a remedy that runs, and the near-miss hint is real: `--budg` answers `did you mean --budget?`, and a missing `github receipt` field lists all seven plus the store need in one run.

`slowtests --example` is a true zero-setup first run, and its line and `--json` renderings carry the same verdict; `--allow-empty`, `--max` with its `MORE` line, and the allowlist with the stated 3x bound are the standard's bounded, honest shape.

`functional` now prints `./`-prefixed directories that paste into `go test`, fixing the 1.1.0 finding, and `--dry-run` on every write verb prints the plan and writes nothing.
