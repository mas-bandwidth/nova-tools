# nova-self-talk READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 7525efe26a92
READ: 8/10
USE: 8/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-self-talk version` prints `nova-self-talk v1.0.1-0.20261006142910-7525efe26a92 linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch directory made for the trial; no live store, no server, no network. Every verb was run: scan (bare and named), shapes, example (with and without `--dry-run` and `--json`), version and help, over the example pages, a page of my own with ten claims of both classes and every licence, standard input, an empty file, a file with NUL bytes, random bytes and a system binary.

## Reasons

READ. The banner answers the three questions in its first nine lines: what the tool flags, how it reads (sentence by sentence against one table of shapes, a dated claim never flagged), and the first run (`example ./pages`, then three lines that each exit 1 and say why that is the tool working). The two classes are glossed where they are named, INSTALLATION included, so the 1.1.0 complaint about an unglossed class name is gone. The output contract is stated line by line with its stream, the exit table is stated once, and `shapes` prints the live detector table with a sentence each row finds and a near miss it passes, which is the best way I have met for a pattern tool to say exactly what it does. docs/CLI.md's first-run transcript carries the same lines the binary prints on the example pages.

What keeps READ at 8. The banner is still 94 lines (cmd/nova-self-talk/main.go:28-121), with the print-line inventory and a flags essay between the usage block and the examples. The per-verb help is thinner than the banner and in places wrong for the verb: `scan -h` says `usage: nova-self-talk scan [flags]` and `example -h` says `example [flags]`, dropping the required `<file>...` and `<dir>`; every verb's `-h` ends with the scan's exit table (`1 findings ... An all-skipped run exits 0`), including `version -h` and `shapes -h`; `--skip` and `--rule-doc` print `<value>` where the banner says `<basename>`; the `shapes -h` excerpt loses the indent of its second line. The banner says which lines go to stderr and which to stdout but never places `SELFTALK MORE`, and it goes to stderr (cmd/nova-self-talk/scan.go:383), so the banner's own `2>/dev/null` recipe loses the only line that says findings were cut; the family's shared output says MORE goes to stdout (pkg/tool/out.go:134). The spec has drifted: its "Says NO" grammar is `SELFTALK FAIL <file>:<line>: STANDING: <claim>` (docs/SPEC.md:1870) where the binary prints `STANDING match="<words>": <sentence>`; it opens a paragraph with "the checks above are walls" (docs/SPEC.md:1751) when nothing above it in the section is a check; it cites "Specimen 8" (docs/SPEC.md:1810) without saying what that is; and its test index points this section's rules at lines 1680, 1684 and 1691 (docs/SPEC.md:3080-3082), which now hold another tool's text. The internal map row still calls the package an "agent self-talk journal stream" (internal/docs/catalog.go:111), and the README row's command scans `./cmd/nova-self-talk/testdata/example-pages/journal.md`, a path a reader holding only the binary does not have.

USE. The first run is as clean as any tool in the set. `example --dry-run ./pages` says what it would write and the next command; the real write lays down two pages; a second run writes nothing and reports `kept=`; a changed page is refused, never replaced. Each pasted example line exits 1 with findings on stderr in line order and the DATED count, count line and NOTE on stdout. `--max 2` on my own page printed two findings per class and a MORE line per class naming `--max 0`; `--json` carried the same counts, items and `more`. Standard input works as `-`. `--skip` of a name no file has gets a NOTE saying it skipped nothing; an all-skipped run exits 0 with `SELFTALK SKIP files=0`, never OK. A missing file among good ones refuses the whole run with "NOTHING was scanned, which is not a green" and scans none, so no partial green escapes. A bare word that is no file is told the verbs. A flag after the files is refused with why. A refusal under `--json` is one JSON object. The licences behave as the help says: an imperative, an aspiration and a dated sentence passed; `RULE:` and a quotation are licensed for the second class only and the first class flagged them, which `shapes` (each licence row says "second class only") and the every-run NOTE both state.

What keeps USE at 8. A binary still scans green: `nova-self-talk /usr/bin/ls` and 300 random bytes both print `SELFTALK OK` and exit 0, the defect the 1.1.0 use rating reported, and a file with NUL bytes is scanned as prose. The 1.1.0 refusal defects are all still there: `--bogus --max abc` names only the unknown flag, though the code's own comment says every problem is named in one go (cmd/nova-self-talk/scan.go:94-106); `--max abc` refuses in the flag library's voice (`invalid value "abc" for flag -max: parse error`); `example --bogus` says `flag provided but not defined: -bogus`, the wording scan rewrites to `unknown flag`; and `help frobnicate` prints the whole banner at exit 0. `example --dry-run /proc/nope` says `EXAMPLE OK ... would-write=RULES.md,journal.md`, exit 0, where the real run cannot write; the dry run checks for clashes but not that the directory can be made. `example --dry-run` over pages already in place says `would-write=-` and still offers `run: nova-self-talk example ./pages`, a command that would do nothing. `version extra` says `got 1` without naming what it got, and points at `version -h` where every other refusal points at `help <verb>`.

A 10 would refuse a file that is not text, name every invocation problem in one refusal in the tool's own voice, make `help <unknown>` say so and exit 2, give each verb's `-h` its real usage line and its own exit table, place MORE in the stream table, make the dry run check what the real run needs, and bring the spec's grammar, line references and map row into line with the binary.

## Good, keep

- `shapes`: the live detector table, each row with a sentence it finds and a near miss it passes, and a test that runs both through the scan. A pattern tool that shows its patterns and proves them is the right answer to "what will this flag".
- All-or-nothing reads: one unreadable path refuses the run and scans nothing, saying "NOTHING was scanned, which is not a green"; and an all-skipped run is `SKIP files=0`, never OK.
- The every-run NOTE saying a green clears the known shapes, never the file, and the DATED count on one line: the tool says what it cannot see and does not spend the reader's context on the good news.
- `example` never replaces a page: a changed page is refused, an identical one is kept and reported as `kept=`.
