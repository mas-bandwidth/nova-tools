# nova-tokens READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 43b487125e85
READ: 7/10
USE: 6/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-tokens version` prints `nova-tokens v1.0.1-0.20261006145252-43b487125e85 linux/amd64 go1.26.6`. Read cold from `nova-tokens help`, every verb's `-h` and docs/SPEC-TOKENS.md, then built and run on a Linux bench machine in scratch directories made for the trial; no live store, no server. The banner's setup and all seven example lines ran as printed. Then fold (one day, `--all`, `--dry-run`, shrink, overlap, partial, no-id messages, a bad JSON line, four concurrent folds of one `--out`), session (twice over one transcript, over two transcripts, `--role`, `--day`, `--dry-run --json`), report (local mode, `--note`, a symlinked `--note`, an unreadable source), check (`--strict`, `--through`, a stray), sum, sources `--unattributed`, profiles, and ledger and report `--redis` against a closed port.

## Reasons

READ. The first line says what the tool is, the second paragraph says how it works, and the usage block lists all nine verbs. Each rule an AI needs before it trusts a number is in plain words: a dash is never a zero, exit 1 still writes, a day that would shrink is refused, two sources of one provider sharing message ids are refused, a fold merges by source. Every verb answers `-h` with its usage excerpt, an `effect:` line saying what it writes, and its flags. Refusals name every missing flag in one run, and `--json` refusals carry each reason as a list item.

What keeps READ at 7. The banner is about 160 lines and its first run sits at the top while the setup and example it points at sit at the bottom. Several sentences are not true: "--timeout is the one flag with a default" (cmd/nova-tokens/main.go:105) beside `--weights` and session's `--day`, both defaulted; "sources is the one that only looks" (main.go:249) when sum, check and profiles write nothing either; and the banner promises "check and sum never see a doubled day" when its own example doubles one (below). The store-mode sentence (main.go:64) states one rule three ways. Every `-h`, `version -h` included, ends with the same seven-line exit paragraph about fold and report. `session -h` does not give the `--weights` numbers, nor that `--role` also becomes the repo cell, nor that a session row is always on repo `unattributed`. `report -h` lists `--bus` and `--swarm`, which the report usage line does not. The docs drift from the binary: docs/CLI.md:1746 says the help has "one setup command" (it has ten lines) and "two exceptions" to the environment rule (the banner names three); docs/USAGE.md:186 says there are no defaults and no environment variables; README.md:54 still says 1.0.0. docs/CLI.md:1742 is a 2,631-character paragraph.

USE. The banner's first run worked as printed and every line ended in a typed status word. The safety rules I tried hold on fold: an unreadable and then a lowered transcript left the day file byte-unchanged with `TOKENS SHRANK` lines and exit 1; two `--claude` sources over copies of one transcript were refused before any write; a fold declaring only some of a row's sources was `TOKENS PARTIAL`; four concurrent folds of one `--out` all finished cleanly under the lock; a symlinked `--note` was refused; `check` cannot go green over an empty `--out`; a bad repos regexp is refused naming the line.

What brings USE down to 6. The shrink rule does not hold on session. Every session row carries the one source label `claude-session` (internal/tokens/claude_session.go:70), so a second `session --out` over a different transcript on the same day replaces the first transcript's row: a day that had a 1,000-input session went to 812 with `written=true`, exit 0, and no `TOKENS SHRANK`. Two windows in one day cannot both be booked, and the loss is silent. `--role` changes the row's identity, so the same transcript rerun with `--role w` replaced the bare-model row instead of being refused as the same spend. The banner's own example still doubles a day: fold then `session --out` over one transcript leave two rows of the same message, and `check` is `CHECK OK` while `sum` says `input=1624` for a day that spent 812. Fold and session disagree on a message with no id: fold drops it with a note and `TOKENS OK` exit 0, session counts it as a turn (claude_session.go:151). `session --day` on a day the transcript has no turn on writes a day file of zeros, so `check` now counts that day as covered. And the 1.1.0 machine-interface findings remain: `report` prints `REPORT OK` and exits 1 with an unreadable source; `sum` over an empty `--out` and `profiles` over an empty root are OK exit 0; `--json` gives counts as strings in sum and numbers in session; most refusals point at the 160-line `nova-tokens help`; `report --dry-run` puts `dry_run=true` on stderr; `REPORT OK` carries `at=` and `build=` twice, the second pair inside an unquoted `subject=`.

A ten needs: session rows keyed by the transcript (or its message ids) so two windows add and a lower count is `TOKENS SHRANK`; the overlap rule applied between fold and session; one status word per exit; one JSON type per fact; every refusal pointing at the verb's `-h`; and a banner and docs that say what the binary does.

## Good, keep

Fold's safety rules hold under trial: shrink left the file byte-unchanged and named each type with both numbers; the overlap refusal fires before any write; `TOKENS PARTIAL` keeps a fold from erasing a row it did not fully declare; four concurrent folds of one `--out` finished cleanly under `fold.lock`. A dash is never a zero, in the day file, in sum and in `usd=`. A bad JSON line is counted as `badline=1` and fails the fold while the rest of the file is still read. `--dry-run` is the real run's plan. `check` cannot go green over an empty directory, names a stray without touching it, and `--through` turns a stale end into a finding. `sources --unattributed` names the stem a rule is missing. The verbs are in their own files, so a reader finds one verb's code in a minute.
