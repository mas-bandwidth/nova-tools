# nova-tokens READ and USE rating, nova-tools 1.2.0

Rater: deepseek/deepseek-v4.1-flash under dsh, a cold reader on a friend's re-rate card
Build: 7acb90e18a76
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of `sprint/mechanical-2026-10-02`, build `7acb90e18a76`. `nova-tokens version` prints `nova-tokens v1.0.1-0.20261007211151-7acb90e18a76 linux/amd64 go1.26.6`. Built and run on a Linux bench, in throwaway directories made for the trial; no live store was dialled and no server was started. Every verb was exercised: `fold` (one day, `--all`, `--dry-run`, shrink and `--allow-shrink`, two same-id `--claude` sources, a bare `--provider` label), `check` (`OK`, empty, `--allow-empty`, notes and strays, `--strict`, a stale `--through`), `sum` (`OK`, empty, `--max`, a repeated `--month`, `--json`), `sources` (plain, `--unattributed`, a bus note that does not parse), `report` (local with and without `--note`, `--dry-run`, `--json`, `--bus`, an unreadable source, and store mode against a closed port), `session` (plain, `--dry-run`, `--out`, `--role`, a bad `--weights`), `profiles` over an empty root, `ledger --dry-run`, and `version`. Every `-h` was read. Nothing was removed outside the trial directories.

## Reasons

READ. The first line is the README's sentence for the tool word for word, and the banner answers the three questions in order: what it does, how it works, and a `setup:`/`example:` block a stranger can paste. Every verb has its own file and every verb answers `-h` with its usage excerpt, its example, an `effect:` line saying what it writes, its flags and the exit table. The rules an AI needs to trust a number are stated where a reader meets them: a dash is never a zero, a day that would go backwards is refused and left as it was, two same-provider sources that feed one message id are refused before a day file is written, and a dry run is the real run's own plan with the real refusals. The `check` paragraph is the best thing here: it counts what it does not name and keeps both counts on the line, so neither door can lie.

What keeps READ at 7. The normative documents disagree with the binary and with each other on the rules the tool is built around. `docs/SPEC-TOKENS.md:1055` (repeated at `:443`) says flatly that fold "does not detect overlap between sources", and `docs/CLI.md:1942` says two declared directories holding one transcript "count every message twice" and calls the shared-id line "a warning, not a correction", while the binary refuses the same two `--claude` flags with `TOKENS REFUSED: two declared sources fed the same 1 message ids (claude:a and claude:b)` at exit 2 before writing anything. The provider flag drifts three ways: `docs/SPEC-TOKENS.md:413`, the heading at `:756` and the demanded test near `:1271` write `--provider <label>=<file>`, while the binary wants `--provider <kind>:<label>=<file>` and refuses a bare label. The banner says "`--timeout` is the one flag with a default" (`cmd/nova-tokens/main.go:105-106`) while `--weights` defaults to `1,1.25,0.1,5` and session's `--day` defaults to every stamped day; `docs/USAGE.md:186` still says "there are no defaults and no environment variables"; and `docs/CLI.md:1933` says the help names "two exceptions" where the banner (`main.go:101-105`) names three environment reads, and calls the ten-line `setup:` block "one setup command". The banner's how-it-works line (`main.go:48`) says "check, sum and report read the day files back", but `report` local mode has no day-file input at all: pointed at a source holding 100 input tokens it reported 100 while the day file beside it held 812, so it folds its named sources live. The `check` usage at `docs/SPEC-TOKENS.md:410` and `docs/CLI.md:1926` omits `--allow-empty`, which the banner (`main.go:68`) and `check -h` list. The banner's `report` usage (`main.go:57-60`) omits `--bus` and `--swarm`, which `report -h` lists and `report --bus ./bus` runs. And `README.md:86-91` still calls these "the Nova Tools 1.0.0 commands" and installs `@v1.0.0` in a 1.2.0 tree. The banner is about 200 lines and its first-run pointer sits at `main.go:50` while the lines it points at are `main.go:171` and `:183`, so a cold reader crosses a hundred lines of rules before the first command.

USE. The setup and all example lines ran as printed and each exited 0 with a typed line. The machine interface is strong: every verb but `version` takes `--json` from one envelope with proper JSON types (`sum --json` prints `"input":812` and `"reasoning":null`), `--dry-run` is the real run's own plan with the real refusals, a refusal names every independent problem in one run, an unknown flag names the verb's own flags and `-h`, and `--max` bounds a listing with `SUM MORE kind=pair shown=1 total=2` and the exact command that widens it. `ledger --dry-run` dialled no store. `fold --dry-run` wrote no day file and left no lock. A Claude transcript, a bus note, a shrink, a stale `--through`, an empty `--out`, an unreadable source and a closed Redis port each produced the typed line and the exit the help promised, with one exception (finding 2).

What keeps USE at 7. The banner's own first run is wrong. After the `fold` example, `session --claude-session ./session.jsonl --out ./out` adds the same message `example-1` a second time as a `claude-session` row on `unattributed`; `check` then says `CHECK OK` and `sum` prints `input=1624` for a day that spent 812, against `main.go:131`'s promise that "check and sum never see a doubled day". The same-provider refusal does not cover `session --out` against a source already in the day file. `sources` prints `SOURCES OK ... unparsed=1` at exit 0 while the banner (`main.go:85-91`) and its own `-h` exit table say an unparsed bus line is exit 1; `sources.go:17-18` says exiting 0 whenever it ran is by design. `sum` over an `--out` with no day file is `SUM OK days=0` exit 0 and `profiles` over an empty root is `PROFILES OK models=0` exit 0, while `check` calls the same emptiness `CHECK FAILED` exit 1. `report --dry-run` puts the body on stdout and `dry_run=true` on stderr, so a caller capturing stdout never sees the marker the help says is on its last line. `fold`, `report` and `session --out` refuse when `--out` is not there, and the `--out` help never says the directory must already exist. A repeated `--month` is silently taken as the last value. `session --role w` writes model `claude-fable-5-1/w` with the role in the repo cell, which only the spec (`docs/SPEC-TOKENS.md:489`) says. A shrink names `date=` where every `TOKENS DAY` line names `day=`. A ten needs: the overlap rule across fold and session so the banner's own example cannot double a day; one status word per exit; every refusal pointing at the verb's `-h`; every flag's default printed; and docs that say what the binary does.

## Good, keep

The banner's first line is the README's sentence for the tool, word for word.

The same-provider overlap refusal fires before any day file is written and names both labels and the duplicate count.

`check` cannot go green over an empty directory, counts a calendar gap without calling it a finding, counts a person's note without calling it a stray, and keeps both counts on the line so `--strict` and `--no-spend` are the only doors that turn them into findings.

A dash is never a zero, in the day file, in `sum` and in `report`'s `usd=`; a day that would shrink is left as it was and each type that moved is named with both numbers.

`--dry-run` is the real run's plan with the real refusals (`TOKENS DAY ... written=false would_write=true`), `ledger --dry-run` dials no store, and `--json` renders the same value with the same types as the lines.

Every source kind exercised folded to the rows the spec names, and a fold from two distinct Claude labels merged to one row naming both sources.

Output is bounded with a total and the command that widens it (`SUM MORE kind=pair shown=1 total=2 nova-tokens sum ... --max 0`).
