# nova-secrets READ and USE rating, nova-tools 1.2.0

Rater: deepseek/deepseek-v4.1-flash, running in dsh (the DeepSeek Harness headless runner), a sprint worker on a friend's re-rate card
Build: 0389f76634ec
READ: 6.5/10
USE: 6/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-secrets version` prints `nova-secrets v1.0.1-0.20261007224659-0389f76634ec linux/amd64 go1.26.6`. Read cold from `nova-secrets help`, every verb's `-h` and docs/SPEC-SECRETS.md, then built and run for real on a Linux bench machine (go1.26.6 linux/amd64, real sops and age-keygen, HOME pointed into a scratch directory) on a throwaway store with a local bare remote and a stub ssh for one real `place`: the banner's setup block, keygen, names, check, exec, seal, seat add, seat inject, gate, place, placed, and the flags, refusals and exit codes around them. Never a live store and never a server.

## Reasons

READ. The banner opens with what the tool is, `how it works:` names the store's nouns (the git working copy, `.sops.yaml`, `recovery.pub`, one `<seat>.yaml` per seat), `setup:` is a paste-able block that made a working store from an empty directory on Linux, and every verb answers `-h` with a usage line, a worked example, an `effect:` line naming the effect (inspection, local write, store write, delivery) and one line per flag that says what it wants. Refusals use one grammar, `SECRETS <VERB> REFUSED: <why>; run: <next>`; an unknown verb or flag lists the valid ones; `exec`'s and `check`'s `-h` carry a full store prerequisite saying why HEAD must equal its upstream and the command for each case; and `gate --base nope` now uses that one grammar too.

What keeps READ at 6.5 is that the help says things the binary does not do. The advertised `first value:` cannot run after `setup:` (finding 1), `check`'s `effect:` claims a proof it does not make (finding 2), every example is Homebrew-only and fails on Linux (finding 6), and `help seat` dumps the whole 108-line banner (finding 7). Smaller defects: "these two lines" for three printed lines (finding 9); a recovery-keygen rule and NOTE that contradict `setup:` (finding 10); a Linux `brew install` remedy (finding 11); the stale package doc and the spec's line count (findings 12 and 13); the CLI reference opening on gate (finding 14); one exit paragraph printed under verbs it does not describe (finding 8); and one `--dry-run` sentence about seal and seat inject printed under place and the others (finding 15).

USE. Once a seat file exists, the core loop is good and I used all of it. `names` and `names --json` read names without a key and report `sealed`/`clear`; `check` read the store's files and git state and passed with the seat's key; `exec` put exactly the `--only` values into a child's environment, printed one OK line naming seat, file and head without a value, and passed the child's status through (a child `exit 7` came back 7); `seal --stdin --no-pr` added a value on a `seal/` branch, printed a NOTE that exec cannot see it yet, and after a fast-forward it opened through exec; `seat add` re-sealed a value to a new seat whose own key then opened it; `gate` approved a new seat with `GATE APPROVE files=2 machines=-`; a 7-field gate registry handed to `place` is now refused by name (finding 22); `place` copied a value to a stub ssh on stdin, wrote a receipt and `placed` listed it; and a missing flag, an unknown flag, a bad `--max`, a missing sops binary and a dirty store were each one line with a remedy.

What keeps USE at 6: a new store's printed first run cannot reach a first value, and the hand-sealed file it forces is not what `seat add` expects (finding 1); `check` passes a key that opens nothing (finding 2); a wrong key on `exec` is a raw `sops failed: exit 128` (finding 3); after `seat inject --no-pr` nothing says `exec` cannot see the value yet (finding 5); `--json` is on `names` alone (finding 4); `placed` on an absent directory is a plain OK count=0 (finding 16); an unknown machine's refusal names no machines and no next command (finding 17); the `--only` refusal promises the seat's names and prints none (finding 18); a bad `--max` loses its `run:` line (finding 19); a store ahead of its upstream is told to `pull --ff-only`, which does nothing (finding 20); a missing `--require` name is answered with `sops <file>`, which decrypts the file to an editor (finding 21); and `version` does not quote the argument it refused (finding 23).

A 10 would give a new store's first value in one printed line that runs after `setup:`; make `check` prove that `--key` opens `--as`'s file; turn every raw helper exit into a named refusal; print each verb's own exit lines and one `--dry-run` line; give every verb a `--json` rendering; and end every refusal, including an unknown machine and a bad flag value, with a runnable next command.

## Good, keep
- `exec` is the right shape for an AI: the value goes only into one child's environment, the OK line names seat, file and store head without the value, and the child's own status passes through, told apart from `exec`'s 125.
- One refusal grammar, `SECRETS <VERB> REFUSED: <why>; run: <next>`, with a runnable next step for a missing flag, a bad key path, a missing sops binary, an absent store, and an unknown verb or flag.
- `--dry-run` on `seal`, `seat inject` and `place` prints PLAN or progress lines that name the file, recipients, branch or receipt without reading or showing a value.
- `seal --stdin` keeps the value off argv; `place` sends it on the ssh child's stdin, never in an argument; no receipt holds a hash of the value.
- `seat add` plus `gate` make adding a seat a reviewable commit (`GATE APPROVE files=2 machines=-`), and a 7-field gate registry handed to `place` is refused by name.
- `names --json` is one value (result, facts, items) with a `MORE` line when `--max` cuts the list, and `check` catches an untracked unencrypted file and a working copy that differs from its remote-tracking ref.
