# nova-secrets READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card (the rating is not the friend's; the file name follows the card)
Build: 43b487125e85
READ: 7/10
USE: 6.5/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02 as staged for this card. `nova-secrets version` prints `nova-secrets v1.0.1-0.20261006145252-43b487125e85 linux/amd64 go1.26.6`. Built and run on a Linux bench machine with the real sops 3.13.3 and age-keygen on PATH, under a scratch HOME made for the trial: the banner's setup pasted line by line, a local bare remote, two seats (ada and bo), every verb run for real, `place` against a stand-in ssh that swallows stdin, and `gate` against branches carrying a three-recipient rule and a cleartext yaml. No live store, no real ssh target, no gh call, no server.

## Reasons

READ. The banner is a good door: one line of purpose, a "how it works" paragraph that names the store's nouns (`.sops.yaml`, `recovery.pub`, one `<seat>.yaml` per seat, a seat key opening its file) and the rule that no value is printed, then a setup block that runs from an empty directory. exec's and check's `-h` state the store prerequisite (a named branch, an upstream, HEAD equal to it), say why, and give the repair commands for each refusal before any flag. Every write verb's `-h` carries an `effect:` line that says what is written and what is not, and the `--dry-run` text says exactly what a dry run still decrypts.

What keeps READ at 7. The banner's "first value" step cannot run: it seals into `ada.yaml`, which the setup never makes, and seal refuses by rule 12 (cmd/nova-secrets/main.go:114). The banner and every example still name `/opt/homebrew/bin/sops` while the setup block and the flag text say `command -v sops`, and the refusal for a missing binary says `run: brew install sops` on Linux (internal/secrets/sops.go:46). Every verb's `-h` repeats the whole exit-code paragraph, exec's 125 included, on verbs that have neither 1 nor 125 (cmd/nova-secrets/main.go:95). `seat -h` prints the whole banner. The package doc still says four verbs (internal/secrets/secret.go:2) and the spec still says "about two hundred lines of Go" (docs/SPEC-SECRETS.md:34) over 6122 non-test lines. `check -h` says it decrypts the seat's file "to prove it opens" (cmd/nova-secrets/main.go:161), and check is green with a key that does not open it.

USE. Once a seat file existed, the core loop did what the help says, first time: `names` (text, `--json`, `--max` with a MORE line that is a pasteable command), `check` green and red (HEAD ahead of its upstream named with `git pull --ff-only`; an unsealed file named), `exec --only` putting exactly the named values in the child's environment and ending with the child's own status (7 came back as 7), `seal --stdin` with `--dry-run` and `--no-pr` leaving the store on its starting branch, `seat add` breaking the new-seat circle with a file only the new seat (and recovery) opens, `seat inject` into an existing seat, `place` writing a mode-0600 receipt that `placed` lists. Refusals name every missing flag at once and a missing seat lists the seats there are.

What keeps USE at 6.5. The first run does not finish from the tool: in a fresh store no verb can make the first seat file (seal refuses a seat with no file, seat add needs a `--from` seat that exists), so I had to seal `ada.yaml` by hand with a `sops -e` pipe the help never shows. `names --as ghost` then tells the reader "seal starts a new seat", the step that just refused (internal/secrets/seatfile.go:193). `check` with another seat's key prints `SECRETS CHECK OK ... mine=0 foreign=1` and exit 0, and the `exec` that follows fails with `sops failed: exit 128`; the 128 is still undiagnosed, though check already knows the key is not a recipient. gate still prints `GATE REFUSE rule=0 file=:` outside the house grammar with no remedy, stops at the first problem (a three-recipient rule hid the cleartext `leak.yaml` on the same branch), and exits 2 for a judged violation. place still reads the gate's seven-field registry row and plans `path=linux/amd64/.config/nova-secrets/GH_TOKEN.env`. `--json` is still names only: check, exec, placed and version refuse it. seat add has no `--dry-run` where every other store write has one.

A 10 would give the banner a first run that finishes (a verb, or a `seat add` with no `--from` for the first seat of a store, that seals a store's first file from stdin), make every remedy agree with the rules it sits beside, make check red (or say mine=0 plainly) when `--key` cannot open `--as`'s file and name the recipient mismatch in exec, put gate on the house grammar with every violation in one run, refuse a registry row of the wrong shape in place, and carry `--json` on every verb that prints a result.

## Good, keep

No value reached stdout, stderr, argv or a file in any run; `exec` gave the child exactly the `--only` names and handed back its exit status. The store prerequisite and its repair commands are in exec's and check's `-h` before any flag. Refusals list every missing flag at once, a missing seat lists the seats there are, and a refusal before exec runs is 125, so a caller can tell the tool's refusal from the command's failure. `seal --no-pr` and `seat inject --no-pr` leave the store on its starting branch with the next push command printed. `seat add` writes the rule before the encrypt and names its next step. The dry runs say what they still decrypt and print the branch, commit and pull request title a real run would take. `place` writes its receipt mode 0600 and records file, blob and head, never a hash of the value.
