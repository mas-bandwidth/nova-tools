# nova-swarm READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 2d1c36b140e1
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-swarm version` prints `nova-swarm v1.0.1-0.20261006141530-2d1c36b140e1 linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch directory made for the trial; no live store, no server, no model called. native ran end to end with a shell-script harness, walled and unwalled; member was tried only as far as its refusals, because it needs a sprint server.

## Reasons

READ. The banner says what the tool is in one line, then how it works, the credential rule, the sandbox rule and how to prepare a card, and its three examples print templates and the lint rules with no setup. Every verb answers `-h` and `help <verb>` with its banner excerpt, flags with a required marker and a default, and exit codes; most carry an `effect:` line. The refusals for unknown verbs and flags name the full verb list and point at `help <verb>`. That is the shape an AI wants.

What keeps READ at 7. The help says things the binary does not do: verify's `effect:` says it writes nothing (cmd/nova-swarm/main.go:173) and it writes `<result>.receipt` beside the result on every run, a refusal included; the spec says every listing takes `--max` (docs/SPEC-SWARM.md:144) and `slots list` refuses it while `lint --rules --max 3` prints all forty rules. The banner's native line lists 16 of native's 27 flags; `--dry-run` on step, and `--usd`, `--sandbox`, `--repo`, `--no-wall` on native are only in `-h`. native also documents two flags, `--owner` and `--slots-store`, as "accepted and read by nothing". The spec has drifted: "eleven living verbs" (docs/SPEC-SWARM.md:48) when the binary has twelve, its usage block omits `step` and `slots run` and carries an older lint line, and its output grammar names `SLOTS OK store= capacity= share=` and `SLOTS GRANTED` where the binary prints `SLOTS INIT OK` and `SLOTS OK owner=`. Line 84 of the spec is one 20,067-character paragraph. The `-h` excerpts pick up stray lines (template's `-h` carries two banner example lines, lint's carries `nova-swarm lint --rules`), and lint's and member's `-h` tell the reader "nova-swarm lint -h has the rest" from inside `lint -h`. lint's flag list prints `<string>` for five file flags and `--card <lint <file>>` for one.

USE. The banner's first run is clean: `template --name read-pr`, `template --name worker` and `lint --rules` exit 0. `template --name card` lints `LINT OK` with ten placeholder NOTEs and fails `--typed` with four DRIFT lines that each name the line to add. The slots lifecycle works and every state change prints a typed line: init, take, a second take refused with holders and a `remedy=`, re-init refused with why, `slots run -- echo hello` printing `hello`, `slots run -- false` passing exit 1 through, and `release --all` against a running `slots run` refused with `SLOTS KEPT` and why. worker check's refusals name what is wanted and the template that prints one. `native` with a fake harness, `--tokens unmetered` and no REPO line ran end to end in about a quarter second, walled (`sandbox=landlock`) and with `--no-wall` (`sandbox=none-by-flag`), and published `RESULT.md`, `usage.tsv` and a report under `jobs/results/<label>/<run>/1/`. native and member name every missing required flag in one run. disk-guard `--dry-run` on scratch roots finished `DISK-GUARD OK freed=0`.

What keeps USE at 7. Things that should fail pass, and one pass writes when it says it does not: `verify` accepts a result whose line 2 is `all good` with no `findings:` head, against the spec's plan-only rule (docs/SPEC-SWARM.md:21); its receipt records `card_sha256=e3b0c442...`, the hash of nothing, when no `--card` was given; `doctor --local /nonexistent` is `DOCTOR OK` exit 0; `profile` over a glob that matches nothing, or a job whose timeline is a header only, is `PROFILE SUMMARY jobs=0` exit 0, and native's own job directory carries no `timeline.tsv` for it to read; native runs a card still holding `BASE: <branch>` and `Deadline: finish within <n> minutes.` without a word. The four 1.1.0 carry-overs are still there: native `-h`'s example refuses as printed, the result template fails verify, required-input refusals use a second grammar with no `run:` line, and native has no `--dry-run`. `step` refuses as `nova-swarmstep REFUSED` (cmd/nova-swarm/step.go:74, a missing blank). An unknown flag on native lists 16 flags "and 11 more" (pkg/nsprint/verbflag/verbflag.go:205), hiding the one the reader needs. `slots list` shows a `take` lease as `state=live stranded=1`, both at once. `slots take --owner bob` against a store with no bob refuses as `share=0`, which reads as a full share, not an unknown owner. `worker check` on the worker template names only the harness, with blanks escaped `<the\x20harness\x20command\x20on\x20PATH>`.

A 10 would make every `effect:` line and spec claim true of the binary, make the native example and the result template pass as printed, give every refusal the one `REFUSED ...; run: nova-swarm help <verb>` grammar, refuse a green over nothing (verify with no head, doctor on a missing file, profile on no jobs), refuse a native card with unfilled placeholders, add `--dry-run` to native, and break the spec's 20 KB paragraph into sections.

## Good, keep

native runs a card end to end inside the wall with a harness of the caller's own, and the NATIVE line says the wall it used (`sandbox=landlock`, `sandbox=none-by-flag`). nativeRun is now 57 lines (cmd/nova-swarm/native.go:1517), down from 1,197. The slots lifecycle is the best part to use: each refusal names the holders and a runnable remedy, and `SLOTS KEPT` says why a running holder's lease is not freed. Unknown verbs and flags list the verbs and point at `help <verb>`. worker check's refusals name the template that prints a valid description. native and member name every missing required flag in one run.
