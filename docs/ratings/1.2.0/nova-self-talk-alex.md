# nova-self-talk READ and USE rating, nova-tools 1.2.0

Rater: GLM-4.6 in opencode, a sprint worker on a friend's re-rate card
Build: c76fcb249cc1
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-self-talk version` prints `nova-self-talk v1.0.1-0.20261007015429-c76fcb249cc1 linux/amd64 go1.26.6`. Built and run on a Linux bench machine against a scratch directory made for the trial: the example pages written by `example ./pages`, plus a probe page written by hand with first-person claims of both classes, every licensed shape, three contradictory or negated sentences, a fenced code block, a NUL-byte-laced file, a binary (the tool's own binary), a path with a slash given to `--skip`, two unreadable paths, and a file named twice. No live store, no server, no network.

## Reasons

READ. The banner's first line is the README row's sentence (README.md:40, "flags sentences where a writer passes a standing verdict on themselves"), and the three questions follow: how it works (sentence-by-sentence over one table of shapes), first run (`example ./pages` then three lines that each exit 1), and the two disjoint classes are glossed where they appear — STANDING/DATED and INSTALLATION. The print-line grammar is spelled out line by line with the stream that holds it, and the exit table covers the all-skipped case. `shapes` turns the detector into a table a reader can audit: each row carries what it finds, its pattern, one sentence it reports and one it passes. The `SELFTALK NOTE` line that prints on every run says what a clear means and what it does not, and a banner format a rule document prints above its findings gives a reader the sentence that says what the finding is FOR, before any finding lands.

What keeps READ at 7. The banner is still 94 lines (cmd/nova-self-talk/main.go:28-121): between the three questions and the example block sit the full print-line inventory and a flags essay, and the same contract is restated in docs/CLI.md and the spec — a cold read turns to skimming by the third restatement. The per-verb help is thinner than the banner and wrong where it counts: `scan -h` says `usage: nova-self-talk scan [flags]` with no `<file>...`; `example -h` says `usage: nova-self-talk example [flags]` with no `<dir>`; every verb's `-h` ends with the scan's exit table (`1 findings ... An all-skipped run exits 0 with SELFTALK SKIP files=0`), even `version -h` and `shapes -h`, which cannot produce that output; `--skip` and `--rule-doc` print `<value>` and `--max` `<int>` instead of `<basename>` and `<n>`; `shapes -h`'s continuation loses its indent so `sentence each finds and a near miss each passes` reads as a second command. The spec's output grammar (docs/SPEC.md:114-115 and docs/SPEC.md:1870) still says `SELFTALK FAIL <file>:<line>: STANDING: <claim>` with no `match=`, which the binary always prints. The internal map calls the package an "agent self-talk journal stream" (internal/docs/catalog.go:111), where `internal/selftalk/selftalk.go:1-3` and the banner both say it classifies self-claims in prose. README.md:40's two tail clauses still read poorly: "Reads the example without editing it" names no example, and "Findings are advisory and produce exit 1" reads as a contradiction until the banner's example block says exit 1 is the tool working. The spec names "Specimen 8" (docs/SPEC.md:1810) without showing the sentence.

USE. The interface is close to 10. `example --dry-run` prints the plan, the next command and the would-write list; the real write lays down the two pages; a second run writes nothing and prints `kept=RULES.md,journal.md`; a changed page is refused before anything is written; `--json` returns one object. Each banner example line exits 1 as promised, with findings on stderr in line order and the count line, DATED count and NOTE on stdout. An unreadable file among good ones refuses the whole run and scans nothing, saying "NOTHING was scanned, which is not a green"; an all-skipped run is `SKIP files=0`, never OK; a `--skip` or `--rule-doc` name that matches no named file gets its own NOTE; CRLF files, a file whose name holds a newline (rendered as `\x0a`), and `-` for stdin all work. `--max` caps each class separately with a `MORE` line naming the remedy, in lines and in `--json` (`more` carries kind, shown, total, remedy). The licences behave as the help and `shapes` say: an imperative, an aspiration, a dated sentence and a quotation pass; `RULE:` and `CHECK:` are licensed for the second class only. The every-run NOTE that a green clears known shapes, never the file, is the honest limit printed by default.

What keeps USE at 7 is the classifier on real prose and a handful of carried interface defects. The tool scans its own binary as prose: `nova-self-talk /path/to/bin/nova-self-talk` returned STANDING matches at line 2924 ("I am bad at estimating time" — a string in the binary's regex test) and a FORECLOSURE at line 2929 spanning binary garbage, exit 0. A file with NUL bytes is scanned as prose. Fenced code blocks are scanned as prose: every transcript of the tool itself in docs/CLI.md and docs/TESTS.md is therefore a finding. Negation is not respected — `I am not bad at this anymore.` and `I am no longer the worst at reviewing.` are STANDING findings. Third-person markers with no first person are STANDING findings: `Every time I open /usr/bin, something fails.` matches because `every time` is in the negative-vocabulary list. The `there is no` FORECLOSURE rule's gap accepts the letter `i`, so `There is no -i: a key named on argv is a key in every ps.` is a finding. A sentence ending `."` is not ended, so `She said: "I am the worst at this."` and the next line's `I will never be a good planner.` print as one FORECLOSURE whose match sits on the next line. A file named twice on the line is scanned twice — every finding reprinted, `files=2 claims=4`, the same defect the user-facing `files=` count will lie about. The carried interface defects from 1.1.0 use are unchanged: `help frobnicate` prints the whole banner and exits 0; `--bogus --max abc` reports only `unknown flag -bogus`; `--max abc` is refused in the flag library's voice (`invalid value "abc" for flag -max: parse error`); `version --json` is refused (`takes no flags and no arguments, got 1`) even though every other verb takes `--json`. The banner's stream table names findings on stderr and counts/NOTE on stdout but never names MORE; MORE prints on stderr next to the findings (cmd/nova-self-talk/scan.go:383-384), so under the banner's own `2>/dev/null` recipe the line that says findings were cut is lost. `version extra` is refused as `got 1` instead of quoting what it got, with `; run: nova-self-talk version -h` instead of the family's `help version`. `example --dry-run /proc/nope` says `EXAMPLE OK would-write=RULES.md,journal.md` exit 0, where the real run cannot write; the dry run checks for clashes but not that the directory can be made. `example --dry-run ./pages` over pages already in place reports `wrote=- kept=RULES.md,journal.md` and offers `run: nova-self-talk example ./pages`, a command that would do nothing. `--json` on `example --dry-run` writes `kept=""` where the typed line writes `kept=-`, two empty markers for one value.

A 10 would refuse a file that is not valid UTF-8 and is not an empty buffer as a non-text file; skip fenced code (or license it like a quotation); let negation (`not`, `no longer`) and bare third-person sentences pass; anchor `there is no` on a word and not a letter; end a sentence at a terminator followed by a closing quote; scan each distinct path once and say so on a NOTE; make `help <unknown>` say so and exit 2; name every independent invocation problem in one refusal in the tool's own voice; place MORE in the stream table or move MORE to stdout as the family does; make the dry run check what the real run needs; give `version` its own `--json` or name the exception; and bring the spec's grammar, the placeholder names in the per-verb help, the README row and the internal map row into line with the binary.

## Good, keep

- The first run. `example --dry-run`, a write that keeps identical pages and refuses different ones (`kept=` versus a refusal), and three pasteable lines each announced to exit 1. Nothing about the first five minutes needs guessing.
- All-or-nothing reads. One unreadable path refuses the run and scans nothing, saying "NOTHING was scanned, which is not a green": a partial green never escapes. An all-skipped run is `SKIP files=0`, never an OK scan.
- `shapes`: the detector as a table, each row with its class, what it finds, how, a sentence it reports and one it passes, held true by a test (internal/selftalk/rules_test.go:48). A reader can audit precision and a precision finding is checkable against it.
- Per-class `--max` with a `MORE` line and its remedy, in both renderings (in `--json` the `more` array carries kind, shown, total, remedy per elided class), and the honest welcome case (the DATED count) on one line. Six hundred of the first class cannot eat one of the second, the class a reader is least likely to know about.
- The every-run NOTE that a green clears the known shapes, never the file, and the rule-document banner that prints above a finding in a rule-named file, saying what the finding is FOR and never a reason to soften a rule. Both refuse the temptation to give the reader an exit-0 summary where the run is partial.
