# nova-self-talk READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: c7257c468a7a
READ: 8/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-self-talk version` prints `nova-self-talk v1.0.1-0.20261006145440-c7257c468a7a linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch directory made for the trial; no live store, no server, no network. Read cold first: `help`, every verb's `-h`, docs/SPEC.md's section, docs/CLI.md's section and the README row. Then every verb was run: the banner's setup and its three example lines as printed, `example` with and without `--dry-run` and `--json` (fresh, repeated, over a changed page, into a directory that cannot be made), `shapes`, `version`, and the scan over a page of my own with 27 lines of both classes, every licence, a table row, a list item, a fenced code block and a quotation, plus standard input, an empty file, a file with a NUL byte, random bytes, a system binary, a directory and every refusal the help names.

## Reasons

READ. The banner answers the three questions in its first nine lines (what it flags, how it reads, the first run), glosses both classes where they are named, states the output contract line by line with its stream, and gives one exit table. `shapes` prints the live detector table with a sentence each row finds and a near miss it passes; a test runs both through the scan, so the table cannot claim a shape the scan misses. That is the right way for a pattern tool to say exactly what it does, and an AI can predict the scan from it. The first run needs nothing but the binary, and every line it offers exits as the help says.

What keeps READ at 8. The banner is still 94 lines (cmd/nova-self-talk/main.go:28), with the print-line inventory and a flags essay between usage and the examples. The per-verb help is thinner than the banner and wrong for the verb in places: `scan -h` and `example -h` drop the required `<file>...` and `<dir>` from their usage lines, every verb's `-h` ends with the scan's exit table (`1 findings ... An all-skipped run exits 0`), `version -h` and `shapes -h` included, and `--skip` and `--rule-doc` print `<value>` where the banner says `<basename>`. The stream table never places `SELFTALK MORE`, which goes to stderr, so the banner's own `2>/dev/null` recipe loses the only line saying findings were cut. The spec has drifted from the binary in three places: both output grammars (docs/SPEC.md:114 and docs/SPEC.md:1870) print `STANDING: <claim>` where the binary prints `STANDING match="<words>": <sentence>`; docs/SPEC.md:298 lists "four informational second tokens" and leaves out MORE; and the test index cites lines 1680, 1684 and 1691 (docs/SPEC.md:3080-3082), which now hold another section. The spec says table rows and list items are separate units, but only for the second class; it never says the first class runs them together (USE, finding 1). The internal map row still calls the package a "journal stream" (internal/docs/catalog.go:111).

USE. The first run is clean. `example --dry-run ./pages` says what it would write and the next command; the real write lays down two pages; a second run writes nothing and reports `kept=`; a changed page is refused, never replaced. The three pasted example lines each exit 1 with findings on stderr and the DATED count, count line and NOTE on stdout. `--max 2` printed two findings per class and one MORE line per class; `--json` carried the same counts, items and `more`; a refusal under `--json` is one JSON object. Standard input works as `-`. A missing file among good ones refuses the whole run ("NOTHING was scanned, which is not a green"); a directory is refused; a bare word that is no file is told the verbs; a late flag is refused with why; `--skip` of a name no file has gets a NOTE; an all-skipped run is `SKIP files=0`, exit 0, never OK. On plain prose the classes behaved as `shapes` says: fallible, bad at, terrible at, can't trust, broken and a lowercase `i am` were STANDING; a dated sentence was counted, not quoted; I'm the best, I have no recall, I always forget, I tend to were flagged by shape; a prohibition and a `RULE:` line passed.

What keeps USE at 7. The first class reads markdown structure wrong, and the scan's whole output is a line number and a sentence. A table row, a list item and a fenced code block that follow a line with no blank between them flatten into one sentence: on my page the claim in a table row on line 20 printed as `mine.md:19: STANDING match="worst": " col I am the worst at this - I always overpromise I am fallible in code.`, the wrong line and four source lines of text, and a three-line table reported its claim on the header row (`t.md:3: ... a b ------ x I am the worst at this .`) where the claim is on line 5. Fenced code is scanned as prose and flagged, which the help does not say. A binary still scans green: `/usr/bin/ls` and 300 random bytes print `SELFTALK OK`, exit 0, and a file with a NUL byte is scanned as prose. The refusal defects carried from 1.1.0 are all still there: `--bogus --max abc` names only the unknown flag; `--max abc` and `--skip a/b` refuse in the flag library's voice (`invalid value "abc" for flag -max: parse error`, `invalid value "a/b" for flag -skip:`); `example --bogus` says `flag provided but not defined`; `help frobnicate` prints the whole banner at exit 0. `example --dry-run /proc/nope` says OK and `would-write=` where the real run refuses. `version extra` says `got 1` without the word and points at `version -h` where every other refusal points at `help <verb>`. Smaller: the first class does not read `We are bad at estimates` while FORECLOSURE reads `We have no recall`, and the DATED licence takes `first time` as a date, so `I am fallible, but I fixed it the first time.` is counted as a record.

A 10 would split the first class's sentences at table rows, list items and code fences and report the claim's own line, say what it does with fenced code, refuse a file that is not text, name every invocation problem in one refusal in the tool's own voice, make `help <unknown>` exit 2, give each verb's `-h` its real usage line and its own exit table, place MORE in the stream table, make the dry run check what the real run needs, and bring the spec's grammars, token list and line references into line with the binary.

## Good, keep

- `shapes`: the live detector table, each row with a sentence it finds and a near miss it passes, pinned by a test that runs both through the scan.
- All-or-nothing reads: one unreadable path or a directory refuses the run and scans nothing, saying "NOTHING was scanned, which is not a green"; an all-skipped run is `SKIP files=0`, never OK.
- The every-run NOTE that a green clears the known shapes, never the file, and the DATED count on one line instead of the good news at length.
- `example` never replaces a page: a changed page is refused, an identical one is kept and reported as `kept=`.
- Per-class `--max` with one MORE line per class, so a flood of the first class cannot hide the second.
