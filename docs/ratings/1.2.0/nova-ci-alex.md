# nova-ci READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 3a5792afa395
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-ci version` prints `nova-ci v1.0.1-0.20261006144833-3a5792afa395 linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch Go module made for the trial (`example.com/mod`, packages `a` and `b`, one slow test, one red test, one SLEEPS skip, one functional-tagged file); `local --dry-run` and `new-verb --dry-run` were run in a copy of this checkout. `bench run` was driven end to end from a second machine (a darwin build of the same head) against the bench, with its run directory under a scratch root. No live store was dialled, no server was started, and `github receipt` was tried only with `--dry-run` and its refusals.

## Reasons

READ. The banner says what the tool is in one line, splits the verbs into "any Go module" and "a nova-tools checkout", and its first run (`slowtests --example`) needs nothing installed. Every verb answers `-h` and `help <verb>` with its banner excerpt, its flags, its own exit-code row and an `effect:` line. Unknown flags list every flag and name the nearest (`--budg` gets `did you mean --budget?`); unknown verbs list the verbs. The `bench run` paragraph is new and good: what is copied, what runs, under what environment, and that it removes its own directory and nothing else.

What keeps READ at 7. `bench run -h` prints the whole banner a second time under `exit codes:` (cmd/nova-ci/bench.go:40 hands the skeleton exitTable's full-banner string, cmd/nova-ci/main.go:209), so the one new verb has the noisiest help in the tool; `bench -h` does the same. The slowtests paragraph says what `--max` does twice in a row (cmd/nova-ci/main.go:66 and :70) and never says its default, 20, which only docs/CLI.md:2191 gives. The flag lists print no default for any flag (`--budget`, `--max`, `--root`, `--cache`) and print `<string>` for the file flags `--allowlist` and `--sleeps`. The banner's exit summary names three verbs that exit 1 (cmd/nova-ci/main.go:125) and leaves out `bench run`, which passes the command's own 1 through. `bench run`'s usage says `-- <go command>` and runs any command (`-- ls -la` ran). The help never says the allowlist and SLEEPS ledger accept only packages under `cmd/`, `internal/` or `tools/`, nor that a bench label is read from `.github/workflows/ci.yml` in the working directory, nor the 3x headroom bound. The spec is 3,024 lines and, apart from the budget and `bench run` sections, is the class tests of this repository's CI; `functional`, `new-rule` and `new-verb` have no section in it. Three 1.1.0 READ findings are still there: docs/TESTS.md:948 says `--enforce` exits 2 (it exits 1), cmd/nova-ci/timing.go is still an undispatched `//go:build ignore` main, and only `slowtests` takes `--json`.

USE. The first run is clean: both banner examples exit 0, one with a CI-SLOW line and one `CI-SLOW OK`, and `--json` renders the same verdict as one object. Fed a real `go test -json -count=1` stream from the scratch module, `slowtests` named the slow package and its slowest test, `--test-budget 1` named the test, `--max 1` printed one finding and a `CI-SLOW MORE ... total=3` line, the SLEEPS skip failed the run at exit 1 on every leg as the help says, and every bad input (a non-TestEvent line, `NaN`, a negative budget, a missing file, a malformed or over-headroom row) was refused at exit 2 with one line naming the problem and a command to run. `functional ./a ./b` printed `./b` and a run pattern; a pattern matching nothing and no argument were refused. `local --dry-run` in this checkout named the merge base, the selected packages and the exact make line, and ran nothing; a bad `--base` was refused with the fetch to run. `new-rule` and `new-verb` `--dry-run` listed their files and wrote nothing. `bench run` is the best verb here: `go vet` came back `CI BENCH host=<bench> run=<dir> exit=0 removed=yes`, a red `go test` streamed its failure and exited 1 with `exit=1 removed=yes`, the run directory was gone afterwards, and an unreachable host was refused with `run: ssh <host> true`. `github receipt --dry-run` checked the fields and named every bad one in one refusal.

What keeps USE at 7. slowtests says it works "in any Go module", but its `--allowlist` and `--sleeps` refuse every package outside `cmd/`, `internal/` and `tools/` (internal/ci/slowtests/slowtests.go:404): in the scratch module, the full import path `example.com/mod/b` and the short `b` were both refused as "must be the full module-relative path", so a SLEEPS skip there can never be ledgered and fails the run with no way out. A bench label in the measured column is read from `.github/workflows/ci.yml` in the working directory (internal/ci/slowtests/slowtests.go:321), and outside this repository the refusal lists the labels as `()`. An allowlist row naming a package the stream does not have (`internal/a`) is silently ignored. An empty stdin, the stream of a `go test` that built nothing, is `CI-SLOW OK packages=0` exit 0. `--budget` and `--package-budget` together, shown as alternatives in the usage, are accepted with `--package-budget` winning; `--load` without `--cpus` silently reads the host's CPUs. The CI-SLEEPS line escapes the blanks inside its prose (`not on the\x20SLEEPS\x20ledger\x20(no\x20--sleeps\x20given)`, cmd/nova-ci/slowtests.go:183). `new-rule foo` in the scratch module, which is no nova-tools checkout and has no git, wrote `internal/ci/foo_class_test.go`, a fixture and `make/rule_foo.mk` at exit 0, where the help promises exit 2 for "not a checkout". The refusal grammar is split again: `bench run` refuses as `BENCH-RUN REFUSED: ...` (internal/tool/tool.go:537) where every other verb says `nova-ci <verb> REFUSED:`, and its missing-`--host` refusal points at `nova-ci help`, not `nova-ci bench run -h`. Its fallback note `CI BENCH PASSED host=... next=...` (internal/bench/bench.go:199) reads as a passed run when it means a host passed over. Normal output is six shapes (`CI-SLOW`, `CI FUNCTIONAL`, `nova-ci local:`, `would write`, `CI BENCH`, `CI RECEIPT`), and only slowtests has `--json`. The four 1.1.0 USE findings are all still there: `functional ./...` prints bare `b` where explicit dirs print `./b`, the JSON facts carry no `per_cpu`, the help omits the 3x headroom bound, and an unknown verb (`helpp`) names no nearest.

## Good, keep

`slowtests --example` is a first run from the binary alone, and on a real stream every bad input is one refusal line with a command that runs. `bench run` does exactly what its paragraph says: it copies, runs under nice with the bench's cache, streams the output, passes the exit through and removes its own run directory, and the closing `CI BENCH ... exit=<n> removed=yes` line is the receipt an AI needs. `local --dry-run` shows the merge base, the selection and the exact make line before anything runs. `github receipt` names every bad field in one refusal and `--dry-run` dials nothing. Unknown flags name the nearest flag.
