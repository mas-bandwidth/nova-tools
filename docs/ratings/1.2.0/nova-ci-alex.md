# nova-ci READ and USE rating, nova-tools 1.2.0

Rater: deepseek/deepseek-v4.1-flash in dsh, a sprint worker on a friend's re-rate card
Build: bc9ee29ed2b0
READ: 8/10
USE: 7/10

No v1.2.0 tag exists on the forge, so this rates the release candidate at the head of `sprint/mechanical-2026-10-02`: `nova-ci version` prints `nova-ci v1.0.1-0.20261007214711-bc9ee29ed2b0 linux/amd64 go1.26.6`. Read cold from `nova-ci help`, every verb's and group verb's `-h`, and the nova-ci material in `docs/CLI.md` and `docs/SPEC-CI.md`. Used for real on a throwaway Go module (`example.com/mod`, packages `a` and `b`, a two-second test and a `SLEEPS:` skip) whose `go test -json` stream was piped into `slowtests`; and in the checkout for `functional ./...`, `local --dry-run`, `new-rule --dry-run`, `new-verb --dry-run` and `github receipt --dry-run`, with every refusal below reproduced. No live store, no server, no network. Built and run on a Linux bench.

## Reasons

READ. The banner answers the three questions before its usage lines: line 1 says what the tool does, the `how it works:` paragraph names the nouns (go test -json events, package selection, a checkout, a receipt) and where the state lives, and `first run:` says nothing is needed because `slowtests --example` carries a built-in stream. Every verb and group verb answers `-h` at exit 0 with its flags, its own exit row and an `effect:` line, so a reader learns whether a verb reads, writes or delivers without running it. Refusals are the house grammar and usually name every independent problem in one line: `github receipt --dry-run --from-runner` named all five missing fields with what each wants, and a bad `--budget`, `--max` or ledger row is refused with its unit or its shape. The top-level help is long but honest, and the `slowtests` paragraph compresses the whole contract (the allowlist row, the 3x headroom ceiling, the `SLEEPS:` marker, the cache note) into the place a reader first meets the verb.

What keeps READ at 8. `bench -h` and `bench run -h` print the whole 126-line banner under `exit codes:` instead of a group index and a verb table (cmd/nova-ci/bench.go:35, cmd/nova-ci/main.go:210), so the tool's one compound verb has the noisiest help in it. No flag prints its default (`--budget` 60, `--max` 20) and the two file flags print `<string>` (cmd/nova-ci/slowtests.go:125-126). An unknown verb lists the verbs but names no nearest, while an unknown flag does (`did you mean --budget?`). The banner's `example:` block is three lines of which two are the same command with one value changed, so it teaches less than the first run does. `docs/SPEC-CI.md` is a 3,112-line spec of this repository's class tests with a bench-run section but no contract section for `functional`, `new-rule` or `new-verb`, and `docs/CLI.md:2371` opens the nova-ci section without the `### First run` heading the standard asks for. A 10 would keep the two compound help pages short, print each flag's default and its file placeholders, give a far unknown verb the nearest name, and give every verb a short contract beside its class tests.

USE. The first run needs nothing: `slowtests --example --budget 60 --load 4 --cpus 16` printed a real `CI-SLOW` line and a `CI-LOAD` line at exit 0, and `--json` rendered the same verdict as one object. On the throwaway module, a real `go test -json -count=1` stream produced `CI-SLOW package=example.com/mod/a seconds=2.0s budget=1s`, a per-test `CI-SLOW test=...` line and a `CI-SLEEPS` line for the skip; `--enforce` turned the finding into exit 1 exactly as the help says. The bounded-output path works (`--max 1` prints one line), bad values are refused with their unit, an unreadable `--allowlist` is refused, and `functional` refuses a pattern matching no package with the command to rerun. `local --dry-run` printed the base, the merge base, all 145 selected packages and the exact `make test` line without running anything; `new-rule --dry-run` and `new-verb --dry-run` listed their files and wrote nothing; `github receipt --dry-run` validated every field and printed the row with `ev=-`.

What keeps USE at 7. The ledgers make the banner's "slowtests ... work in any Go module" false: both the full import path `example.com/mod/a` and the short `a` were refused as "must be the full module-relative path", because `--allowlist` and `--sleeps` accept only packages under `cmd/`, `internal/` or `tools/` (internal/ci/slowtests/slowtests.go:440). In a plain module a `SLEEPS:` skip therefore fails the run at exit 1 and there is no row that can clear it. The refusal sentence itself is escaped (`not on the\x20SLEEPS\x20ledger\x20(no\x20--sleeps\x20given)`, cmd/nova-ci/slowtests.go:188). `functional ./...` prints one 28,680-character `-run` argument naming 829 tests, with no bound or note that it must travel as one argument. `--json` facts carry `load` and `cpus` but not the `per-cpu` figure the line prints (cmd/nova-ci/slowtests.go:388-392), and only `slowtests` accepts `--json` at all, so the family still has several line-only shapes. `new-rule --dry-run` in a module that is not a nova-tools checkout lists `internal/ci/...` paths at exit 0, though the help promises exit 2 for "not a checkout" (cmd/nova-ci/newrule.go:55). `--load` without `--cpus` silently reads the host's CPUs, and `--budget` with `--package-budget` is accepted with the latter silently winning, though the usage shows them as alternatives. A 10 needs the ledgers to accept any module-relative package, the SLEEPS prose out of the escaped value, a bounded `functional` selection, `per_cpu` in the facts, `--json` on every verb, a checkout test in the scaffold verbs, and a refusal when paired flags are given alone.

## Good, keep

`slowtests --example` is a first run from the binary alone with no store, no module and no setup, and its `CI-SLOW` and `CI-LOAD` lines are a real result that teaches the measurement-versus-verdict distinction; `--enforce` then turns the same finding into the exit the nightly leg needs. The refusal grammar is the best part of the tool: one line names every independent problem at once (`github receipt` named all five missing fields) and normally ends in a command that runs, and a near-miss flag gets `did you mean --budget?`. `--dry-run` prints the exact plan from the same code path for every write and delivery verb, so `local`, `new-rule`, `new-verb` and `github receipt` are safe to try before they run. `--max` keeps output bounded with a `MORE` line and a total, `github receipt --dry-run` prints `ev=-` and dials nothing, and every verb's `effect:` line says whether it reads, writes or delivers.
