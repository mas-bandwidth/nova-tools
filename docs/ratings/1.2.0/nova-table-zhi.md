# nova-table READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: d5f6f465a3ad
READ: 8/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-table version` prints `nova-table v1.0.1-0.20261006152209-d5f6f465a3ad linux/amd64 go1.26.6`. Built and run on a Linux bench machine. The root help, `help <verb>` and all 35 verb, subverb and version `-h` pages were read cold. Then the banner's example, every verb's `example:` line and about sixty more calls ran against a throwaway Redis that listened on a Unix socket only (`--port 0`, no save, no append-only file), made inside the trial directory as the banner's own recipe says and shut down with `shutdown nosave` afterwards. No live store was touched.

## Reasons

READ. The banner says in one line what the tool is, then in five lines how it works. Next it gives what a first run needs, a store-less `--dry-run` example, and a four-line throwaway-store recipe that worked as printed. Each `-h` page has usage, an example, its flags grouped as flags / connection / write epoch and receipt where it has them, exit codes and an `effect:` line. The help forms all work: `help cell`, `cell -h`, `help cell add`, and `--version`. An unknown verb, subverb, flag or argument count is refused with the full list and a `run:` line.

What keeps READ at 8. The banner is still 127 lines, and the column grammar, fold table, epoch rules and shell rules still come before the `example:` block. The same 385-character `effect:` sentence is repeated on 22 write pages. On the view verbs it talks about "the table, its epoch, its rows and columns, a bound cell", none of which a view has. `--score` and `--at-epoch` print as `<string>` when they take numbers. Three things are never said: member records are shared by every table that uses the default `--member-prefix`; a new epoch starts with no rows; and `check` never says what it checks. Dated quotations of the owner are still in the package's comments (pkg/ntable/render.go:26, :39, :42, :45, :60, :67, :396; cmd/nova-table/order.go:15). The guide now opens with a statement of the design (docs/nova-table/README.md:3), which is better.

USE. The banner's example ran first time and drew the table it promised. Every verb example ran. The one exception is `cell move`'s example, which moves `b2` right after `cell remove`'s example has removed it. Every write prints a typed line with `trips=`. `--receipt` adds an event id and the before and after revisions. Formulas and folds are exact: `sum(ok+failed)`, `pct(ok/ok+failed):pooled` giving 60.0% over 3 of 5, the `union` fold of members, and `--exclude` leaving a member out of the counts. A bound cell is refused for `cell add` and `clear` with the owner verb as the remedy. A standing `row sort --keep` refuses `row move` and names `row sort --manual`. `col del` on a column that still holds text names the cell to clear. Stale and ahead epochs are refused, naming both numbers. `--at-epoch 0` reads the old epoch after the epoch hash moves. `batch` reports `changed=no` and a code on each refusal. `shell` runs from a pipe, prints receipts, names the failing line, and `--keep-going` exits with the highest status. `--dry-run` with no store prints the exact FCALL with `dialled=0 written=0`.

What keeps USE at 7. Some state traps the user, and some outputs claim more than happened. After a plain `drop`, `show` says create, but `create` with new columns is refused with `run: nova-table set`, and `set` is refused with `run: nova-table create`. Neither names the way out, `drop --definition`. This loop was reported on 2026-10-02 and is still there. Member records are shared by every table on the default prefix. A batch `create` with `expect.absent` into one table is refused `MEMBEREXISTS` ("observed record without placement") for an id that has only ever been placed in another table. So the help's own batch example is refused on any store where the banner example has run. `member find u2 shared` says `state=unplaced` for a member placed in u1. `cell remove` of an id that is not in the cell prints the same `TABLE CELL ... n=2` line as a real remove, with exit 0. `cell move` from a column to itself prints a move. `cell move` of a non-member is refused with the bare code `NOTMEMBER`. A view's summary line prints a literal `-> ETA` with no value. `watch --out` prints nothing on success. Malformed batch manifests exit 1, not the 2 that usage gets, and are still refused one problem at a time. `--json` is still only on `batch` and `member read`.

The reading says: a careful tool whose writes can be trusted and whose refusals nearly always point the way. To reach 10 it needs the drop/create/set loop closed, member identity scoped the way the help describes, no-op writes that say they did nothing, and `--json` on the reads.

## Good, keep

The banner's throwaway-store recipe works as printed, and the unreachable-store refusal prints it again with the address it tried. Every write prints `trips=`, and `--receipt` gives the event id and both revisions. `--dry-run` with no store prints the exact FCALL with `dialled=0 written=0`, and refuses a bad column spec exactly as the real run does. Bound cells, standing sorts, stale or ahead epochs and `col del` of a column with text are each refused with a runnable remedy. Formulas and folds compute exactly (`pooled` 60.0% over 3 of 5). Layered help (`help cell`, `cell -h`, `help cell add`) answers with no store. `shell` names the failing line and keeps the highest status.
