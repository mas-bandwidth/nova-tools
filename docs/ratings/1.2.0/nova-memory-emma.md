# nova-memory READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 7525efe26a92
READ: 7/10
USE: 7.5/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02 as staged for this card. `nova-memory version` prints `nova-memory v1.0.1-0.20261006142910-7525efe26a92 linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch directory made for the trial: the banner's two-file corpus, then a third note with frontmatter, a wikilink and a long paragraph, a dated log, a second root and a gold.tsv. No live store, no server.

## Reasons

READ. The banner is a good door. One line says what the tool is for, "how it works" says the index is built in memory per run and nothing is written, the setup block makes a corpus in four lines, and the example runs from it unchanged (cmd/nova-memory/main.go:43). Every required flag says why it is required (`--channels`, `--k`, `--floor`, `--links`, `--pin`), every verb's `-h` carries its synopsis, a worked example, an `effect:` line and its flags, and the exit codes are spelled per verb. An AI could run every verb from the help alone, and I did, apart from eval's file.

What keeps READ at 7. The first thing the banner teaches is the CAL rule: a hit at or below the CAL score "is no better than noise" (cmd/nova-memory/main.go:54). The same banner's own example then shows its rank-1 hit at score=0.99 under CAL 1.46, and docs/CLI.md:416 repeats the rule over a quickstart whose right answers (3.48, 3.12, 2.97) are all under CAL 4.05. A reader who follows the rule throws away the right answer; a reader who notices the contradiction stops trusting the line. eval's `<gold.tsv>` is still never described in the banner or `eval -h` (cmd/nova-memory/main.go:70); I guessed query, a tab, then the expected path, and was right. boot is still described as "the memories a session loads" (cmd/nova-memory/main.go:132) when it reads nothing out: it prints `BOOT OK files=2 bytes=338`. `verify -h` says `--root` is repeatable (cmd/nova-memory/main.go:376), and verify refuses two. Every `-h` repeats the whole exit-code paragraph, which opens with the hard-to-parse "by verb (each ran here), search, stats, boot: 0 ran" (cmd/nova-memory/main.go:143), and `version -h` says "the index lives in memory for the run" for a verb that builds none (cmd/nova-memory/main.go:252).

USE. The first run is the banner's: setup, then `quickstart --root ./corpus` runs stats, one search and one check, printing each command line above its output, and ends saying bm25 and k=3/2 were choices, not defaults. search, check (file and stdin), stats, verify (coverage, frontmatter, exempt, links gate and info), eval (pass and fail), boot (pass and refusal), multi-root, `--exclude`, `--` before a dash word and `--json` on every verb but version all did what the help says. `search --root ./corpus` with nothing else names `--channels`, `--k` and the missing query in one run, each with a hint. An unknown flag names every flag the verb takes and points at `search -h`. `--floor 0` and `--k 0` are refused with the reason. A miss is exit 0 with a `SEARCH MISS every query term is out of vocabulary` line. verify kept the frontmatter finding visible next to the wikilink one, and the counts carry the totals.

What keeps USE at 7.5. The CAL line called every right hit noise in every run I made: 0.99 under 1.46 on the banner's corpus, and on a four-file corpus the optics note answering "laser alignment drift" at 1.21 and the log at 2.27, both under CAL 3.01. Snippets still stop at 120 bytes (internal/memindex/channels.go:321), in the JSON too, so the long note was cut mid-sentence before the part I searched for. boot refuses at the first missing pin entry and names only that one (cmd/nova-memory/boot.go:123); a pin with two missing files took two runs. verify's coverage passes on a mention, not a link: adding "We do not cover optics here." to the index cleared the optics coverage finding (internal/memindex/verify.go:267). The text-mode eval MISS line prints `query=zebra\x20stripes`. Missing-flag refusals still send the reader to the whole banner (`run: nova-memory help`) where the unknown-flag refusal already sends them to `search -h`.

A 10 would make the CAL rule match what the tool's own examples show (or replace it with a calibration that a right short-query hit clears), describe gold.tsv in `eval -h`, say boot validates and prints no content, let a caller see a whole passage, report every bad pin entry in one run, make coverage require a link, and send every refusal after a verb to that verb's `-h`.

## Good, keep

The index is built in memory each run and nothing is written; every verb's `-h` says so on its `effect:` line. Every required flag is required for a stated reason, and a refusal names all the missing ones at once with a hint each. An unknown flag lists every flag the verb takes. quickstart prints each command above its output and says at the end which choices it made for you. Every receipt carries class, root and file:line, and the log-class NOTE is a good guard against mistaking a record for a lesson. verify bounds findings per kind with the totals always printed, and eval refuses a floor that cannot fail.
