# nova-decide READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 164014a60238
READ: 7/10
USE: 8/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-decide version` prints `nova-decide v1.0.1-0.20261006145059-164014a60238 linux/amd64 go1.26.6`. Read cold from `nova-decide help`, every verb's `-h`, docs/SPEC-NOVA-DECIDE.md and the nova-decide section of docs/CLI.md, then used on a Linux bench machine in a scratch directory with copies of the testdata and files written for the trial. Every deciding verb ran on the fixed backend; the jev backend was run only to its key refusal and its `--dry-run` (no key, no model call). No live store, no server.

## Reasons

READ. The banner's first line says what the tool is, the usage block names all fourteen verbs, and ten examples run from a checkout root. Every verb's `-h` prints its usage line, its banner example, a short paragraph on what the decision asks, every flag with a required marker, the exit codes and an `effect:` line. The built-in decisions explain themselves well: `gate -h` says how a failure is routed and what an unset bar does, `score -h` names all eleven escalation classes, `import -h` says where each label comes from and that a second import adds nothing.

What keeps READ at 7. The how paragraph, the first thing a cold reader parses, is still a compressed pseudo-run (cmd/nova-decide/main.go:59) with a state written `R?` and an output line the tool does not print. The help does not show defaults that the code sets: `calibrate --bars` is `0.5,0.7,0.9` (cmd/nova-decide/main.go:240) and `findings --bar` is `0.5` (cmd/nova-decide/main.go:317), and neither `-h` says so. `brief -h` names the options of ambiguous_step and not those of minutes. The banner says "A verb that lists takes --max", and the two verbs that list lines, calibrate and findings, refuse `--max`. Every deciding verb's effect line says `delivery: sends beyond this machine` when the fixed backend only appends a file. `import` and `score-grades` have no example line in the banner or in `-h`, and grade's usage line omits `--examples`, `--held-out` and `--seed`. The code's opening comment and the spec's title still call this a system "trained from its own record" while the spec says the training verbs are not built, and the spec's two-sides table (docs/SPEC-NOVA-DECIDE.md:13) lists neither import nor score-grades. docs/CLI.md is still one prose block from the read line to the first-run mistakes.

USE. The banner's first run works, and so does the whole lifecycle on files made for the trial: ask, read, score, attempt, grade, gate (with and without `--bars`), brief over one file and over a directory with `--max 1` and its `MORE` line, outcome, calibrate on a noul and on `verdict=BOUNCE`, findings, and import of a verdict and a HOLD report. The 1.1.0 complaint that a repeated ask with no `--op` asks again is fixed: the id is now derived from the schema and the state, and the second run prints `recorded=existing` with the same `reply-5435d7a6f30f`. The record lock holds: 20 concurrent asks with one `--op` left one line, 20 with distinct ops left 20, and 10 concurrent outcomes added 10. `--dry-run` creates no file on ask, import and outcome; `--json` gives one object on success and on refusal, with `why` and `remedy`. Missing flags are all named in one run; an unknown flag lists the verb's flags with a "did you mean"; a bad schema, an answer outside [0, 1], an unknown choice, a reused op over another state, a corrupt record line (named by file and line), a conflicting outcome (exit 1, with the recorded label and its time) are each refused with why.

What keeps USE at 8. Some remedies are not commands, or are wrong for the failure: an empty state ends `run: make --answers answer every question of the schema` (cmd/nova-decide/main.go:778), which has nothing to do with the state; a brief whose fixed answers do not fit ends `run: run the same line again` (cmd/nova-decide/main.go:739), which fails the same way. Most refusals point at the whole banner (`run: nova-decide help`) rather than the verb's `-h`. Two greens over nothing: `findings --record missing.jsonl` is `FINDINGS OK scored=0` exit 0, and `import --verdicts 'nomatch/*'` is `IMPORT OK` with every count zero, exit 0. An answers file with eleven questions the schema does not have (score's answers given to read) is accepted without a word. score-grades over a log of the wrong shape prints a Go type (`struct { Lines []decide.LogLine "json:\"lines\"" }`). Carried from 1.1.0: `help --json` is an unknown verb, `help ask --json` ignores the flag, ask's `--dry-run` prints no ANSWER lines, the GATE OK line does not print the bars it routed by, and minutes' options appear in neither the refusal nor the help.

A 10 would make the how paragraph the fixture's own two lines, print every flag's default in `-h`, make every remedy a command that changes the failing input and points at `<verb> -h`, refuse a green over a missing record or an empty glob, class a fixed run as a local write, give calibrate and findings `--max` or drop the banner's claim, and make the spec's title and table match the built verbs.

## Good, keep

The fixed backend makes every deciding verb runnable with no key and no network, and the banner's examples run as printed from a checkout root. Idempotency is now the default: an ask with no `--op` replays from the schema and the state, and an op reused over another state is refused, not overwritten. The record lock held under 20 concurrent writers with no lost and no doubled lines. A corrupt record line is refused by file and line number. `outcome` is once-only with a clear exit 1 that names the recorded label and its time. `--json` carries a refusal's `why` and `remedy`, and `--dry-run` writes nothing. calibrate refuses a one-sided record and a misspelled option instead of printing a meaningless AUC. The jev backend's key refusal names the stable `reason=key_absent` and the exact `nova-secrets exec` line.
