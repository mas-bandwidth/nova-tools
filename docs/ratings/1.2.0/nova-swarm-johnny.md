# nova-swarm READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card; the rating is this worker's, not the friend's
Build: 7e117276e198
READ: 6.5/10
USE: 7/10

No v1.2.0 tag exists yet. The build rated is the head of sprint/mechanical-2026-10-02, built and run on a Linux bench in a scratch directory: no live store, no server.

## Reasons

READ. The banner says what the tool is in one line, gives a short how-it-works and a credential and sandbox paragraph, and its three examples spend nothing. Every verb answers `-h` with its usage, its flags (most with `required:` and a default), its exit codes and, on most verbs, an `effect:` line. An unknown verb or flag gets one `REFUSED` line that lists the flags and ends with `run: nova-swarm help <verb>`. A store that is missing says what to run (`run: nova-swarm slots init --store nostore ...`). That is the shape an AI wants. The safety ideas read well: the key is data, the wall is on by default and its opt-out is named on the result line.

What costs the score. The help is wrong in places a reader acts on. `verify -h` says `writes nothing` (cmd/nova-swarm/main.go:173), and verify writes `<result>.receipt` beside the result (cmd/nova-swarm/main.go:533), even inside a published results directory. The `native -h` example uses `--slot slots/1 --root jobs`, and native refuses that slot as outside the root (cmd/nova-swarm/main.go:138). `lint -h` says `--max` caps the item lines, and the NOTE lines are never capped. Three places name the typed header three ways: `template -h` says KIND, PATHS, TEST, DEPENDS-ON and DONE-WHEN; `lint -h` says KIND, PATHS, TEST, PAUSED and DEPENDS-ON; the lint itself asks for KIND, PATHS, TEST and DEPENDS-ON, then notes START and STOP. Placeholders drift between `<file>`, `<string>` and `<lint <file>>` on one screen. `worker -h` has no flags and no example; `slots run -h` has no example and does not say it passes the command's exit code through. `step -h` never says what a script step is, and that is the refusal a stranger meets first.

The spec has not been brought to the banner. It says eleven living verbs (docs/SPEC-SWARM.md:48); the binary has twelve, and the spec's usage fence has no `step` and no `slots run`. Its member paragraph is now one 20067-character line (docs/SPEC-SWARM.md:84). Its output grammar names `SLOTS OK store=... capacity=...` and `SLOTS GRANTED` (docs/SPEC-SWARM.md:129); the binary prints `SLOTS INIT OK ... reserve=...` and `SLOTS OK owner=... granted=...`. The pipeline chapter still describes a card as stateless model calls (docs/SPEC-SWARM.md:316), and the only check is that the spec contains the sentence (pkg/swarm/pipeline_doc_test.go:24); native hands the whole card to one harness process.

A 10 is help whose examples run as written and whose `effect:` lines are true, one refusal shape everywhere, and a spec whose fence and grammar are the binary's.

USE. The banner's first run is clean: `template --name read-pr`, `template --name worker` and `lint --rules` exit 0. `template --name card` lints `LINT OK checks=45` with ten placeholder NOTEs, and once filled lints `LINT OK` with none. The slots loop works: init, take, a second take refused with `holders=me:1` and a `remedy=`, re-init refused with why, `slots run -- echo hi` printing `hi`, `slots run -- sh -c "exit 7"` exiting 7, `--wait 3s` waiting 3.3 s then refusing. `worker check` on an empty file lists ten drifts, capped by `--max 2` with a `WORKER MORE` line. `native` with a three-line fake harness ran end to end, walled (`sandbox=landlock`, 1.18 s) and with `--no-wall` (`sandbox=none-by-flag`), published `RESULT.md`, `usage.tsv` and a report, and `verify` passed the published result. Better than 1.1.0: native now reaches its flags, and every missing native or member flag is named in one run.

What costs the score. The `native -h` example fails as written, twice: the slot is outside the root, and a relative `--harness ./harness` passes the existence check and then fails as `fork/exec ./harness: no such file or directory` because the child runs in the job directory; walled, the same mistake reads `WALL REFUSED denied <job dir>` and `wall ran without a SANDBOX OK line`, which points at the wall, not the path. A card naming `REPO:` spent 78 s cloning before native refused for a missing `identity.tsv`, a check that needs no network; the remedy names a fleet `make -C fleet converge` from another repository and a `nova-config argv` a stranger does not have. `native --tokens 1000` with no usage store ended `NATIVE OK budget=-/1000`, exit 0: the budget was not measured and the run passed, where the spec's exit table says that case is exit 2 (docs/SPEC-SWARM.md:119). `profile` over a glob of garbage, over a glob that matches nothing, and over four real native jobs each print `PROFILE SUMMARY jobs=0` and exit 0. The `result` template still fails `verify` (line 1 is `# <task>`). Missing-flag refusals have no `REFUSED` word and no `run:` line, beside unknown-flag refusals that have both. `step` refuses as `nova-swarmstep REFUSED`. A lease taken from a shell lists as `state=live stranded=1` at once, and neither word is defined on `slots list -h`. No verb takes `--json` or `--dry-run` except `step` and `disk-guard`.

Not tried: `member` against a server (it needs a sprint server, and this card starts none), a real model call, and `step` on a script-only card (no help says how to write one). `disk-guard --dry-run` was run on scratch roots only.

A 10 keeps this slots loop and this native loop, makes the native example the one that runs, checks identity and resolves the harness path before any staging, and refuses an unmeasured numeric budget instead of passing it.

## Good, keep

`native` with a fake harness runs end to end walled in about a second and publishes `RESULT.md`, `usage.tsv` and a report under `<root>/results/<label>/<run>/1/`; the NATIVE line names the sandbox backend or `none-by-flag`, the card and binary hashes and the budget.

Every missing `native` and `member` flag is named in one run, and unknown flags list the flags that exist and end with `run: nova-swarm help <verb>`.

The slots loop: a full share is refused with the holders and a `remedy=` command, init never overwrites a store and says why, `slots run` passes the command's exit code through, and a missing store names the `slots init` line to run.

`worker check` lists every drift in one run, each saying what the field wants, and caps them with a `WORKER MORE` line.
