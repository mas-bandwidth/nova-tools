# nova-ci READ and USE rating, nova-tools 1.2.0

Rater: claude-opus-5-5 (Claude Code)
Build: 88bcd46a21ad
READ: 7/10
USE: 6.5/10

## Reasons
READ. `nova-ci help` and every verb's `-h` (slowtests, functional, local, new-rule, new-verb, bench run, github receipt, version, and the bare `bench` and `github` groups) were read cold, then docs/SPEC-CI.md and the nova-ci section of docs/CLI.md. The banner is honest about scope: it splits the verbs into "in any Go module" and "in a nova-tools checkout", labels each verb's effect (inspection, local write, delivery, store write), and gives per-verb exit codes. Most verbs' `-h` quote their own lines, flags and exit row and end in an `effect:` line, which is what an AI needs before it runs anything. The first place of confusion is `nova-ci bench run -h` and `nova-ci bench -h`: their `exit codes:` section is the entire 90-line banner followed by the bench row (cmd/nova-ci/bench.go:35 and :40 hand internal/tool the banner-plus-row that exitTable returns, and internal/tool prefixes it with `exit codes:` again). The first place of doubting a claim is cmd/nova-ci/main.go:37, "usage, in any Go module". Its `--allowlist` and `--sleeps` refuse every row whose package does not start with cmd/, internal/ or tools/ (internal/ci/slowtests/slowtests.go:405), so in a module of my own neither file can be written at all. The spec also contradicts the help: docs/SPEC-CI.md:197 says slowtests "refuse[s] any package whose summed elapsed time is over --budget", while the help and the tool treat CI-SLOW as a measurement unless `--enforce`. The first place of boredom is the spec: 3036 lines, nearly all of them class tests of this repository's CI. functional, new-rule and new-verb are never named in it, and the slowtests and bench run sections are two of about sixty. Smaller costs: the `--max` paragraph appears twice in the slowtests help (cmd/nova-ci/main.go:66 and :70); the top exit summary "1 the verb said no (slowtests, local, github receipt)" leaves out bench run, whose 1 is the command's own; and the github receipt line "with the password in the variable NOVA_SPRINT_REDIS_PASSWORD_ENV names" needs a second read to see that it is an indirection.

USE. Used for real on a Linux bench, inside the job directory, in a throwaway Go module of my own with fast, slow, SLEEPS-skipped and functional-tagged tests. No live store, no server, and no write outside the job directory. `slowtests` was run on `--example` (budget 60 and 120, `--json`, `--enforce`, `--package-budget`), then on the module's real `go test -json -count=1` stream with `--budget 1 --test-budget 1` and `--max 1`. It caught the slow package and both slow tests, flagged the unledgered SLEEPS skip as CI-SLEEPS at exit 1, and the MORE line named the hidden count and the flag. `functional ./a ./b` printed `./b` and `^(TestFunc)$`, which go test accepts, and `functional ./a` printed the packages=0 line. `local --dry-run` in this checkout printed the merge base, the two packages and the exact make line. `new-rule` (dry and real) and `new-verb --dry-run` were run in the throwaway module. `github receipt --dry-run` was run with good fields and with four bad fields. `bench run` was run against an unresolvable host, a host whose key is not known, a missing command, `--json` and a path holding `~`. About 25 refusals were provoked. Nearly all of them name the fault, the value and a command to run next. github receipt names every bad field in one turn. The bench refusals print the exact `ssh <host> true` to try.

The score is held at 6.5 by four things I reproduced. (1) A stream from a failed `go test` reads as green. Piping `go test -json ./doesnotexist` (setup failed), or a package that does not compile, into `slowtests --enforce` printed `CI-SLOW OK packages=1` at exit 0, and empty stdin printed `CI-SLOW OK packages=0` at exit 0. docs/CLI.md says to check go test's own status separately, but the banner does not, and the OK line does not say that a package failed. (2) The allowlist and sleeps files cannot be used outside nova-tools (above). (3) With NOVA_TEST_NO_HOST=1 set in the environment, which is the house bench environment and the one bench run itself exports, `bench run` panics with a 40-line Go stack from internal/testguard instead of a REFUSED line. (4) `new-rule my-rule` in a module that is not a nova-tools checkout wrote internal/ci/my-rule_class_test.go, a fixture and make/rule_my-rule.mk, and exited 0. The help says "2 ... not a checkout", and cmd/nova-ci/newrule.go:45 never checks. Smaller costs: the CI-SLEEPS line prints its ledger text with `\x20` escapes ("not on the\x20SLEEPS\x20ledger\x20(no\x20--sleeps\x20given)") because a sentence goes through oneline.Field (internal/ci/slowtests/slowtests.go:558); a flag-parse refusal names only the first bad value (`--budget x --test-budget y --max z` names only --budget); the bench refusals are headed `BENCH-RUN REFUSED` and `CI REFUSED` where every other verb says `nova-ci <verb> REFUSED`, and the missing-command refusal points to `nova-ci help` instead of `nova-ci bench run -h`; and only slowtests takes `--json`. A full bench run end to end was not exercised: no bench host was reachable by key from the bench itself, and I started no server to make one.

A 10 needs:
- slowtests to count failed and build-failed packages and to refuse, or at least name, an empty stream, with go test's own status named in the banner;
- the allowlist and sleeps rows to accept a package of any module, or the help to say they are nova-tools only;
- bench run to answer a host guard with a REFUSED line, never a panic;
- new-rule and new-verb to refuse a root that is not a nova-tools checkout;
- bench's `-h` to quote its own exit row only;
- `--json` on every verb and one refusal prefix across the tool;
- a short tool section in the spec covering every verb, with the class tests kept apart from it.

## Good, keep
Refusals that name the fault, the value and a runnable next step; github receipt lists every bad field in one turn, and the bench refusals print the exact `ssh <host> true` to try.
`slowtests --example`, a first run from the binary alone, and `--json` whose refusal is an object with `why` and `remedy`.
The CI-SLOW MORE line, which names the hidden count and the flag that prints the rest.
CI-SLEEPS failing on every leg, while a slow package is a measurement unless --enforce.
`--dry-run` on every write verb, printing the plan and a NOTE that nothing was written (local prints the merge base and the exact make line).
The banner's split between verbs for any Go module and verbs for this checkout, and the `effect:` line on every verb's -h.
