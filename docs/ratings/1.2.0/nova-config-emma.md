# nova-config READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 02c2dc398d85
READ: 8/10
USE: 7.5/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-config version` prints `nova-config v1.0.1-0.20261006143623-02c2dc398d85 linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch directory made for the trial, on a `--file` store and a scratch `XDG_CONFIG_HOME`; no PostgreSQL, no Redis, no server started. apply, status and inventory were tried against a dead Redis address and against fixtures only.

## Reasons

READ. `nova-config help` says what the tool is in one line, how the two stores divide the work, and a first run that needs no database; the usage block covers every verb; the kinds list says what each kind is and which flags add requires. Every verb answers `-h` with its effect, its required flags, an example and the exit codes, and every kind field's help says its type, its default and what reads it. SPEC-CONFIG.md is in sections (the boundary, kinds, schema, history, apply, lines, connecting) and its Lines block is the grammar the binary prints. cmd/nova-config/main.go is 648 lines, down from 1,646, and machine width --json is now the family envelope.

What keeps READ at 8. The help says things the binary does not do: the banner offers `--seat` as a store for every verb (cmd/nova-config/main.go:109), and `machine list --seat` is an unknown flag; the inventory first run (cmd/nova-config/verbs.go:176) names a fixture by a path relative to a source checkout, so it refuses as printed from anywhere else. The spec has drifted: its field table gives loop a `width` (docs/SPEC-CONFIG.md:52) the binary refuses as an unknown flag, gives fleet four fields where `kinds` prints six (docs/SPEC-CONFIG.md:49), and its apply order omits tier (docs/SPEC-CONFIG.md:488). The friend kind's help speaks of every friend as "she" and "her" (pkg/config/kind.go:412), a pronoun the tool cannot know. sprint set's decide flags carry calibration history (AUC, label counts, failure counts) in the help a caller reads to set one value (pkg/config/kind.go:444). `login --as` means a seat while every other verb's `--as` is the actor (cmd/nova-config/login.go:320). `help machine` lists two usage lines and four examples, not the six verbs. Every verb's `-h` repeats the migrate and machine self exit codes.

USE. The banner's example ran as printed: migrate made the file (`from=0 to=34 applied=34`), and a second migrate was `applied=0`. On one file I added machines, the fleet row, two friends, the sprint row, a loop, two routes and a tier order; list, show, history, width and status agreed with every write, and history shows each change as `before>after` under its actor. The refusals are the best part: a missing set of required flags, two bad values (`--slots "no"`, `--tla "maybe"`), a bad name, a duplicate, a missing row, a ref naming no row, removing a row another kind names, a disabled route with no note, a tier naming a disabled route or another tier's route, `--every` with `--keepalive`, and a `--pg_dsn` holding a password (refused without quoting it) each refuse in one line with the reason and a runnable next command, exit 1 for the store's no and 2 for usage. `--dry-run` prints `CONFIG DRY-RUN ... wrote=nothing slots=4>1` and writes nothing. Success `--json` is one envelope, and the width NOTE travels in its `notes`.

What keeps USE at 7.5. Three carry-overs from 1.1.0: under `--json` a refusal leaves stdout empty and prints the plain REFUSED line on stderr; an unknown flag hides the bad values beside it; a dead Redis prints two to four `redis: ... pool.go:762` library lines before the one REFUSED line, on apply, status, machine list and inventory. The fixture path is the weakest: the first run's own fixture refuses outside a checkout, a wrong fixture shape dumps a Go struct type, a fixture with no `redis_port` and `pg_dsn` names a store write as its remedy, and `--host nope` against a fixture points at `nova-config machine list`, a store the fixture stands in for. Smaller: the rows migrate seeds into a `--file` store carry `created=2023-11-14T22:13:20Z` (pkg/config/store.go:247); `machine show` prints `width=-` where `machine width` and the add NOTE say `width=default`; list `--json` gives numbers as strings (`"slots":"4"`) while `machine width --json` gives `"width":6`; `machine remove m1` held by the fleet points at `machine list`, not at `fleet set --store`.

A 10 would put the refusal envelope on stdout under `--json`, collect unknown flags with bad values in one refusal, silence the Redis pool's logger, make the inventory fixture path work from the released binary alone, make the banner's `--seat` claim and the spec's field table true of the binary, and drop the guessed pronoun from the friend kind.

## Good, keep

The refusal grammar on a store write: one line, every independent problem named (missing flags, two bad values, an argv and a missing mode together), the reason, and a runnable next command carrying the same `--file`. The ref discipline: a ref naming no row and a row another kind names are both refused with the holder named (`friend f1 is the --coordinator of the sprint`, `route flash-a is in the --routes of tier flash`). A disabled route must carry its reason. The `--file` store runs every verb but apply's write and inventory with no database. History records every write with actor and before and after. Passwords never on the line: `--pg_dsn` with one is refused without echoing it.
