# nova-memory READ and USE rating, nova-tools 1.2.0

Rater: GLM 5.3 flashx (z-ai/glm-5.3-flashx) in opencode, a sprint worker on a friend's re-rate card
Build: adc585d68173
READ: 8/10
USE: 8/10

No v1.2.0 tag exists on the forge yet, so this rates the head of the release-candidate branch. `nova-memory version` prints `nova-memory v1.0.1-0.20261007015850-adc585d68173 linux/amd64 go1.26.6`. Used for real on a throwaway directory made for the card: a corpus of my own writing (four frontmatter notes, a wikilink index, a dated log, a handbook root file, a two-paragraph draft, a gold set, two pin files, a second root), never a live store, no server, nothing written — every verb is an inspection and the tree was untouched at the end. Help and every verb's `-h` were read before any run, then the banner's setup and example, then the trials below.

## Reasons

READ. `nova-memory help` answers the three questions in order: one purpose line (the README's sentence word for word), a four-line how-it-works that names the nouns (the `--root` directories, the in-memory bm25 and trigram index, the receipts) and says nothing is written, and a first-run line that ends in a setup block and four `example:` lines that run as printed. Before the usage, the banner teaches the one statistic the tool prints: the CAL line, what the probe is, and which `score=` compares with it — a tool that hands you the reading rule beside the reading. Every verb's `-h` carries its usage with an example line, an `effect:` line (inspection: reads, writes nothing), every flag with what it wants, and the exit codes; the help says each code "ran here", and it did. docs/CLI.md is the best first-run writing in the set: a real transcript, what each flag wants, the read caps with their byte numbers and the memory story behind them, and a why-it-exists paragraph that ends by telling you to build a gold set and measure instead of believing.

What keeps READ at 8. The tool's own examples break its own noise rule, on the exact screens a cold reader studies: the banner pastes `SEARCH CAL score=1.46` beside `SEARCH HIT rank=1 score=0.99 score-channel=bm25`, and the First-run transcript prints `CAL score=4.05` over a rank-1 hit at `score=3.48` — by the rule as written, both correct answers are noise (finding 1). Every verb's `-h` repeats the whole-tool exit table, ten lines of other verbs' codes over a two-flag verb (finding 11). And `check`'s lines lead with MEMORY while every other verb leads with its own name, an exception the CLI.md Reading-it paragraph still does not name (finding 10).

USE. The first run worked exactly as printed, and then the whole surface did: stats, one- and two-channel search (fused ranks with per-channel scores and a CAL line every run), check from a file and from stdin over a multi-paragraph draft (candidates=2, receipts per candidate), verify under `--links gate` and `--links info` with `--coverage`, `--frontmatter` and `--exempt` (exit 1 on findings, 0 on the pass, per-kind caps held: 26 unresolved wikilinks beside 4 coverage findings at `--fail-max 2` printed 2 lines and a `MORE` per kind and one count line carrying the totals), eval over my gold set (recall@3=0.667, MRR, `EVAL MISS` lines, exit 1 under the floor), and boot over a pin (missing file, empty pin, non-canonical path, duplicate entry: every one refused with the reason). Refusals are the best of the set: a run short `--channels`, `--k` and `--floor` named all three in one run; an unknown flag lists the verb's flags and ends `run: nova-memory search -h`; an unknown verb lists all eight verbs; `--floor 0` and a zero-row gold file are refused as harnesses that cannot fail; a verify with no gating check is refused as a run that cannot fail. A 9,000,000-byte filler file was refused with the file, its size, the cap and the `--exclude` remedy. `--json` carried the same facts on every verb, refusals included.

What keeps USE at 8. The CAL rule misleads in practice: a reader applying it to my own runs throws away true hits on thin corpora and keeps noise on thick ones, with no verdict on the line to check against (finding 1). A repeated `--root` on boot silently keeps only the last root, so the verb boots a corpus the caller did not name first, or refuses a pin entry that the first root holds (finding 3). The gold harness still scores a header row as a query (finding 2), `--exclude notes/` still excludes nothing and says nothing (finding 6), the boot's OK line still names no path (finding 7), and the hit snippet still cuts mid-word at ~121 characters in lines and `--json` alike (finding 9).

## Good, keep
The refusal grammar: a run short three required flags names all three in one run, each with what the flag wants; an unknown flag lists the verb's flags; every refusal ends `run:` with a command that pastes. The CAL line re-scored on the caller's corpus every run, so the noise band is never a stale number, and the banner teaches it before the first query. verify refusing a run that cannot fail, capping each kind separately with a `MORE` line and a count line that carries the totals on failure too, and refusing `--exempt` without `--frontmatter`. The read caps named with the file, the number and the remedy (`--exclude`). A zero-row gold file refused as a broken harness, not a pass. boot refusing every pin pathology — missing, empty, non-canonical, duplicate, absolute, escaping — with the entry named. Every receipt carrying class, frontmatter name and type, root and file:line, so a dated log never masquerades as a banked note. quickstart printing each command line above the output it produced and naming every choice (channels, k, words-source, candidate) it made.
