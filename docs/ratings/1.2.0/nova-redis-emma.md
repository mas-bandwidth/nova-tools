# nova-redis READ and USE rating, nova-tools 1.2.0

Rater: deepseek-v4 in dsh (the DeepSeek Harness headless runner), a sprint worker on a friend's re-rate card; the rating is the worker's, not the friend's
Build: 9c9b2ebc49fd
READ: 7/10
USE: 7/10

This rates nova-redis at `9c9b2ebc49fd`, the head of `sprint/mechanical-2026-10-02`. `nova-redis version` prints `nova-redis v1.0.1-0.20261007202756-9c9b2ebc49fd linux/amd64 go1.26.6`. Read cold: the banner, `help` and every verb's `-h` (the `install` and `uninstall` groups included), the nova-redis sections of docs/SPEC-REDIS.md and docs/CLI.md, cmd/nova-redis/README.md, docs/TESTS.md and the source. Used for real on a Linux bench in a throwaway store the tool's own recipe starts on a Unix socket (nothing live was touched): spill with and without `--json`, recall of a value, of a miss and of an aged-out key, fn load and fn check (LOADED, UNCHANGED, OK, STALE, REPLACED), acl check, acl apply (dry-run and real, `saved=no-acl-file`), acl render, the install and uninstall dry-run plans, serve --dry-run, every first-run refusal, a dead loopback port and a missing socket.

## Reasons

READ. The banner's first line is the README row's sentence, and the six lines after it answer how the tool works and where its state lives: one `redis-server` launched from `serve`, scratch under `<owner>:<name>` with a required TTL, the embedded function library, and the password taken from a variable. Every verb has a real page behind `-h`: usage, the `from` line it came from, flags with what each wants, the exit table and an `effect:` line; `install`, `uninstall`, `acl render`, `acl check` and `acl apply` have one too. The refusals are the best part: `spill` with a bad owner, a name holding whitespace, a missing value and a TTL of `10x` names each problem in one run, and `serve --dry-run` with no flags names all three it wants. The spec is short, normative and mapped to named tests. The `--json` envelope on spill and recall is one `result` and `facts` object, and a JSON refusal puts every reason in one `why` array.

What keeps READ at 7. The banner's own `example:` block, and the `Example` text every verb's help repeats, still use `--addr`, the spelling `--redis` replaced and `main.go:318` calls "the old spelling ... kept for one release", and they dial `127.0.0.1:6379` while the throwaway recipe printed directly above makes a Unix socket: a reader who starts the recipe's store and pastes the example gets `connection refused`, and a machine with a real service at 6379 receives the example's live `spill`. The normative spec (docs/SPEC-REDIS.md:19-25), the command reference (docs/CLI.md:2619), the tool README and the first-run transcript all still teach `--addr`, so the page a reader is told to trust points at the flag the tool now calls old. The spec's verb list (docs/SPEC-REDIS.md:15-28) omits the four `install` and `uninstall` verbs the tool ships, and the tool README's verb list omits them too. The nova-redis section of docs/CLI.md (2599-2666) has no `### First run`, the one onboarding point the neighbouring tools meet. The effect line on `spill`, `fn load` and `acl apply` says `local write: writes files on this machine`, though each writes the store at `--redis`, which may be another machine. Every verb's `-h` quotes the whole tool's exit essay, including outcomes it cannot have, and the acl outcomes are in none of them. The banner promises `--max` for a verb that lists, and no verb here lists. Comments and one CLI line still tell past issue numbers.

USE. Three jobs went end to end with no wrong guess from this tool's help. A scratch write and read: `spill --redis <sock> --owner ada --name note --ttl 10m --value hello` printed `SPILL OK key=... ttl=10m0s expires=... bytes=5`, `recall` returned the value, `--json` carried the same facts, and a key whose TTL had passed read as a miss at exit 1. A function deploy: `fn load` printed `LOADED nova_sprint sha=5ad34e439bc4996e`, a second load `UNCHANGED`, `fn check` `OK`, a foreign library `STALE` then `REPLACED`. An ACL plan and apply: `acl render` opened no store, `acl apply --dry-run` printed four `ACL WOULD-SET` lines and exited 0 against a dead port, and on the throwaway store `acl apply` set four users and printed `ACL APPLY OK ... saved=no-acl-file` with a NOTE that they last until a restart, after which `acl check` printed `ACL CHECK OK`. `serve --dry-run` refused a wildcard bind, a relative `--dir`, an out-of-range port and a `--users` file missing a user, each before anything started; the `install` and `uninstall` dry-run plans printed the whole unit; `recall --redis unix:<sock>` worked; and every dead-store path exited 2 with the next step.

What keeps USE at 7. Two dry-run paths lie about what happened. `spill --dry-run` with a login refusal — a named user whose password variable is empty, a bad `--password-env`, a user with whitespace — answers `SPILL FAILED: --dry-run was given and the verb never read it (Call.DryRun); it may have written` at exit 1 instead of the real `SPILL REFUSED` at exit 2; `install store --dry-run` with a missing login field or a bad `--bind`/`--port`/`--dir` does the same. `--password-env NAME` with an empty variable and no `--user` is dropped silently and the spill dials as the default user with no password, so a store that wants one answers a refused login rather than the empty variable. `acl check` and `acl apply` against a store that never answered end with a login remedy instead of "start the store or correct the address". `recall` has no `--dry-run`, so the read verb cannot be planned store-free. The fn, acl and serve answers are prose only, with no `--json` for a caller to parse. The fn lines lead with the state and never name the verb. And the banner's example dials 6379, which on a real machine may be the live store the card warns against.

## Good, keep

- One run names every independent problem, each with `; run:`, and the door is the verb's own help; the sweep is pinned by tests in cmd/nova-redis (spill_test.go, fn_test.go, acl_test.go, serve_test.go, firstrun_test.go).
- `spill --dry-run` and `acl apply --dry-run` make every check and dial nothing; a real spill and recall round-trip the value in the line and in `--json`, and a lost reply is `SPILL UNCONFIRMED` at exit 1 with a recall as its remedy, never a second write.
- `fn load` and `fn check` report LOADED, UNCHANGED, REPLACED, OK, STALE and MISSING with the library digest and a pastable next command.
- `acl apply` names every user it would create and every `--password-env-for` the paste needs, and `serve --dry-run` refuses a wildcard bind, a relative `--dir` and a `--users` file missing a user before anything starts.
- The unsigned-socket address form works for every verb that dials, and the store is opened through one path (internal/redisconn) with the password only ever named, never passed.
