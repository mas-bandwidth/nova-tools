# nova-bus READ and USE rating, nova-tools 1.2.0

Rater: GLM 5.3 Flash X (z-ai/glm-5.3-flashx) in opencode, a sprint worker on a friend's re-rate card
Build: c76fcb249cc1
READ: 8/10
USE: 7/10

No v1.2.0 tag exists on the forge yet (the newest is v1.0.0), so this rates the release candidate at the sprint base c76fcb249cc1; `nova-bus version` prints `nova-bus v1.0.1-0.20261007015429-c76fcb249cc1 linux/amd64 go1.26.6`. Read cold from the banner, `help <verb>`, every verb's `-h`, docs/SPEC-BUS.md, the nova-bus section of docs/CLI.md and cmd/nova-bus, then used in a throwaway directory. No store was started (the card forbids a server on the machine), so the store verbs ran against a dead loopback port, a missing Unix socket path, a public address and a name that does not resolve, and everything that needs no store ran for real: help, version in lines and JSON, and about forty refusals across every verb. The live half — send, recv, the deaf-name gate, receipts and wait against a store that answers — could not run and is rated only from its help, spec and code.

## Reasons

READ. The banner answers the three questions in order: one line of what (the same sentence as the README row, README.md:24), five lines of how (the loop a harness runs, the deaf-name rule, the streams and the log, where a first run's store comes from), and an `example:` block of the seven first-run lines docs/TESTS.md executes. The tool is now a member of the family: dispatch, banner, help, refusals and the output envelope are internal/tool's (cmd/nova-bus/main.go:8), every verb takes `--json`, the listing verbs take `--max` with `MORE`, and every verb's `-h` carries usage, its banner excerpt, every flag with its default and what it wants, exit codes and an `effect:` line that is true of the binary (peek, log and names say `inspection: reads, writes nothing`; send says the delivery and the transaction). SPEC-BUS.md is the spec a cold reader wants: the keys, the at-least-once promise said plainly, the token-retry rule and its TLA machine, the push-proof gate, the receipts, the ACL table and a round-trip budget per verb, and where it and the code meet they agree. The 1.1.0 READ findings are largely answered: main.go is 1,117 lines on the shared skeleton instead of 3,823 hand-rolled ones, `REFUSED` no longer rides exit 1, the retired `--beat` flags are gone with the git bus they served, and SPEC-BUS.md is now the one normative spec of a tool that exists.

What keeps READ at 8. The exit table is told wrong on most pages: every `-h` quotes the tool-wide table whose exit 1 names recv and wait outcomes (`recv: nothing waiting; recv --exec: the command failed; wait: nothing came`), and that parenthetical is printed unchanged on send, ack, peek, receipts, log, names and version, seven verbs that can never exit 1; wait and overdue each carry a table of their own, so three shapes live in one tool (cmd/nova-bus/main.go:179, :187, :378). `version -h` alone has no `example:` line. The CLI.md command table omits the two newest verbs and the flags the newest work added (docs/CLI.md:521-532: no receipts, no overdue row; the send row has no `--kind`, `--token`, `--token-life`, `--token-cleanup` or `--dry-run`; the recv row no `--kind` or `--dry-run`), and SPEC-BUS.md's "The verbs" list (docs/SPEC-BUS.md:76-144) omits receipts and overdue too, though both have pages and a section of their own below. The store address is told three ways: the banner's first run says "(else NOVA_BUS_REDIS)" and stops, eight verbs' `--redis` help adds "else the fleet row's bus from the sprint store", and wait's (main.go:212) drops "from the sprint store". And `--kind`'s help never says its default is status, which only the spec states.

USE. Everything that could run without a store ran, and the refusal grammar is the best part of the tool, all of it witnessed: a bare `nova-bus` and an unknown verb name all ten verbs and point at `nova-bus help`; an unknown flag names the flags there are and points at that verb's page (`run: nova-bus peek -h`); a missing required flag is named with what it wants and `refusing to guess`, both missing flags in one run; every bad value says the shape it wants (`--after` wants `<ms>-<seq> as WAIT ARMED and WAIT OK print it`; `--timeout -1s` wants `at least 0, 0 for ever`; `--max 0` wants `a count of at least 1 (--all takes every message)`); `--forever` without `--exec` and `--ack` with `--exec` are refused with the reason each. The address policy holds before any dial: a public address is refused naming the rule and the address it resolved to, an unresolvable name says so, a relative socket path is refused with the two forms it accepts, and the fallback chain is one refusal naming all three sources when none is set. A dead store answers one line with the address, the login, the cause and the next step (`start the store or correct the address, which was given to this tool`), `--json` renders the same refusal as one object, and an empty password variable is refused before the dial with the variable to export. Exit codes held everywhere: 0 on help and version, 2 on every refusal.

What keeps USE at 7. The declared dry runs are the worst answer the tool gives. On any refusal that happens before the verb body reads the flag — a store that did not answer, a refused address — send, recv and ack print `SEND FAILED: --dry-run was given and the verb never read it (Call.DryRun); it may have written` at exit 1 (witnessed against a dead port and a public address; the open and the flag read are main.go:510/:525, :589/:602, :709/:720): a dry run that wrote nothing is told it may have written, at the exit code that means the verb ran and said no, and the real reason (the store, the address) is never said. Nothing beyond version and help runs without a store, dry runs included, so a cold reader cannot try one core line — no SEND draft, no RECV plan — before adopting the tool, where nova-table prints its FCALL with `dialled=0` and nova-redis plans a spill with `written=0` store-free. And the message checks sit behind the dial: `--kind bogus`, `--to "BAD NAME"`, an empty `--stdin` body and a missing `--as` are all answered with the store's error when the store does not answer, so one run does not name every problem it can find. The deaf-name gate, the identity refusals and every success line remain unrun here; they are rated from help, spec and code only, and the score carries that.

## Good, keep

The refusal grammar, all of it witnessed: every problem of a run named at once, each with what the input wants and `refusing to guess`; an unknown verb answered with all ten names; an unknown flag answered with the flags there are and the verb's own page. The address policy enforced before any dial, one line naming the rule, the address and what it resolved to, with the unresolvable case said and the two socket forms given. The dead-store line that names the address, the login, the cause and the next step, and the empty-password refusal that names the variable to export before anything dials. `--json` on every verb rendering the same refusal as one object. The token-retry contract documented in send's help where the caller meets it, with the fingerprint, the life and the cleanup said in plain words. The banner and README saying the same one sentence, and a first run the tests execute.
