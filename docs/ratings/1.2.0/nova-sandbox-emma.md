# nova-sandbox READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 3a5792afa395
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-sandbox version` prints `nova-sandbox v1.0.1-0.20261006144833-3a5792afa395 linux/amd64 go1.26.6 backend=landlock platform=linux`. Built and run on a Linux bench machine (landlock ABI 8, clamped to 6), in a scratch directory made for the trial with a scratch HOME; no live store and no server. `help`, every verb's `-h`, and docs/SPEC-SANDBOX.md (the opening, exit codes, output grammar, the two lists and the process caps) were read first. Then `check`, `probe` (bare, `--secret`, `--net-deny`, `--json`), `policy` (with and without a command, `--json`), `version`, `worktree --prune`, `run`, `reap`, every `egress` verb, and about 60 bare-form runs: the wall against reads, writes, execs, the network, symlinks, a path with a blank, nested and duplicated roots, background children, and every refusal I could provoke.

## Reasons

READ. The banner opens with how the wall works in five lines and a first run that works as printed: `check`, make a scratch HOME, `probe`, then a write inside. The flag paragraphs say what each grant does and why it exists (`--read` CARRIES EXECUTE; `--read-noexec` is for a cache this user can write; `--write` is required because no writable directory is a misconfiguration), and the exit table tells the wrapped command's status from the tool's by the `SANDBOX DONE` line, which is the right answer to the env(1) ambiguity. The spec states its own ambiguities instead of hiding them.

What keeps READ at 7. The help makes promises the Linux wall does not keep, and a reader has no way to know: `--read` is "NOT writable" (cmd/nova-sandbox/main.go:78), but a `--read` nested inside a `--write` stays writable; `--net-allow` "opens the loopback host:port named" (main.go:103), but on Linux it is accepted and dropped; "every path is yours and none is guessed" (main.go:167), but the command's own directory is a computed root with execute. The banner is 159 lines and still omits flags the verbs take (`--gpu` and `--json` are in no usage line; probe takes `--max` and `--net-listen` that its `-h` and usage do not list). The per-verb help says `usage: nova-sandbox <verb> [flags]` above an excerpt of the banner, opens its exit line with "each verb's own, by verb:" before one verb's codes, and the example in `egress -h` and `egress plan -h` omits the required `--resolver`, so it is refused if pasted. The required GitHub names in an egress policy are in no help. `help frobnicate` prints the whole banner at exit 0, where `nova-sandbox frobnicate` is refused at 2. The spec is 2337 lines with no short path for the bare form.

USE. The wall held everywhere the help draws it. A read outside every grant (a file beside the job, `~/.ssh`, `/etc/shadow`, `/proc/1/environ`, another process's cwd) was denied; a write outside `--write` was denied; a disjoint `--read` was readable and not writable; under `--read-noexec` neither a script nor a copied binary would run; `--net-deny` stopped an HTTPS connect while a run without it reached the network; a symlink inside the write set into an unnamed directory did not widen it; a `--write` given as a symlink was resolved and printed resolved; a path with a blank was escaped on `cwd=` and `deletes=` and decoded by `cwdb64=`. Status passes through (`exit 7` is 7, a SIGTERM is 143, a command's own `exit 125` is 125 with `SANDBOX DONE exit=125` telling it from a refusal). About 30 refusals were provoked and nearly all are excellent: a relative path is answered with its absolute form, a HOME outside the wall with the exact `mkdir` and `HOME=` line to run, `--read` and `--write` on one path with which flag adds nothing, and several problems are named in one turn. `probe` is the right shape: a control step proves the probe can see a write before it trusts a denial.

What keeps USE at 7. Three grants are wider than the caller asked and the tool says nothing: `--read-noexec D -- D/prog` runs `D/prog`, a `--read` inside a `--write` is writable, and `--net-allow` with `--net-deny` on Linux leaves the named loopback port closed (measured: the port answered outside the wall and was refused inside it) while `policy` prints no trace of the flag. A background child outlives `SANDBOX DONE exit=0`: a `sleep 20 &` was still running after the tool exited (still inside the wall, but the caller was told the run ended). The refusal reasons drift from the grammar: `--json` on the bare form is `reason=no_command`, a missing `--secret` file is `PROBE REFUSED reason=check ... (bad_read)`, `version extra` is `reason=unknown_flag` (not in the spec's set) and points at `nova-sandbox version`, a missing `--` prints two `SANDBOX REFUSED` lines, and every `egress` refusal (drop, check, apply) offers the plan command as its remedy. On Linux `reap --dry-run` exits 125, a code reap does not document. `/dev` is a read root, so a wrapped command lists other jobs' file names in `/dev/shm`.

A 10 would refuse, or narrow, every grant it cannot keep as the help words it (a `--read` under a `--write`, a `--read-noexec` holding the command, a `--net-allow` the backend cannot open), count the command-directory root on `SANDBOX OK`, say that children may outlive the run or kill the group on exit, put every accepted flag in a usage line, make the pasted examples run, and give every refusal a reason the grammar lists.

## Good, keep

- The refusals: each names the reason, the flag, and the corrected command (the absolute form of a relative path, the exact `mkdir` and `HOME=` line for a HOME outside the wall), and several problems are named in one turn.
- `SANDBOX OK` before the command and `SANDBOX DONE exit=<n>` after it: a log that ends in a crash still says what the wall was, and a command's own 125 is told from a refusal.
- `probe` with its `write_outside_control` step: a denial is trusted only after the same write is shown to succeed without the wall.
- `cwdb64=` beside `cwd=`, and `deletes=` with escaped separators: the machine-readable receipt is exact where the readable one cannot be.
- `--read-noexec` itself, and a path in two lists being a refusal rather than a merge.
