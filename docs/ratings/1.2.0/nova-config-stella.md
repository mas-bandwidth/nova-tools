# nova-config READ and USE rating, nova-tools 1.2.0

Rater: GLM (glm-5.3-flash) in opencode, a sprint worker given a friend's re-rate card
Build: 65416146b5bb
READ: 7.5/10
USE: 7.5/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-config version` prints `nova-config v1.0.1-0.20261007020011-65416146b5bb linux/amd64 go1.26.6`. Built and run on a Linux machine, in a scratch directory made for the trial, on a `--file` store and a scratch `XDG_CONFIG_HOME`; no PostgreSQL, no Redis, no server started. apply and inventory were tried against a dead loopback address only.

## Reasons

READ. `nova-config help`, every verb's `-h`, `help machine`, `help machine width`, `help login`, the nova-config section of docs/CLI.md, docs/SPEC-CONFIG.md and docs/nova-config/README.md were read cold. The banner answers the three questions: one line of what, five of how (the two stores, the kinds, the file), and a first run of five commands that ran as printed with no database. Every kind verb's `-h` carries its usage, an `effect:` line, its required flags marked in a `required:` line and again on each flag, an example that runs on the same file, and typed flags (`text:`, `number:`, `list:`, `json:`, `true|false:`, `decimal:`). The unknown-verb refusal names every verb there is. SPEC-CONFIG.md is in sections and its Lines block is the grammar the binary prints; docs/CLI.md's nova-config section is a usage table, a First run, and paragraphs per topic.

What keeps READ at 7.5. The `--seat` flag means the opposite on two verbs of the same kind: on `machine add` and `loop add` it is the row's own field (a required one on machine), and on `machine set`, `loop set` and every other verb it is the store connection from seats.tsv; the banner presents `--seat <name>` as the store for every verb without the exception, and `machine set` can never change the row's seat field at all (cmd/nova-config/kindverbs.go:113). Only the spec's Connecting section untangles it. The friend kind's help calls every friend "she" and "her" (internal/config/kind.go:432). sprint set's `-h` carries calibration history in flag helps of 400 to 700 characters (AUCs, "24 of the calibration's 39 flaky failures", internal/config/kind.go:468). Every verb's `-h` repeats the migrate `--dry-run` and `machine self` exit codes. `login -h` has no `example:` line and prints its effect after the exit codes. The spec has drifted in six places: the loop field table and the schema block still list a `width` migration 0017 removed (docs/SPEC-CONFIG.md:52, :446; the binary refuses `--width`), the fleet summary row omits `bus` and `loops_dir` (:49), the apply order omits tier (:488), `answer_rules_off` lists six rules where the binary takes ten (:246), and the tiers schema block says `name PK flash|pro` where heavy arrived in 0028 (:462). `kinds` prints tier `rows=many` while the tier section says three rows made by migrate and `tier add` always refuses with "tier pro exists". `machine self` prints the bare hostname, the one output with no typed prefix and no line in the Lines grammar. README.md:30 still ends "This is the Nova fleet configuration model.", and docs/CLI.md:2467 is a 2,849-character paragraph.

USE. Everything below ran for real on the throwaway file. The banner's example ran as printed: `migrate` made the file (`from=0 to=35 applied=35`), a second migrate was `applied=0`, and the add, set, list and history lines agreed; history shows every change as `before>after` under its actor and time. On one file: two machines (one with the add NOTE naming `machine set m2 --width <n>`), the fleet row, a friend, the sprint row, a loop, a route, a tier set with a route named twice; `kinds`, `status` (lines and `--json`), `machine width` for a set width, an unset one (`width=default member=true`), `--width 0` (`member=false`), `--width default`, `machine self`, dry-run writes in lines and `--json` (before and after field maps), and `migrate --dry-run` printing all 35 migrations `state=applied`. About fifteen refusals were provoked: a missing set of required flags, `--slots no` beside an unknown flag, a duplicate, a missing row, a bad name, a ref naming no row, a removal of a row another kind names, `--every` with `--keepalive`, `--keys` without `--seat`, a disabled route with no note, a tier set naming a disabled or foreign route, `--tiers "flash,gold"`, `--width -1`, a `config_dir` that is not absolute, a `--pg_dsn` holding a password (refused without quoting it), `--answer_rules_off frobnicate` (the refusal lists all ten rules), and an unknown verb; every one named the fault and a runnable next command, exit 1 for the store's no and 2 for usage.

What keeps USE at 7.5. The carried defects of 1.1.0 are all still met in use. Under `--json` a refusal leaves stdout empty and prints the plain REFUSED line on stderr, so a caller parsing the envelope cannot read the refusal. An unknown flag hides the bad values beside it. A dead Redis prints four `redis: ... pool.go:762` library lines before the one REFUSED line, on apply and on inventory. The inventory first run names a fixture by a checkout-relative path and refuses as printed from anywhere else; a fixture of the wrong shape dumps a Go struct type; a fixture missing `redis_port` and `pg_dsn` is answered with a store write the fixture does not read; and `--host nope` on a fixture points at `nova-config machine list`, the store the fixture stands in for. The rows migrate seeds carry `created=2023-11-14T22:13:20Z`, the in-memory store's fixed test clock. `list --json` gives numbers and booleans as strings (`"slots":"8"`, `"width":"6"`) while `machine width --json` gives `"width":6` — the same field a string in one verb and a number in another. `machine remove m1` held by the fleet points at `machine list`, and `friend remove f1` held by the sprint at `friend list`; neither frees the row. And the `--seat` flip lands in use: `machine set m2 --seat s2 --file try.json` exits 2 with a refusal that lists `seat` among "the fields" while the flag was read as the store connection.

A 10 needs one meaning for `--seat` on every verb of a kind, the refusal envelope on stdout under `--json`, one refusal collecting unknown flags and bad values, a quiet Redis logger, an inventory fixture the released binary can reach with a remedy that stays on the fixture, typed JSON fields, removal remedies naming the write that frees the row, seed rows stamped by the wall clock, and a spec whose field tables say what the binary takes.

## Good, keep

The refusal grammar on a store write: one line, every independent problem named, the reason, and a runnable next command carrying the same `--file` (`--every 60 --keepalive true` is answered with `--every 0 or --keepalive false`; `--keys API_KEY` without a seat with `want --seat <seat>`). A disabled route must carry its reason, refused before the store is opened. The ref discipline: a ref naming no row and a row another kind names are both refused with the holder named. The `--file` store runs every verb but apply's write with no database, and the banner's example runs as printed (migrate, add, set, list, history on one file). History records every write with actor, time and `before>after`; `--dry-run` prints the change from the same checks, lines or JSON, and writes nothing. Passwords never on the line: `--pg_dsn` and `login --dsn` with one are refused without echoing it. `machine width` speaks the width vocabulary (a number, `default`, `0` not a member, `-1` refused).
