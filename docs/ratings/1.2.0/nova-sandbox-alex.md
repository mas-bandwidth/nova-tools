# nova-sandbox READ and USE rating, nova-tools 1.2.0

Rater: deepseek/deepseek-v4.1-flash under dsh, a cold reader on a friend's re-rate card
Build: 3df84cf8d819
READ: 7/10
USE: 6/10

Is this a good tool for an AI to use? No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of `sprint/mechanical-2026-10-02`, build `3df84cf8d819`. `nova-sandbox version` prints `nova-sandbox v1.0.1-0.20261007212519-3df84cf8d819 linux/amd64 go1.26.6 backend=landlock platform=linux`. Built and run on a Linux bench (landlock ABI 8, clamped to the tool's table at 6), in throwaway directories under the job directory with a scratch HOME inside each `--write`; no live store was dialled and no server was started. `nova-sandbox help`, every verb's `-h` (and every egress subverb's), and docs/SPEC-SANDBOX.md were read cold, then `check` (plain and `--json`), `probe` (bare, with `--secret`, `--net-deny`, `--read-noexec`, `--json`, `--max`), `policy` (plain, `--json`, with and without a command, with `--secret`/`--max`/`--acl`/`--net-allow`/`--gpu`), about forty bare-form runs (reads, writes, execs, a path carrying execute under `--read`, a path under `--read-noexec`, a path in both lists, `--cwd`, `--tmp`, `--net-deny`, `--net-allow`, `--name`, `--acl`, `--gpu`, exit codes 0/3/126/127/143, a missing command, a missing `--`), `worktree --prune`, `run`, `reap`, and the whole `egress` family (`plan` with a resolvable host, `check`, `apply`, `drop`). Every external effect stayed inside the job directory; the one nft table the trial applied was dropped in the same trial.

## Reasons

READ. The banner is the best part of the tool. Its first line is the README's sentence for nova-sandbox word for word (README.md:42, cmd/nova-sandbox/main.go:45), the `how it works:` paragraph answers in five lines what is readable, what is writable and what 125 means, and the `example:` block is a four-step first run (`check`, `mkdir`, `probe`, a write inside) that runs as printed with `HOME` inside the `--write`. The flag paragraphs give the reason, not just the type: `--read` "CARRIES EXECUTE", `--read-noexec` is "the flag for a cache or a data tree", `--write` is required because "a command with no writable directory is a misconfiguration". The exit paragraph separates the wrapped command's own status from the tool's and names the `SANDBOX DONE exit=<n>` line that tells them apart. `check`, `policy` and `probe` take `--json`; the refusal texts are one line, name the flag as typed, and for `HOME` end with the exact `mkdir -p … && HOME=… nova-sandbox …` line to paste.

What holds READ at 7. The short texts and the binary disagree in several places a cold reader meets early. The `-h` examples cannot run: `probe -h` prints `nova-sandbox probe --write /pool/jobs/j1 --net-deny --json` (cmd/nova-sandbox/verbhelp.go:79), which omits the `HOME` the probe requires and names a pool that does not exist; `policy -h` prints `--write /pool/jobs/j1 --read /usr/local/go` (verbhelp.go:78), also without `HOME`; `egress -h` prints `--policy infra/image/egress.txt --model-host api.example.com` (verbhelp.go:81), and that host is not in the policy file and no `--resolver` is given, so the plan refuses. `-h` also omits flags the verb accepts: `probe -h` has no `--max` (verbhelp.go:44-45) although probe parses it and the spec lists it (docs/SPEC-SANDBOX.md:467), and `policy -h` has no `--secret`, `--max` or `--acl` (verbhelp.go:48-55) although policy takes all three and prints a `POLICY NOTE` for each (cmd/nova-sandbox/main.go:1149-1153) — against docs/CLI.md:1735, "`<verb> -h` lists each verb's flags". The bare form's unknown-flag answer lists flags that belong to other verbs (main.go:404-405): `--bogus` is answered "the flags are --read, …, --secret, …, --json, …, --max", then the same tool refuses `--secret`, `--max` and `--json` on the bare form as "not a flag of the bare form" (main.go:490-491). The banner's usage block (main.go:56-74) omits `--gpu`, which the bare form, probe and policy all take, and it leaves run's `--out`, `--artifact`, `--max-procs`, `--max-mem` and `--out-max-bytes` to `run -h`; and `main.go:4-6` still says this binary "is the darwin half of it; on every other platform the wrap REFUSES", which the linux run itself disproves.

USE. The wall works, and that is the whole job. On the bench the tool built and every walled run I made was contained: a write outside `--write` was denied, a read outside every grant was denied, `--read` was readable and not writable and carried execute, `--cwd` and `--tmp` outside the wall were refused, `--net-deny` turned a `/dev/tcp/1.1.1.1/443` connect into `Permission denied` (BLOCKED) while the same run without it connected, the command's own status came back (0, 3, 126, 127, 143 for `kill -TERM`), and `SANDBOX OK` / `SANDBOX DONE exit=<n>` lettered each. `probe` is a real self-test: five steps, the `write_outside_control` step first so a denial that was never possible cannot pass, and the `--secret` file's contents are never read. `policy` prints the exact landlock ruleset (roots by name, `writefile=/dev/null`, `writefile=/dev/tty`) and runs nothing. `egress plan` resolved github.com once, pinned seven addresses and wrote a `default deny` nftables table; `egress check` read it back (`allow=7 deny=6`); `egress apply` loaded it; `egress drop` removed it.

What holds USE at 6. `--read-noexec` — the flag whose entire promise is "under this flag it can only read it" (cmd/nova-sandbox/main.go:88-91) — is silently widened when the wrapped command lives in that directory: `nova-sandbox --read-noexec D --write W -- D/true` ran the binary at exit 0 with `read-noexec=1` on the OK line, and `-- D/script.sh` ran the script. Executed from a shell instead, the same file is denied (`exec: … Permission denied`, exit 126), so the rule is applied; what defeats it is the tool's own computed root, "the directory of the resolved command", which `OptionalRoots` adds with execute (pkg/sandbox/policy.go:233, :833) and the overlap check never sees (policy.go:717-731 compares only the caller's lists). `probe --max` is accepted and does nothing: `--max 1` and `--max 0` still print all five steps with no `MORE` line (`--max` is parsed at main.go:381-387 and read nowhere). Two Linux flags are silent no-ops: `--gpu metal` prints `gpu=metal` on an OK line that grants nothing and prints no `SANDBOX NOTE`, where `--acl` gets one; and `--net-deny --net-allow 127.0.0.1:11434` prints `net=denied` with no note, though the banner says `--net-allow` opens the named loopback host:port. `egress` points every refusal at the wrong remedy: `egress check --plan missing` and `egress drop --run 'bad id'` both end `run: nova-sandbox egress plan …`, and an nft failure prints its stderr raw, so the line carries literal `\x0a` where the newlines were. `reap` and `run` on linux exit 125, a code `reap -h` never names (its line says only "0 clean, 3 something remained"). `docs/CLI.md:1718` still says `--secret` is required on a probe, which the banner, the spec and a four-step probe at exit 0 all contradict.

A 10 needs: the command directory folded into the `--read-noexec` overlap check or granted without execute; `probe --max` either bounding the step list or dropped from the spec; every `-h` example a command that runs as printed; every accepted flag in its own `-h` and usage line; the bare form's unknown-flag list holding only the bare form's flags; `--gpu metal` and `--net-allow` refused or noted on linux; the egress remedy naming the subverb that failed; and a one-line refusal grammar for `run`, `reap`, `worktree` and `egress`.

## Good, keep

The banner's first line is the README's sentence for the tool word for word (README.md:42, cmd/nova-sandbox/main.go:45), and the `example:` block is a first run that works as printed.

Every refusal is one line that names the reason, the flag as typed and the corrected command, and several independent faults are reported in one turn; a `HOME` refusal ends with the exact `mkdir -p … && HOME=… nova-sandbox …` line to paste.

`SANDBOX DONE exit=<n>` tells the wrapped command's own status (0, 3, 126, 127, 143) from the tool's 125, and `SANDBOX OK` says the wall is up before the command starts.

`probe` is a self-test with a control step first, so a wall that denies everything cannot pass; a probe without `--secret` runs its four remaining checks, and every path it touches is named by the tool.

`policy` prints the exact ruleset for the flags (roots, `writefile=/dev/null`, `writefile=/dev/tty`, `gpu=`) and runs nothing; `check --json` and `policy --json` render one value in one shape.

`egress plan` resolves and pins the allowlist once, writes a `default deny` table scoped to the card's uid, and `egress check` reads it back against its invariants (`allow=7 deny=6`).
