# nova-version READ and USE rating, nova-tools 1.2.0

Rater: deepseek-v4.1-flash in dsh, a sprint worker on a friend's re-rate card
Build: 0389f76634ec
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of `sprint/mechanical-2026-10-02`. `nova-version version` prints `nova-version v1.0.1-0.20261007224659-0389f76634ec linux/amd64 go1.26.6`. Built and used for real on a Linux bench (go1.26.6, linux/amd64), in throwaway directories made for the trial: the binary's own `example` manifest, hand-made `nova-*` stubs of copied and renamed executables, hand-written snapshots, and `moved` over two real revision pairs of the clone. No live store, no server, and no bus that could deliver: every `send` was one that could not deliver. No go command ran on the machine that wrote this.

## Reasons

READ. `nova-version help` is a strong first screen: one purpose line, a four-line "how it works" that names every verb and says which half of the tool belongs to nova-update, one usage line per verb, an exit table by verb, and a four-line `example:` block that runs with the binary alone. Every verb's `-h` carries the banner excerpt, its flags and an `effect:` line that says before the run what it touches (inspection, local write, delivery). `report -h` states the manifest's six rules in place, so a cold reader can write a manifest without opening a spec, and `snapshot -h` now prints its real per-binary default ("30s with --bin, 5s with --file"). The spec is numbered, each rule names the mistake it prevents, and a refusal that reads a whole file names every bad line of it at once.

What keeps READ at 7. The help still trips a reader in ways an AI cannot resolve from the tool alone. Every verb's `-h` repeats the whole five-verb exit table, so `example -h` and `version -h` print codes for verbs they do not drive (`internal/update/versiontool.go:30-38`). `moved -h` prints no default for `--timeout` or `--budget` though `snapshot -h` now prints its own (`internal/update/versiontool.go:59-60`). `report`'s usage line leaves out `--send`, which its flag list and its effect line rely on (`internal/update/versiontool.go:117`); `send`'s usage line leaves out `--kind`, `--max`, `--timeout`, `--budget` and `--draft`, which its flag list prints (`internal/update/versiontool.go:131,151-159`). `report` and `send` take no `--json`, which the banner states, so the only machine form of a report is one key=value line with escaped bytes. `help nosuch` and an unknown verb are refused as `VERSION REFUSED`, which reads as the `version` verb (`internal/update/versiontool.go:20`). The two entry points name two different contracts (`cmd/nova-version/main.go:3` says SPEC-VERSION.md, `docs/CLI.md:2157` says SPEC-UPDATE.md), and each covers half the verbs. The source-metadata comments cite SPEC-VERSION item 6 for the mixed/partial source rule that is item 4 of the snapshot-and-diff section (`internal/update/snapverb.go:71,123,241`, `pkg/buildinfo/buildinfo.go:307`). The manifest block calls its six numbered lines "the six lines" while line 6 is an example and line 5 carries two rules, and the `{version}` in the example's apply column is substituted only by nova-update and is explained nowhere here (`internal/update/cli.go:252`, `internal/update/example.go:20`). `docs/CLI.md:2182` still says "the adopted 16", and the README still pins 1.0.0 (`README.md:86-91`).

USE. The first run is the banner's and it works as printed: `example --out versions.tsv`, then `snapshot --file`, then `report --file`, each exit 0 with a next-step note, and `example` never overwrites (`unchanged=true`). Refusals are the best part of the tool: bare `moved` names all four missing flags at once, a manifest with three bad lines names line 3 and both faults of line 4 in one refusal, both unreadable snapshots are named in one `diff` refusal, an unknown flag lists the verb's flags, and every refusal ends `run:`. `diff` reports changed, removed (`to=-`) and added (`from=-`) sets correctly and its `--json` carries the same facts and items. `snapshot --bin` reads each binary's own `version`, notes a skipped symlink by name, notes a partial source by name and refuses a mixed source or a mixed stamp naming both binaries and both values. `moved` built two real revision pairs at this head (43s with the warm bench cache, inside the default 30s/60s bounds; the earlier 1.2.0 timeout did not reproduce).

What keeps USE at 7. `moved`'s summary contradicts its own note. Across a wide pair it printed `added=0 deleted=0 renamed=0 verbs=314` and a `--json` with no items, while the note it wrote holds fifteen change lines (`added=gc tool=nova-sprint`, `added=mirror tool=nova-swarm`, `added=--actor tool=nova-config verb=<kind>`); `diffMoved` counts only a whole tool in `added`/`deleted` (`internal/update/cli.go:1021-1022,1028-1029`) and appends the verb and flag entries without a count (`internal/update/cli.go:1060,1062`), while `verbs=314` is the total at `--to` (`internal/update/cli.go:1017`). An AI reading the summary or the JSON concludes that nothing moved. `snapshot --bin` is all or nothing: one non-executable `nova-data` stops the run at exit 2 as `cannot read nova-data version (not_found)` with `go build ./cmd/nova-data` as the remedy, though the file is present and merely not executable (`internal/update/snapverb.go:224`), and a directory of three bad binaries names only the first per run (`internal/update/snapverb.go:224,228`). `snapshot --bin --dry-run` still demands an `--out` it never writes (`internal/update/versiontool.go:86-99`), and an existing `--out` is replaced without a word (`internal/update/snapverb.go:289`). `send` lists a `--draft` it refuses and has no `--dry-run`, so the one verb that delivers beyond the machine cannot be previewed (`internal/update/versiontool.go:151-159`). `report --snapshot` writes the state file even without `--send`, contradicting its own effect line that report reads and writes nothing without `--send` (`internal/update/versiontool.go:123-124`). `report --draft` prints `Subject: versions on - at ...` when no `--host` is given (`internal/update/report.go:91`). With the bus unconfigured, the bus's own refusal is clipped at 200 bytes mid-remedy (`refusing to g...`) and this tool's retry clause names a `--snapshot` that does not fit a missing store (`internal/update/report.go:146,190`). One bad flag value still ends the list early, and the exit table's `snapshot: ... 1 a tool is UNKNOWN` holds only for `--file` (`internal/update/versiontool.go:35`).

A 10 needs `moved`'s counts and JSON to match its note and to define each count in `-h`; `snapshot --bin` to read every binary and name every bad one together under the exit code the table promises, with `not executable` told apart from `not_found`; a `--dry-run` that needs no invented `--out`; an overwrite that says so; a `send` that can preview and does not offer a flag it refuses; `report`'s effect line and its actual writes to agree; a machine form for report; and the version-of-record lines, defaults and exit tables trimmed to what each verb drives.

## Good, keep

The banner's first run, which works as printed with the binary alone, and the next-step note after every success. The refusal grammar: bare `moved` names all four missing flags in one run, a manifest with three bad lines names each line and each fault, both unreadable snapshots are named in one `diff` refusal, an unknown flag lists the verb's flags, and every refusal ends `run:`. `snapshot --bin` reads each binary's own `version` rather than its file name, notes a skipped symlink and a partial source by name, and refuses a mixed stamp or a mixed source naming both binaries and both values with the commands that rebuild one set. `diff`'s `to=-` and `from=-` and its matching `--json`, `example`'s never-overwrite with `unchanged=true`, the `--max` bound with its `MORE shown=... total=...` line on every listing verb, and `moved`'s refusal of a revision the checkout does not hold, naming `git fetch`.
