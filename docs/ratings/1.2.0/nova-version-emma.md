# nova-version READ and USE rating, nova-tools 1.2.0

Rater: deepseek-v4 in dsh, a sprint worker on a friend's re-rate card
Build: 24e5b7120dda
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of `sprint/mechanical-2026-10-02`. `nova-version version` prints `nova-version v1.0.1-0.20261007204559-24e5b7120dda linux/amd64 go1.26.6`. Built and used for real on a Linux bench, in throwaway directories made for the trial: the binary's own `example` manifest, hand-made `nova-*` stubs of copied and renamed executables, hand-written snapshots, and `moved` over two real revisions of a scratch clone. No live store, no bus that could deliver, no server started, and no go command on the machine that wrote this.

## Reasons

READ. `nova-version help` is a strong first screen: one purpose line, a five-line "how it works" that names every verb and says which half of the tool belongs to nova-update, one usage line per verb, the exit table by verb, and a four-line `example:` block that runs with the binary alone. Every verb's `-h` carries its banner excerpt, its flags and an `effect:` line that says before the run what it touches (inspection, local write, delivery). `report -h` states the manifest's shape in place, so a cold reader can write one without opening a spec. The spec is numbered, each rule names the mistake it prevents, and the source carries its reasons in comments.

What keeps READ at 7. Much of the 1.1.0 READ finding is still here. Every verb's `-h` repeats the whole five-verb exit table, so `example -h` and `version -h` print codes for four verbs they do not drive (`internal/update/versiontool.go:30-38`). The flag lists and the usage lines disagree: `report`'s usage line leaves out `--send` though its flag list and effect line rely on it (`internal/update/versiontool.go:117,123`), and `send -h` lists `--draft`, `--kind`, `--max`, `--timeout` and `--budget` that its usage line never offers (`internal/update/versiontool.go:131,151-159`). No `-h` prints a default: `--timeout` and `--budget` read "one child's deadline" and "whole run deadline" (`internal/update/versiontool.go:59-60`), and the 30s/60s live only in the spec. `moved` defines none of its counts in help, so `verbs=314` is unreadable there. The two entry points still name two different contracts: `cmd/nova-version/main.go:3` says SPEC-VERSION.md and `docs/CLI.md:2157` says SPEC-UPDATE.md, each covering half the verbs. The source gate's comment cites SPEC-VERSION item 6 at three sites for a rule that sits at item 4 (`internal/update/snapverb.go:71,123,241`). The manifest block calls its six numbered lines "the six lines" while line 6 is an example and line 5 is two rules, and `{version}` in the example's apply column is explained nowhere in this tool (`internal/update/cli.go:250`, `internal/update/example.go:20`). The README still pins 1.0.0 (`README.md:86-91`).

USE. The first run is the banner's and it works as printed: `example --out versions.tsv`, then `snapshot --file`, then `report --file`, each exit 0 with a next-step note, and `example` never overwrites (`unchanged=true`). Refusals are the best part of the tool: bare `moved` names all four missing flags, a manifest with three bad lines names line 2, line 3 and line 4 together, both unreadable snapshots are named in one `diff` refusal, an unknown flag lists the verb's flags, and every refusal ends `run:`. `diff` reports changed, removed (`to=-`) and added (`from=-`) sets correctly and its `--json` carries the same facts and items. A skipped symlink is noted by name and not silently dropped, and a mixed set is refused naming both binaries and both stamps.

What keeps USE at 7. `snapshot --bin`, the verb's own deepest real use, is all-or-nothing and names one failure at a time. A `--bin` holding one non-executable `nova-data` is refused at exit 2 as `cannot read nova-data version (not_found)` with `go build ./cmd/nova-data` as the remedy, though the file is present and simply not executable; no snapshot is written. A directory of three bad binaries named only `nova-noparse`. `snapshot --bin --dry-run` still demands an `--out` it never writes, an existing `--out` is replaced without a word, and the source-metadata keys and partial/mixed rules appear in no `-h` line. `send -h` offers a `--draft` the verb refuses. `report` takes no `--json`, so its only machine form is one key=value line with escaped bytes. One bad flag value still ends the list early. `moved` with the default bounds fit a warm-cache two-revision build at this head (33s), but its note and `--json` give bare counts and no rows, and a no-store `send` clips the bus's own refusal at 200 bytes, hiding the fix it names.

A 10 needs the verb's own exit line and defaults in every `-h`, no flag the verb refuses, the source keys and rules in `snapshot -h`, a `--dry-run` that needs no invented `--out`, every bad binary named together under the exit code the table promises, `moved`'s counts defined and written as rows, the bus's missing-store remedy kept whole, and a machine form for report.

## Good, keep

The banner's first run, which works as printed with the binary alone, and the next-step note after every success. Refusals that name the problem and the next command: bare `moved` names all four missing flags at once, a manifest with three bad lines names all three with their line numbers, both unreadable snapshots are named in one `diff` refusal, and every refusal ends `run:`. `snapshot --bin` reads each binary's own `version` line, notes a skipped symlink by name, notes a partial source by name, and refuses a mixed set naming both binaries and both stamps with the commands that rebuild one set. `diff`'s `to=-` and `from=-` and its matching `--json`, `example`'s never-overwrite, and the UNKNOWN path's remedy naming the searched PATH. `moved` reads the two revisions' own builds and never a hand-written list.
