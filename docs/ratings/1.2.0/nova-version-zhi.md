# nova-version READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 02c2dc398d85
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-version version` prints `nova-version v1.0.1-0.20261006143623-02c2dc398d85 linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch directory made for the trial; no live store, no server, and no bus: nova-bus was not on PATH, so every send was one that could not deliver.

## Reasons

READ. The banner answers the first question in its first line and the second in its "how it works" paragraph: report reads, snapshot records, diff compares, moved writes the note, and the manifest verbs are shared with nova-update (internal/update/versiontool.go:23-27). Every verb's `-h` has its usage line, its flags and an `effect:` line that says before the run what it touches. report's `-h` carries the manifest's rules in place, so a cold reader can write a manifest without opening a doc. The spec is numbered, each rule says the mistake it prevents, and its tests are named.

What keeps READ at 7. No `-h` prints a flag's default: `--timeout` and `--budget` read "one child's deadline" and "whole run deadline" (internal/update/versiontool.go:59-60), and the 30s/60s that snapshot uses are only in the spec. send's `-h` lists `--draft`, `--kind`, `--max`, `--timeout` and `--budget`, none on its usage line, and `--draft` is then refused (internal/update/versiontool.go:156). report's usage line leaves out `--send`, though its effect line is about `--send` (internal/update/versiontool.go:117). The manifest rules call themselves six, but rule 6 is an example and rule 5 is two rules, and none of them explains the `{version}` that `example` writes into its own apply column (internal/update/example.go:20). Every verb's `-h` repeats the whole five-verb exit table. The two entry points name different contracts: cmd/nova-version/main.go:3 says SPEC-VERSION.md and docs/CLI.md:1954 says SPEC-UPDATE.md. The README's trial section still pins 1.0.0 (README.md:54-59).

USE. The first run is the banner's and it works as printed: `example --out versions.tsv`, then `snapshot --file`, then `report --file`, each with a next-step note. Running `example` again does not overwrite (`unchanged=true`). A manifest with four bad lines is refused in one run, naming each line and the fix. The UNKNOWN path names the missing command and the PATH it searched, and a slow command is named as `timeout` with the flag that raises it. `snapshot --bin` over two real nova-* binaries wrote a sorted TSV, diff named the added tool with `-` on the absent side, a symlinked nova-* was noted and not recorded, and a mixed-stamp set was refused naming both binaries, with the rebuild commands. `moved` over a three-commit range wrote its note when given a long `--timeout`.

What keeps USE at 7. `moved` with its default bounds failed on this bench after 42s with `cannot build ./cmd/... at <sha> (timeout) (repair the package at that revision)`. The package was fine, and the same run passed with `--timeout 10m`. That refusal also left `nova-version-moved-<n>` and `go-build<n>` directories in TMPDIR without saying so. moved's note and `--json` give bare counts and no rows: `verbs=288` is a total, not a change, and only the spec says so. `snapshot --bin` stops at the first nova-* file that does not answer `version` and exits 2, while help's exit table promises 1 for an UNKNOWN tool. With two bad files it named one per run. `snapshot --dry-run` still demands an `--out` it never writes. An existing `--out` is replaced without notice. `send` with no nova-bus says `send not confirmed: not_found; the bus said: nothing` and does not say that nova-bus is not on PATH. `report --send` without `--snapshot` says to retry "with the same --snapshot". Flag-value refusals name one bad value per run.

A 10 would print defaults in `-h`, show only the flags a verb takes, give moved bounds that fit a full build and a timeout refusal that names the timeout, list moved's rows, name every bad binary in one snapshot run, and name nova-bus when the bus is missing.

## Good, keep

The banner's first run, which works as printed with the binary alone, and the next-step note after every success. A manifest refusal that names every bad line with its fix in one run. The UNKNOWN remedy that names the command and the PATH searched. snapshot reads each binary's own `version` line, notes a skipped symlink by name, and refuses a mixed-stamp set naming both binaries with the commands that rebuild one set. `example` never overwrites. `--json` on example, snapshot, diff, moved and version has one shape: result, facts, items.
