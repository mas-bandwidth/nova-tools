# nova-update READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker dealt a friend's re-rate card
Build: 43b487125e85
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet (the newest is v1.0.0), so this rates the release candidate at the head of sprint/mechanical-2026-10-02. A binary built from it with `go build` says `nova-update v1.0.1-0.20261006145252-43b487125e85 linux/amd64 go1.26.6`. The help was read cold first (`nova-update help`, every verb's `-h`, `help release` and every release verb's `-h`), then docs/SPEC-UPDATE.md, then the tool was used on a Linux bench machine in a scratch directory made for the trial: fake tools, installers and a fake `nova-bus` on a scratch PATH, no live store, no server, no real bus. The manifest verbs ran end to end (example, check, status, apply real and dry, report with a snapshot, draft and send, watch, adoption); github:, npm: and brew: sources were each read once over the network; `release build` built all 24 tools into a scratch root, `release install` installed them into a scratch bin, `release pull` and `release cut` ran with `--dry-run`. adopt and cycle were read, not run: they need ssh machines and an ansible inventory.

## Reasons

READ. The banner is good for an AI: one sentence on what the tool is, a paragraph on how the manifest works, a first run that needs only the binary, the full usage, the defaults, the exit-code contract, and five examples. Every manifest verb's `-h` carries its usage line, an `effect:` line, its flags with what each wants, and the exit codes; the manifest's six rules are printed where they are needed. Unknown verbs and flags refuse with the whole list and a `run:` line.

What keeps READ at 7. Several sentences are not true of the binary. The help and the spec say a result's first line is `OK, FAIL or REFUSED`; the binary prints `CHECK FAILED`, `STATUS FAILED`, `APPLY FAILED`, `REPORT FAILED` (internal/update/out.go:30). Manifest rule 4 says `local:<argv> (a pin takes this only)` (internal/update/cli.go:254), while the example two lines later is a `tool` whose latest is `local:go version`. The top usage lists `release <cut|build|install|adopt|pull>` (internal/update/cli.go:146) and the spec says "Five verbs" (docs/SPEC-UPDATE.md:440), but `release` refuses without a verb by naming six, `cycle` included. Every release verb's `-h` says the version is "such as 1.2.0", and every release verb refuses `1.2.0` as not v-prefixed (internal/release/release.go:227). `help release` and each release verb's `-h` say cut and build "run the dogfood gate FIRST" and refuse on an open edge; with no receipts directory the build skips the gate, prints a NOTE, exits 0 and records `gate=skipped reason=` with an empty reason. The release verbs have no `effect:` line, though install, build and pull write; their notes are single lines of 666 to 1,840 characters (internal/release/cli.go:33 on), repeated under every verb that shares them. `watch -h` says a check's command is "run as written" (internal/update/adopt.go:222) when it is split on single spaces with no quoting, and `adoption -h` still never lists the eight states its ledger takes. The spec still opens "One tool, three verbs" (docs/SPEC-UPDATE.md:6), says "Those ten usage lines" are the help "byte for byte" (docs/SPEC-UPDATE.md:412) over a fourteen-line block that omits the banner's `version` line, and says "The estate runs it nightly" (docs/SPEC-UPDATE.md:27).

USE. The manifest verbs are the strongest part of the tool. `example --out` writes, then answers `unchanged=true` the second time and refuses to overwrite a foreign file. A manifest with five problems was refused with all five at once, each with its line and remedy; a header-case typo, a duplicate name, a double space in an argv, a bad `--kind`, `--max -1` and `--timeout banana` each refused with the remedy. CRLF line endings were read fine. A slow version command came back UNKNOWN `timeout` with the remedy; `--max 1` gave one MORE line per kind. The apply loop is honest: `--dry-run` prints the resolved argv and starts nothing, a real apply prints BEFORE, RUN and AFTER and re-reads the version, an installer that does not change the version is `APPLY FAILED ... installed 0.1.0, asked 0.2.0` exit 1, and `--version 0.1.5` installs that version. Models, unknown names, missing names and `none` installers refuse with who owns the entry. `report --snapshot` with a fake nova-bus sent once, said `unchanged since fake-1 to nobody; nothing sent` the second time, and sent again with REPORT CHANGED lines after the version moved. `--json` is one envelope everywhere it is offered, refusals included. github:cli/cli, npm:opencode-ai and brew:jq answered in 323 ms; a 404 repository was UNKNOWN with the URL. `release build` with an absolute `--out` built and verified 24 tools and wrote a build record; `release install` installed them, and a second install skipped all 24.

What keeps USE at 7. One release defect and one apply behaviour cost the most. `release build --out rel` (relative) built all 24 tools into the source checkout, because the `go build -o` runs with `cmd.Dir = source` (internal/release/edges.go:284), wrote an empty SHA256SUMS under the caller's directory, and then said `BUILD REFUSED: the SHA256SUMS just written cannot be read back: SHA256SUMS lists no artifact` with exit 2, the code for "refused before acting", leaving `rel/` untracked in the checkout. `apply` on an entry already at its latest runs the installer anyway (internal/update/cli.go:705): the example manifest's own entry, applied for real, ran `go install golang.org/dl/go1.26.6@latest` and wrote `~/go/bin/go1.26.6` when `status` had just said EQUAL; I removed that file after checking the module cache showed it was new. Other defects: the pin reader still takes the line's second token (internal/update/read.go:72), so a pin read with `go version` on both sides is `EQUAL installed=version latest=version`, exit 0, `pins=0`; `--send` with no nova-bus on PATH says `send not confirmed: not_found; the bus said: nothing (retry --send ...)` and `sent=uncertain`, when nothing could have been sent; `Compare` orders only equally long versions (internal/update/read.go:393), so jq `1.6` against `1.8.2` is DIFFERENT, not STALE; a header-only manifest is `CHECK OK checked=0` exit 0 and an empty checks file is `ADOPT DONE sha=e3b0c44298fc ok=0` exit 0, the hash of nothing; the model refusal's remedy is `ollama pull mdl`, the entry's name, not its `qwen3:8b` tag (internal/update/cli.go:667); with `--version` the BEFORE line calls the asked version `latest=` (internal/update/cli.go:702). Carried over: watch still splits one pass across stdout and stderr; `release cut --dry-run` still asks the forge where the branch is before any plan, even with `--local-diff`, and fails offline (internal/release/cut.go:489); `release install` has no `--dry-run`.

A 10 would make every help and spec sentence true of the binary (FAIL or FAILED, the six release verbs, the version shape, the gate's skip); resolve `--out` and `--source` to absolute paths once; make apply on an entry already at the target a no-op unless asked; read a pin's version-shaped token; say a missing nova-bus is not found and `sent=no`; order versions of unequal length; refuse a green over nothing; keep watch on one stream; and give the release verbs `effect:` lines, short notes, and a dry-run for install.

## Good, keep
A manifest refusal lists every problem at once, each with its line and a remedy, then one `run:` line.
The apply loop re-reads the version after the installer and fails when it did not move: `APPLY FAILED ... installed 0.1.0, asked 0.2.0`.
`--dry-run` on apply prints the resolved argv and starts no process; `example --out` never overwrites a foreign file.
`report --snapshot` sends a changed report once, and says what it did not send and why.
UNKNOWN is never OK: a timeout, a missing tool, a 404 source and an undeclared latest each come back UNKNOWN with a remedy, exit 1.
`release build` verifies what it built and writes a record of the commit, the Go and the gate; `release install` verifies against SHA256SUMS and skips what is already there.
