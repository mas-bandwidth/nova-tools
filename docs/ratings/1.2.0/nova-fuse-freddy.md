# nova-fuse READ and USE rating, nova-tools 1.2.0

Rater: deepseek-v4.1-flash in opencode, a sprint worker on a friend's re-rate card
Build: c76fcb249cc1
READ: 7/10
USE: 9/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-fuse version` prints `nova-fuse v1.0.1-0.20261007015429-c76fcb249cc1 linux/amd64 go1.26.6`. Read cold (`nova-fuse help`, every `help <verb>`, the spec, the reference) and used for real on a scratch directory made for the trial: hand-written and tool-written boxes, every write verb, every dry run, a hand-edited box, a box holding two spellings of one surface, a null quarantine, an unknown top-level key, a directory in place of the box. No live store, no server, no network.

## Reasons

READ. `nova-fuse help` is still a strong first screen: line one is the one-sentence job, `how it works` names the box and the surface in five lines, the usage table gives one line per verb, the exit table is by verb, and the six-line `example:` is one sitting that runs as printed. Every `help <verb>` carries the verb's usage, its flags, its exit codes and an `effect:` line saying before the run whether it inspects or writes. The reference's `### First run` is a real transcript and the gate is stated in the reader's terms: only exit 0 is permission, `status` never gates.

What keeps READ at 7. The 1.1.0 findings are nearly all still there. The normative grammar prints `FUSE FAIL` and `LOCKDOWN FAIL`, `QUARANTINE FAIL`, `LIFT FAIL`, `INIT FAIL`, while the binary writes `FUSE FAILED`, `LOCKDOWN FAILED`, `QUARANTINE FAILED`, `LIFT FAILED`, `INIT FAILED` and the executed reference agrees with the binary (docs/SPEC.md:2043,2049-2054 against cmd/nova-fuse/check.go:59, init.go:38, main.go:453,598,693; docs/CLI.md:316). The box listing is said to be "in the box's own order" (docs/SPEC.md:2185) while the binary sorts it (internal/fuse/fuse.go:213), and the spec contradicts itself two hundred lines earlier where it says quarantines sort (docs/SPEC.md:2074). The package doc is still eighty-six lines of shouted numbered headings before a sentence (internal/fuse/fuse.go:1). The banner is still about seventy lines of prose before the `example:` block (cmd/nova-fuse/main.go:37, example at main.go:95). The verb list stands in the usage constant (main.go:47), the `verbs` slice (main.go:141), the help map (help.go:28) and two unknown-verb sentences that now disagree: `help nosuch` lists `lift quarantine, lift lockdown` while a bad first word lists `lift` and `help` (help.go:108 against main.go:205). The trial section still opens "These are the Nova Tools 1.0.0 commands" and installs the older tag while the tree ships this release (README.md:55). The tool still does not call the shared skeleton and still refuses `--json` by design (main.go:74).

USE. The gate is trustworthy and the refusals are excellent. `check` exits 0 only when it proved what it was asked, 1 when a fuse is positively blown, 2 when it cannot prove clear; a readable box that is blown still reports with `status` at exit 0. Every write re-reads the box and says `verified`. A surface is matched folded, in both directions, and a refusal quotes the spelling as stored. `--dry-run` on all four write verbs writes nothing and says `dry_run=true`. `status` keeps its uncapped count under a bounded list with a `MORE shown= total=` line, and `--max 0` widens it. A second quarantine of one surface no longer silently loses the first: the line says `already=quarantined` and `the standing record kept; the new reason was not recorded`. Repeated flags, a `--box` beginning with `-`, more than one surface, a blank surface, an empty reason and a missing box are each refused in one line with a remedy. A malformed box, a null top level, an unknown top-level key and a directory at the path all fail closed at exit 2. `lift lockdown` refuses forever before reading anything.

What keeps USE at 9. Three 1.1.0 findings stand. No verb has `--json`, so an AI parses typed lines by hand and must read the spec for the grammar. `check --bogus` names only the unknown flag and never the also-required `--box`, so a cold caller needs a second run. The blown `FUSE FAILED` line and its remedy go to stderr while `FUSE OK` goes to stdout, so a caller that reads only stdout sees an empty result on exit 1. One new finding: `init` silently creates missing parent directories (`init --box ./gone/deep/x.json` made the tree and a box at exit 0), which nothing in the help, the reference or the spec says.

A 10 needs the spec's grammar samples equal to the bytes the binary writes; the box listing stated as the sorted order the binary prints; a machine-readable rendering or the exception argued where the family standard can see it; the missing `--box` named in the same run as an unknown flag; the blown result on stdout; one verb list feeding dispatch, help and every refusal; the package doc and the banner cut to their rules; the README on the shipped release; and the parent-directory make either stated or refused.

## Good, keep
The gate contract and its exit codes: one verb that looks, exit 0 as the only yes, 1 for a positive blow and 2 for cannot tell, with `status` deliberately never gating (cmd/nova-fuse/check.go:27). The folded matching that cuts both ways and the refusal that quotes the stored spelling, with the lift remedy a runnable one-line command over the exact box and surface (cmd/nova-fuse/check.go:13). Every write verified by re-reading the box and saying `verified`. The four dry runs that write nothing and say `dry_run=true`. `status`'s uncapped count under a bounded list with its `MORE` line. The failure mode that treats an absent, unreadable, malformed, null, unknown-shaped or directory box as BLOWN, never as clear (internal/fuse/fuse.go:225). The `already=quarantined` line that keeps the first record and announces that the new reason was not recorded. `lift lockdown` refused forever before anything is read. The `--` door that keeps an untrusted surface or reason from becoming a flag.
