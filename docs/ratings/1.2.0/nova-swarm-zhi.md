# nova-swarm READ and USE rating, nova-tools 1.2.0

Rater: deepseek/deepseek-v4.1-flash under dsh (the DeepSeek Harness headless runner), a friend on a re-rate card
Build: 81b318639963
READ: 6/10
USE: 6/10

No v1.2.0 tag exists on the forge, so this rates the release candidate at the head of sprint/mechanical-2026-10-02: `nova-swarm version` prints `nova-swarm v1.0.1-0.20261007220135-81b318639963 linux/amd64 go1.26.6`. This file carries the READ and USE work of attempt 1 (head 71e59f072686), re-verified at this base; every finding below names one place. Built and run on a Linux bench in a scratch directory made for the trial; no live store, no server and no model was called. `native` ran end to end with the tree's own fake harness (cmd/nova-swarm/testdata/fakeharness), walled and unwalled; `member` and `mirror` were read only, because the first needs a sprint server and the second reaches the network.

## Reasons

READ. The banner says what the tool is in one line, the same sentence as its row in the README (README.md:31), then how it works, the credential rule, the sandbox rule and how to prepare a card, and its three examples print templates and the lint rules with no setup. Every verb answers `-h` and `help <verb>`, most carry an `effect:` line, every flag is described with a required marker, and the exit table is quoted by every verb. `native` with no flags names all seven missing inputs in one run, each with what it wants. That is the shape an AI wants.

What keeps READ at 6. The help says things the binary does not do, and the spec has drifted from the binary it is normative for. `verify -h` says `effect: inspection: ... writes nothing` (cmd/nova-swarm/main.go:184) while every run writes `<result>.receipt` (cmd/nova-swarm/main.go:553), a refused result included. SPEC-SWARM.md:48 says "eleven living verbs" while `nova-swarm help` prints and the dispatch carries fifteen, and the spec's usage block (SPEC-SWARM.md:50) omits `step`, `install`, `uninstall` and `slots run`. The output grammar (SPEC-SWARM.md:131) names `SLOTS OK store=<dir> capacity=<n> share=<n>` and `SLOTS GRANTED`; the binary prints `SLOTS INIT OK store=... owner=... capacity=... reserve=... share=...` and `SLOTS OK owner=ada granted=1 held=1 share=2 free=3`. No verb accepts `--json`, so the one output structure with two renderings the standard asks for is absent from the whole tool. An unknown flag truncates the flag list (`native --bogus` ends `--repo and 11 more`, `lint --json` ends `--trust and 1 more`), hiding the flag a reader wants. The required-input refusals use a second grammar with no `REFUSED` token and no `run:` line, `worker -h` and `slots run -h` have no `example:` line, and `profile -h` and the `slots init|take|release|run -h` pages have no `effect:` line. The read-pr prompt still carries measurement history inside the instructions the worker follows (pkg/swarm/templates.go:27), and the member paragraph at SPEC-SWARM.md:86 is one 20,067-character line.

USE. The banner's first run is clean: `template --name read-pr`, `template --name worker` and `lint --rules` exit 0. `template --name card` lints `LINT OK` and fails `--typed` with four DRIFT lines that each name the line to add. The slots lifecycle works and every state change prints a typed line: init, take, a second take refused with the holders and a runnable `remedy=`, `slots run -- echo hello` printing `hello`, `slots run -- false` passing exit 1 through, and `SLOTS KEPT` naming why a running holder's lease is not freed. `native` with the fake harness ran a card end to end in about a tenth of a second, walled (`sandbox=landlock`) and with `--no-wall` (`sandbox=none-by-flag`), publishing `RESULT.md`, `usage.tsv` and a report under `results/<label>/<run>/1/`. `disk-guard --dry-run`, `install --dry-run` and `uninstall --dry-run` print the plan and write nothing. `worker check` drift names the field and the template that prints a valid description.

What keeps USE at 6. Things that should fail pass, and one pass writes when it says it does not: `verify` accepts a result whose line 2 is `all good` with no `## Head` and no `findings:` line, against the spec's plan-only rule (SPEC-SWARM.md:21), and its receipt records `card_sha256=e3b0c442...`, the hash of nothing, when no `--card` was given; `doctor --local /nonexistent` is `DOCTOR OK` exit 0; `profile` over a glob that matches nothing, or a native job directory with no timeline.tsv, is `PROFILE SUMMARY jobs=0` exit 0. The four carried 1.1.0 defects are still there: the native `-h` example refuses as printed, the result template fails verify, required-input refusals use the second grammar, and no verb has `--json` or `--dry-run` where it writes or spends. `step` refuses as `nova-swarmstep REFUSED` (cmd/nova-swarm/main.go:220, the join in `refuse` that adds no blank). `slots list` shows a `take` lease as `state=live stranded=1`, both at once. `slots take --owner bob` against a store with no bob refuses as `share=0`, which reads as a full share, not an unknown owner. `slots list` refuses `--max` and `lint --rules --max 3` prints all forty-five rules and no MORE line, against the spec's cap-and-count rule (SPEC-SWARM.md:146). `native --dry-run` is an unknown flag on the verb that spends.

A 10 would make every `effect:` line, help claim and spec statement true of the binary, give every verb one `REFUSED ...; run: nova-swarm help <verb>` grammar and `--json` from one result value, list every flag in a refusal, add `--dry-run` to native, refuse a green over nothing (verify with no head, doctor on a missing file, profile on no jobs), make the native example and the result template pass as printed, and paste the banner's usage block into the spec.

## Good, keep

The banner's line 1 is the README's row sentence (README.md:31), the shape the standard asks.
