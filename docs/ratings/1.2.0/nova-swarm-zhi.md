# nova-swarm READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker dealt a friend's re-rate card; the rating is this worker's, not the friend's
Build: 193a6f8002d0
READ: 6.5/10
USE: 6.5/10

No v1.2.0 tag exists yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. A binary built from it says `nova-swarm v1.0.1-0.20261006150140-193a6f8002d0 linux/amd64 go1.26.6`. The banner and every verb's `-h` (the five `slots` subverbs and `worker check` included) were read first, then docs/SPEC-SWARM.md, then the tool was used on a Linux bench machine in a scratch directory made for the trial: no live store, no server, no model called. `native` ran with four shell-script harnesses (one that writes the card's result, one that sleeps, one that exits 3, one that writes the wrong line 1), walled and unwalled. `member` was read and not run, because it needs a sprint server.

## Reasons

READ. The banner says in one line what the tool is, then how it works, what a first run needs, the exit table, the credential rule and the wall rule, and its three examples spend nothing. Every verb answers `-h` with exit 0, its usage, flags marked `required:`, its exit codes and, on most verbs, an `effect:` line. Unknown verbs and flags get one `REFUSED` line listing what exists and ending `run: nova-swarm help <verb>`, and a missing store names the `slots init` line to run. The sandbox and credential paragraphs are the clearest part: the key is data, the wall is on unless `--no-wall` is written, and the opt-out is printed on the result line.

What costs the score is help that is wrong where a reader acts on it. `verify -h` says `writes nothing` (cmd/nova-swarm/main.go:173), and verify wrote `result.md.receipt` beside every result it read, a published one included (cmd/nova-swarm/main.go:533). The `native -h` example puts `--slot slots/1` outside `--root jobs` and is refused as written. `lint -h` says `--max` caps item lines, and `--max 2` printed all ten NOTE lines (cmd/nova-swarm/lint.go:1062). The typed header is named three ways: `template -h` says KIND, PATHS, TEST, DEPENDS-ON and DONE-WHEN; `lint -h --typed` says KIND, PATHS, TEST, PAUSED and DEPENDS-ON; the lint drifted on KIND, PATHS, TEST and DEPENDS-ON only. `slots run -h` says `0 done` and never that the command's exit code passes through, which it does. `worker -h` has no flags and no example. `step -h` never says what a script step looks like, which is the refusal a stranger meets first. In the spec, the usage fence (docs/SPEC-SWARM.md:48) has no `step` and an older `lint` line, and the output grammar names `SLOTS OK store=... capacity=...` and `SLOTS GRANTED`, which the binary never prints; line 84 is one 20067-character paragraph.

A 10 is help whose examples run as written and whose `effect:` and exit lines are true, one refusal shape, a documented script step, and a spec whose fence and grammar are the binary's.

USE. The first run is clean: `template --name read-pr`, `template --name worker` and `lint --rules` exit 0, and `template --name card` lints `LINT OK checks=45`. The slots loop works: init, take, a second take refused with `holders=me:1` and a `remedy=`, re-init refused with the reason, `slots run -- echo hi` printing `hi`, `slots run -- sh -c 'exit 7'` exiting 7, a take over the share refused at once. `worker check` on `{}` names all ten missing fields in one run. `native` with an absolute harness ran walled (`sandbox=landlock`) and unwalled (`sandbox=none-by-flag`) in about 0.2 s, published `RESULT.md`, `usage.tsv` and a report, and `verify --usage` passed the published result. `--idle 2s` ended a sleeping harness at 2.03 s with `why=harness-silent`, `CARD IDLE` and a written block report. Every missing native flag is named in one run, and `--tokens 0`, `--deadline banana` and a model with no slash are each refused with the reason.

What costs the score is that `NATIVE OK` does not mean what a caller will read it to mean. A harness that wrote `RESULT: other sha=fff` for a card whose line 1 is `RESULT: trial sha=0123456789ab` ended `NATIVE OK ... rc=0`, exit 0: native knows the contract line and never compares it (cmd/nova-swarm/main.go:1007). `--tokens 1000` with no usage store ended `NATIVE OK budget=-/1000`, exit 0, where the spec's exit table says that case is exit 2 (docs/SPEC-SWARM.md:119). A harness that exited 3 was reported `harness=silent why=harness-silent`, while the field's own comment says silent is a child that exited 0 (cmd/nova-swarm/native.go:192). `--deadline 3s --tokens unmetered` was refused because the default `--usage-interval 5s` is not shorter than the deadline, though an unmetered run samples nothing (internal/swarm/nativebudget.go:129). A relative `--harness ./harness` passes the flag check and then fails inside the job directory as `WALL REFUSED denied <job dir>` and `ran without a SANDBOX OK line`; the true cause, `harness cannot be run`, is only in the report file. With no `--identity`, the refusal's remedy is a `make -C fleet converge` in another repository (internal/swarm/staging.go:41). `profile` printed `PROFILE SUMMARY jobs=0`, exit 0, for a glob that matches nothing, a glob of garbage and the run's own slot and result directories. `slots take` from a shell lists at once as `state=live stranded=1`, because the lease's holder is the take process that has exited, and `--owner ghost` is refused as `share=0` without saying the owner has no row. The result template still fails verify, `step` still refuses as `nova-swarmstep REFUSED`, `step --dry-run` refuses before printing anything, missing-flag refusals still lack `REFUSED` and `run:`, and `worker check` prints the template's placeholder as `<the\x20harness\x20command\x20on\x20PATH>`.

Not tried: `member` against a server, a real model call, a REPO: card's staging, and `step` on a script-only card, because no help says how to write one.

A 10 keeps this slots loop and this native loop, and makes `NATIVE OK` mean the contract held and the budget was measured: compare line 1, refuse an unmeasurable numeric budget before launch, name a non-zero exit as `rc`, and resolve the harness path once at the check.

## Good, keep

The native loop: with an absolute harness, a walled run takes about 0.2 s, prints one NATIVE line with the sandbox backend or `none-by-flag`, the card and binary hashes and the budget, and publishes `RESULT.md`, `usage.tsv` and a report under `<root>/results/<label>/<run>/1/`.

`--idle` works as written: a silent harness ended at 2.03 s under `--idle 2s`, with `CARD IDLE`, exit 1 and a block report written for it.

The slots loop: a full share is refused with the holders and a `remedy=` command, `init` never overwrites a store and says why, `slots run` passes the command's exit code through, and a missing store names the `slots init` line to run.

Every missing `native` flag is named in one run, each saying what it wants, and bad values (`--tokens 0`, `--deadline banana`, a model with no slash) are refused with the reason.

`worker check` lists every missing field of an empty description in one run, each saying what the field wants.
