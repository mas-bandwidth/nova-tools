# nova-swarm READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 7a61cf1d1ff9
READ: 7/10
USE: 6/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-swarm version` prints `nova-swarm v1.0.1-0.20261006144045-7a61cf1d1ff9 linux/amd64 go1.26.6`. Built and run on a Linux bench machine in a scratch directory made for the trial: no live store, no server started, no model called. The banner and every verb's `-h` were read before anything was run, and docs/SPEC-SWARM.md after. native ran end to end with shell-script harnesses, walled and unwalled, through OK, no-result, nonzero-exit and deadline endings. member was run once against an address with nothing listening, and the slots lifecycle against a fresh store.

## Reasons

READ. The banner gives what the tool is in one line, how a card flows, the credential and sandbox rules and how to prepare a card. Its three examples run with no setup. Every verb answers `-h` with its banner excerpt, flags, exit codes and, for most, an `effect:` line, and an unknown verb or flag names the verb list and `help <verb>`. That is close to the shape an AI wants.

What keeps READ at 7. The one contract a first user of native has to meet, the harness, is not written anywhere a reader looks first. native `-h` says the harness is "checked for existence and execution" but not how it is called: it gets `run --model <m> --title <label> -- <the whole card>`, runs with the job directory as its working directory, and must leave RESULT.md there to be published. I learned that by having a script print its own argv. The banner's "Inputs" list is a card, harness, model, slot, root, deadline and token budget, but a pool identity is required too (`--identity` is shown as optional, with a default file that a fresh root does not have). A card's `REPO:` line also needs a "bench mirror", which no help text names or explains how to make. The help says things the binary does not do. verify `-h` says "writes nothing" (cmd/nova-swarm/main.go:173), but every run writes `<result>.receipt`. lint `-h` says `--fleet` checks "bash-4 builtins", but it knows two, `mapfile` and `readarray` (cmd/nova-swarm/lint.go:480). slots run `-h` lists exit codes 0 and 2, but it passes the command's own exit through (7 from `sh -c 'exit 7'`). The spec still says "eleven living verbs" (docs/SPEC-SWARM.md:48) above a usage block older than the banner, and line 84 is one 20,067-character paragraph. lint's flag list prints `--card <lint <file>>` and five `<string>` placeholders.

USE. Three verbs work well when used for real. `template` and `lint` give a usable card in two commands. The slots lifecycle is clear at every step (init, take, a second take refused with the holders and a remedy, release, `slots run` passing its command's exit through). native, once its harness was given as an absolute path, ran a card in about a third of a second, walled (`sandbox=landlock`) and unwalled (`sandbox=none-by-flag`), and published RESULT.md, usage.tsv and the report under `<root>/results/<label>/<run>/1/`. A harness that writes no result is `why=no-result`, a harness that exits 3 is `why=rc` with exit 3, and the next command after each one is clear.

What keeps USE at 6. One input crashes a verb, the example as printed fails, and several results are a pass when they should not be. `verify` panics with a Go stack trace (`slice bounds out of range [2:1]`, pkg/swarm/contract.go:82) on a RESULT.md that holds only its contract line, which is the smallest result a harness can write. native's own `-h` example names `--harness ./harness`: with that file present, the existence check passes, and the child then fails to start. Walled, it fails with `NATIVE REFUSED: card2 wall ran without a SANDBOX OK line naming its backend`, and the real cause (`--read . is relative`, `.../jobs/card2/harness cannot be run`) is only inside the report file. With `--no-wall` it fails as `fork/exec ./harness: no such file or directory`. A relative path is resolved against the job directory rather than the caller's. Things that should fail pass: `NATIVE INCOMPLETE ... why=no-result` exits 0. `member --once` against a server that refused the connection exits 0. `slots release --label nosuch` is `SLOTS RELEASED released=0`, exit 0. `--tokens 100` with a harness that reports no usage is `NATIVE OK budget=-/100`, with the budget never checked. `doctor --local /nonexistent` is `DOCTOR OK`. `profile` over native's own job directories is `PROFILE SUMMARY jobs=0`, exit 0. lint passes a card with its placeholders unfilled (`LINT OK`, ten NOTE lines that each carry the same 330-character remedy). A 3s deadline ends at `wall=8.04s` as `why=harness-silent`, and the NATIVE line has no word for a deadline at all. Asking for that deadline needs `--usage-interval 1s`, because the default refusal reads `--usage-interval is shorter than --deadline, got 5s against a deadline of 3s`, which states the opposite of the fault. The 1.1.0 carry-overs remain: the result template fails verify, required-input refusals have a second grammar with no `run:` line, `nova-swarmstep REFUSED`, the unknown-flag list cut to "and 11 more", and no `--json` anywhere.

A 10 would make the help's harness contract and required inputs complete, make a relative `--harness` work (or refuse it) at the check, never panic, give every "should fail" above a nonzero exit, give a deadline its own word on the NATIVE line, make the `-h` example and the result template pass as printed, use one refusal grammar, and make every `effect:` and spec claim true of the binary.

## Good, keep

native, given a harness by absolute path, runs a card inside the wall in a third of a second, and its NATIVE line says the wall it used, the budget and the reason a run is incomplete (`why=no-result`, `why=rc` with the child's exit passed through). The published results directory (RESULT.md, usage.tsv, report) is the right shape to hand to verify. The slots lifecycle is the best part of the tool to use: each state change is one typed line, a refused take names the holders and a runnable `slots list` remedy, and `slots list` on a missing store prints the exact `slots init` to run. The banner's three examples and `template --name card` then `lint` give a first card with no setup. Unknown verbs and flags name the verb list and `help <verb>`. member names every missing required flag in one run, and its NOTE on an empty `--pass` names the consequence and the fix.
