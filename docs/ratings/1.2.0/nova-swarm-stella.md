# nova-swarm READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker dealt a friend's re-rate card
Build: 361d4451bcd8
READ: 7/10
USE: 5/10

There is no v1.2.0 tag on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. A binary built from it says `nova-swarm v1.0.1-0.20261006144651-361d4451bcd8 linux/amd64 go1.26.6`. I read `nova-swarm help` and every verb's `-h` (the five `slots` subverbs included) before using anything. Then I used the tool on a Linux bench machine, in a scratch directory made for the trial: no live store, no server, no model. The verbs I ran were the three banner examples, template, lint, verify, the whole slots lifecycle, native end to end with shell-script harnesses (walled, `--no-wall`, a relative harness, a deadline kill, an idle kill), step (dry run, walled, unwalled), doctor, profile, worker check and `disk-guard --dry-run`. I read member but did not run it, because it needs a sprint server. One thing I have to disclose about the cold read: before I started, I saw another friend's 1.2.0 rating of this tool on its branch. So every finding below was re-run on my own build, and the ones they had and I could not reproduce are left out.

## Reasons

READ. The banner is a good contract for an AI. In order it gives one sentence on what the tool is, how a card flows, the credential and sandbox rules, how to prepare a card, the exit-code meaning, and three examples that run with no setup. Every verb answers `-h` with its banner excerpt, its flags (marked `required:` where they are, with defaults), its exit codes and, mostly, an `effect:` line. Unknown verbs and flags are refused with the full verb or flag list and a `run:` line. `template -h` lists a card's required lines and says what each one is for.

READ is held at 7 because some of the text is not true of the binary, and the hardest verb hides what you most need to know:
- **native.** `native -h` documents eleven flags the banner usage leaves out (`--bench`, `--no-shared-caches`, `--no-wall`, `--owner`, `--recipient`, `--repo`, `--sandbox`, `--slots-store`, `--stage-timeout`, `--usage-interval`, `--usd`). Two of them say they are "accepted and read by nothing" (cmd/nova-swarm/main.go:644). `--idle` says the card ends when "neither its output nor its process tree has moved". In fact output under 4096 bytes per window counts as still (internal/swarm/nativeidle.go:74), so a harness printing one line a second is killed as idle. The help never mentions three preconditions that each surface only as a refusal: the shadowed-binary preflight that runs before every launch, the pool identity, and the argv the harness is called with (`run --model <m> --title <label> -- <the whole card>`).
- **Other verbs.** `verify -h` says it "writes nothing" (cmd/nova-swarm/main.go:173), yet it writes `<result>.receipt` on every run, refusals included. `step -h` never says what a script step looks like; that is in lint's `script-step` remedy only. `worker -h` lists no flags and has no example, and `profile`, `slots init|take|release|run` have no `effect:` line. The no-verb refusal calls `template --name card` "the one that only looks" (cmd/nova-swarm/main.go:234), but five other verbs only look too.
- **The spec.** It still says "eleven living verbs" (docs/SPEC-SWARM.md:48), and the binary has twelve. Its slots grammar (docs/SPEC-SWARM.md:129) names lines the binary does not print. Line 84 is one 20,067-character paragraph.

USE. The first run is clean. The banner examples exit 0, and `template --name card` lints `LINT OK` with one NOTE per unfilled line. Each slots change prints a typed line: a second take is refused with its holders and a `remedy=`, re-init is refused with the reason, and `slots run -- sh -c 'exit 7'` exits 7. native with an absolute harness and `--identity` ran walled in 0.03 s (`sandbox=landlock`) and published `RESULT.md`, `usage.tsv` and a report under `<root>/results/<label>/<run>/1/`, and it left no process behind after any kill. A `--slot` outside `--root` and a model with no slash are refused before anything is made. `step` unwalled rewrote, checked its POST and committed in one line. `step --dry-run` and `disk-guard --dry-run` print a real plan and write nothing.

USE is held at 5 because native, the verb that spends, misreports how it ended. I made three abnormal ends on purpose and got three wrong reasons:
- **Deadline as idle.** A harness printing `tick` every second, under `--deadline 4s` with the default 5m idle, ended with `CARD IDLE ... idle=4s` and `why=rc`. It published a `RESULT: BLOCKED` saying "the card's log and its process tree were both still for 4s". The log had grown every second.
- **Deadline as silence or no result.** A silent harness under `--deadline 3s` ended `why=harness-silent`. With `--idle 0` and `--deadline 4s` it ended `why=no-result`. Neither run says the deadline fired.
- **Late kills.** Those two runs ended at `wall=8.04s` and `wall=9.03s`, about five seconds past "the wall-clock bound that ends the child".
- **Relative harness.** `--harness ./harness`, the shape of native's own `-h` example, passes the check and then fails inside the wall. It prints `NATIVE REFUSED: n1 wall ran without a SANDBOX OK line naming its backend`, and the real cause (`.../jobs/n1/harness: no such file or directory`) is only in the published report.
- **The doctor preflight.** It refuses a launch when the build on PATH differs from `~/.local/bin`, and its remedy is to copy the installed binary over the PATH one. For a newer build under test, that remedy is a downgrade. Worse, the preflight compares PATH against `~/.local/bin` and never checks the binary that is actually running (cmd/nova-swarm/doctor.go:532): run by absolute path with PATH unchanged, the same new build launches without complaint.

Smaller defects. A walled step fails its POST with `exit status 125:` and nothing after the colon, and leaves the rewrite uncommitted. `step` leaves a `TMPDIR/nova-step-*` directory on every non-dry run (cmd/nova-swarm/step.go:91). A missing `--dir` is exit 1 `STEP FAILED`, not exit 2. Refusals print as `nova-swarmstep REFUSED`. lint rejects "there are no tests." because of the trailing period (cmd/nova-swarm/lint.go:212), and does not know the kind `script` that docs/SPEC-ISA.md:26 declares. `slots release` of a label nobody holds and `profile` over no timelines both report success. A lease from `slots take` lists as `state=live stranded=1`. The remaining carry-overs are listed in the table below.

A 10 needs native to name the deadline as the deadline and stop at it, the idle rule to say in its help and its BLOCKED report what "moved" means, `--harness` resolved to an absolute path once, and the doctor preflight to check the running binary with a remedy that never downgrades it. It also needs every `-h` sentence and spec claim true of the binary, the result template to pass verify, a refusal for every green over nothing, and one `REFUSED ...; run:` grammar for every refusal.

## Good, keep
- The banner's three examples run as printed with no setup, and `template --name card` prints a card that lints `LINT OK`, with one NOTE per unfilled `<...>` line.
- The slots lifecycle prints a typed line for every change. A refusal names its holders and a `remedy=`, re-init explains why it never overwrites, and `slots run` passes the command's exit code through.
- native refuses early and specifically: a `--slot` outside `--root`, a model with no slash, `--tokens 0` with how to say unmetered. A walled run states its backend (`sandbox=landlock`), an unwalled one says `sandbox=none-by-flag`, and no kill left a process behind.
- `step --dry-run` and `disk-guard --dry-run` print the real plan and write nothing.
