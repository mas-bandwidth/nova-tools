# nova-swarm READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker dealt a friend's re-rate card
Build: b250530c1ab3
READ: 7/10
USE: 6/10

No v1.2.0 tag exists on the forge yet (the newest is v1.0.0), so this rates the release candidate at the head of sprint/mechanical-2026-10-02. A binary built from it with `go build` says `nova-swarm v1.0.1-0.20261006143256-b250530c1ab3 linux/amd64 go1.26.6`. The help was read cold first (`nova-swarm help` and every verb's `-h`, the five `slots` subverbs included), then the spec, then the tool was used on a Linux bench machine in a scratch directory made for the trial: no live store, no server, no model called. native ran end to end with a shell-script harness, walled and unwalled, and was killed by its deadline once on purpose; step ran a regex script card walled and unwalled; member was read, not run, because it needs a sprint server.

## Reasons

READ. The banner is good for an AI: one line saying what the tool is, how a card flows, the credential rule, the sandbox rule, how to prepare a card, the exit-code meaning, and three examples that run with no setup. Every verb answers `-h` and `help <verb>` with the banner excerpt, the flags with `required:` and defaults, exit codes, and mostly an `effect:` line. Unknown verbs and flags refuse with the whole verb or flag list and a `run:` line.

What keeps READ at 7. Several sentences in the help are not true of the binary. `verify -h` says it writes nothing (cmd/nova-swarm/main.go:173) and its own exit codes then name "a receipt that cannot be written"; it writes `<result>.receipt` every run. The no-verb refusal says `template --name card` "is the one that only looks" (cmd/nova-swarm/main.go:234), when lint, verify, doctor, version and slots list only look too. The spec says every listing takes `--max` with a MORE line (docs/SPEC-SWARM.md:144); `lint --rules --max 3` prints all 45 rules and `lint --card --max 2` prints all ten NOTEs. native's `-h` never says the harness is called with an opencode-shaped argv (`run --model <m> --title <label> -- <the whole card>`), that a card's `REPO:` line needs a bench mirror, or that a pool identity is required; each is found only by its refusal. `step -h` never says what a script step is; the card shape (`SCRIPT: regex|go|lisp`, a fenced program, `POST:` lines) is only in a lint remedy. `worker -h` lists no flags (`--env`, `--max`) and has no example; `slots run -h` and `slots take -h` have no `effect:` though they write a store, and `slots run -h` does not say the command's own exit code is passed through. The spec still says "eleven living verbs" (docs/SPEC-SWARM.md:48) for twelve, its output grammar names `SLOTS OK store= capacity= share=` and `SLOTS GRANTED` where the binary prints `SLOTS INIT OK` and `SLOTS OK owner=`, and line 84 is one 20,067-character paragraph.

USE. The first run is clean: the three banner examples exit 0. `template --name card` lints OK with ten placeholder NOTEs, and `--child-rules` on a card with one rule removed names exactly that rule with its verbatim sentence. The slots lifecycle prints a typed line for every change: init, take, a second take refused with its holders and a `remedy=`, re-init refused with why, `slots run -- sh -c 'exit 7'` exits 7, and `slots run` against a full share refuses after `--wait`. native with an absolute harness path, `--tokens unmetered` and `--identity` ran in a few hundredths of a second, walled (`sandbox=landlock`) and with `--no-wall`, and published `RESULT.md`, `usage.tsv` and a report under `<root>/results/<label>/<run>/1/`. A harness that sleeps was killed at its 12 s deadline (`wall=12.01s`, exit 1) with no process left behind. `doctor` correctly refused a freshly built binary that shadows the installed one, naming both stamps. `disk-guard --dry-run` on scratch roots ended `DISK-GUARD OK freed=0`.

What keeps USE at 6. Three things misreport what happened. A run killed by its deadline says `why=harness-silent` (cmd/nova-swarm/main.go:1007) and publishes a zero-byte `report`, so the reader is told the harness was silent, not that the deadline fired. A relative `--harness ./harness`, the shape of native's own `-h` example, passes the existence check against the caller's directory (cmd/nova-swarm/native.go:431) and then fails `fork/exec ./harness: no such file or directory`, after staging. `step` walled failed its `POST: exit0 grep -q hi out.txt` with `exit status 125:` and nothing after the colon, leaving the rewrite in the checkout uncommitted. Other defects: `lint` does not accept "there are no tests." as the no-tests statement, because `.` counts as a word character after `no tests` (cmd/nova-swarm/lint.go:212); `step` leaves a `nova-step-*` directory in TMPDIR on every run (cmd/nova-swarm/step.go:91); `slots release --label <a label nobody holds>` is `released=0` exit 0; native refuses `--deadline 5s --tokens unmetered` because the usage interval is "shorter than" the deadline, when it is equal, and no budget is sampled for an unmetered run; the pool-identity refusal names an internal tool as its remedy (pkg/swarm/staging.go:41). The carry-overs I checked are still there: the result template's line 1 is `# <task>` and fails verify; verify passes `RESULT: ...` then `all good` with no `findings:` head; verify's receipt holds the empty-input hash without `--card`; `doctor --local /nonexistent` is `DOCTOR OK`; `profile` over nothing is `PROFILE SUMMARY jobs=0` exit 0; native runs a card with unfilled `<...>` lines without a word; required-input refusals have no `REFUSED` and no `run:`; `step` prints `nova-swarmstep REFUSED`; `slots list` shows `state=live stranded=1`; an unknown owner refuses as `share=0`; worker check names only the harness, escaped `<the\x20harness\x20command\x20on\x20PATH>`.

A 10 would make every `effect:` line, help sentence and spec claim true of the binary; resolve `--harness` once to an absolute path; name the deadline as the deadline; make every failure line carry its cause; make the result template pass verify; refuse a green over nothing (verify with no head, doctor on a missing file, profile on no jobs, release on no lease); give every refusal the one `REFUSED ...; run:` grammar; and document the harness argv, the script-step shape and the staging preconditions in the verb's own `-h`.

## Good, keep
The banner's first-run promise holds: three examples, no setup, all exit 0, and `template --name card` produces a card that passes the general rules.
The deadline is held by the machinery: a sleeping harness was killed at 12.01 s and left no process.
`slots` prints a typed line for every change and refuses a full share with its holders and a runnable remedy; `slots run` passes the command's exit code through.
`--child-rules` names a missing rule with its exact sentence and where to get it.
`doctor` catches a shadowing binary and names both stamps.
Unknown verbs and flags refuse with the full list and a `run:` line.
