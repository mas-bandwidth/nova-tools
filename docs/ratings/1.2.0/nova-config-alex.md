# nova-config READ and USE rating, nova-tools 1.2.0

Rater: GLM (glm-5.3-flash, flash tier) in opencode, a sprint worker on a friend's re-rate card
Build: 96b7601e9689deac174c1b166e8113b9ce8c55c4
READ: 8/10
USE: 8.5/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-config version` prints `nova-config v1.0.1-0.20261007015736-96b7601e9689 linux/amd64 go1.26.6`. Built and run on a Linux machine in a scratch directory, with no database: every verb of every kind against the `--file` JSON store (migrate, twice, and its `--dry-run` ledger; add, set, list, show, history for machine, friend, sprint, loop, route, tier, fleet; `machine self`, `machine width`; `--json` and `--dry-run` variants), `inventory --fixture` and `--host`, `status` on a fresh and a populated file, and the refusals provoked one by one (duplicate name, bad value, unknown verb and flag, the sprint bar rules, the loop argv and seat rules, the disabled route's note rule, the tier remove refusal). `login`/`logout` were tried against a scratch `XDG_CONFIG_HOME` and a store without a `.sops.yaml`: the secret did not resolve, nothing was recorded, and the refusal named why. `apply --check` and `apply --dry-run` were refused for the missing `--redis`; no Redis was started and no store was dialled beyond an address on port 1.

## Reasons

READ. The banner answers all three questions: line 1 says what it does (the same sentence as README.md's table), `how it works:` names the kinds, the schema, the history and the Redis copy in five lines, and the `example:` block is a five-line first run on `--file try.json` that runs as printed (I pasted it; every line exited 0). Every verb answers `-h` and `help <verb>` with its usage, an `effect:` line (inspection, store write, local write, external delivery), required flags marked, and a worked example on the same file. The kinds section of `help` names each kind's fields and which `add` requires, and `kinds` prints the same as lines. The exit table is stated once and repeated on every verb's `-h`. The refusals are in one grammar, and the store-selection rules (dsn, password-by-variable-name, `--file`, seat, login) are all stated before the first example.

What keeps READ at 8. The banner is dense past five lines: the store-selection paragraph runs nine lines and holds four sources with their environments in one breath, so a cold reader parses it twice. Every verb's `-h` repeats the full six-line exit table and a four-line `--pg`/`--file` description, so `sprint set -h` is over a hundred lines for eleven flags. Whether a verb's `-h` carries the `from `nova-config help`:` context block depends on whether the banner's example block happens to name it: machine verbs do, and `friend add`, `route add`, `tier set`, `sprint set`, `fleet set` and `loop add` open at `effect:` with no pointer to the banner. The note a row records for people prints with every blank escaped (`held\x201:46\x20PM:...`), readable only after decoding; `--json` shows it plain. The docs trail the binary in four places a reader checks first: the guide says friend `--tiers` is "flash, frontier, pro" (heavy missing) and "the tier is `flash` or `pro`", the spec's schema block still says routes `tier flash|pro` and tiers `name PK flash|pro` while the same spec declares heavy two pages earlier, and it still lists `width` in `config.loops`, which migration 0017 dropped. `--json` on a refused verb prints nothing on stdout and plain text on stderr, so the one output structure has one rendering only where it works.

USE. The first run is clean: migrate makes 35 migrations on a file in under a second, runs again as `applied=0`, and its `--dry-run` prints the whole ledger with `ready=yes`. Every kind verb behaved as its `-h` says: `add` refuses a duplicate with `run: nova-config machine set m1 --<field> <value> --file try.json`; missing required flags are named all at once, each with what it wants; `--slots abc`, `--width 0`, `--token_cap -1`, a bad tier, an upper-case name, a provider with a slash and a blank model each get their own line naming the want. The domain rules bite exactly as documented: a loop with `--keys` and no `--seat` is refused, so is `--every 60 --keepalive true`, and an argv spelling `--width` is refused naming the rule; `route set --enabled false` without `--note` is refused before anything is written; `tier remove` is refused with the reason; the fleet's and the sprint's named rows protect their machines and friends from removal; `--pg` and `--file` together are refused. `status` on a fresh file ends `run: nova-config migrate --file fresh.json`, a paste. `inventory --fixture` printed a whole Ansible inventory offline, and an unknown `--host` named the known machines. `--json` and the lines carry the same values, and `friend show --json` shows the note whole. `login` recorded nothing when the secret did not resolve, saying what was missing and the two remedies.

What keeps USE at 8.5. A refused verb under `--json` leaves stdout at zero bytes (the 1.1.0 finding), so an automated caller cannot read the refusal it just caused. An unreachable `--redis` buries the refusal under four go-redis connection-pool log lines (it failed after 5 dials, about a second and a half), the noise `internal/redisconn` exists to keep off the tool's one line. `apply --dry-run` still skips the missing-`--as` check the real apply makes (the 1.1.0 finding; cmd/nova-config/apply.go:48). A bad field value on sprint refuses at exit 1 while the same class of error on machine, friend and route refuses at exit 2. `inventory --host nope --fixture <file>` ends `run: nova-config machine list`, which repeats no input and opens nothing from a fixture run. `migrate --file sub/dir/t.json` leaks the raw os error for a hidden temp file instead of saying the directory does not exist. `status` prints `redis=-` and no NOTE naming how to give one (the 1.1.0 finding).

## Good, keep

The `--file` store: every verb, the same refusals, history and revisions, with no database, and the banner says so before the first example. Refusal discipline: every missing required flag in one run, each naming what it wants; remedies that repeat the `--file` or `--pg` the run was given, so a refusal pastes. The domain rules enforced at the boundary: a loop runs every n seconds or is kept alive, its `--keys` need a `--seat`, a member's width is its machine's; a disabled route carries its measured reason; the tier rows migrate made are never removed; the fleet's and the sprint's named rows protect their machines and friends. `machine self` opens no store without `--check`. `migrate` is idempotent with a `--dry-run` ledger that says pending and missing apart. `inventory --fixture` answers offline with a whole Ansible inventory. `login` writes nothing until the secret resolves, and never the password.
