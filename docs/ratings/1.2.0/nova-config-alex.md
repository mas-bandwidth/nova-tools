# nova-config READ and USE rating, nova-tools 1.2.0

Rater: deepseek/deepseek-v4.1-flash under dsh, a cold reader on a friend's re-rate card
Build: bc9ee29ed2b0
READ: 7/10
USE: 6/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of `sprint/mechanical-2026-10-02`, build `bc9ee29ed2b0`. `nova-config version` prints `nova-config v1.0.1-0.20261007214711-bc9ee29ed2b0 linux/amd64 go1.26.6`. Built and run on a Linux bench, in a throwaway directory under the job directory, on a `--file` store and the `--example` inventory fixture; no PostgreSQL, no Redis and no server was started. `nova-config help`, every verb's `-h`, `docs/SPEC-CONFIG.md`, the nova-config section of `docs/CLI.md` and `docs/ratings/README.md` were read cold, then migrate (twice), the kind verbs (add, set, list, show, history, width, self), `kinds`, route add and the provider-prefix refusal, `tier set`, `tier list` and the `tier add` dead end, loop add and the seat collision, `inventory --example`/`--fixture`/`--host` and its refusals, `status` against a dead Redis address, and the refusals provoked one by one.

## Reasons

READ. `nova-config help` answers the three questions: one line saying what the tool is, a `how it works:` paragraph naming the two stores and the kinds, and an `example:` block that runs on a `--file` store. `docs/SPEC-CONFIG.md` is in sections (boundary, kinds, schema, history, apply, lines, connecting) and every verb answers `-h` with its effect, its required flags, a worked example and the exit table. The grammar is generated from the descriptors, so the same six verbs hold for every kind and `kinds` prints each field and the required ones from the same source. The refusals are the best part of the READ: one line, the reason, and a runnable next command that repeats the same `--file`. The kinds are described in the place a caller reads: `nova-config <kind> add -h` names each field's type, default and what reads it.

What holds READ at 7. The help and the docs disagree in several places a cold reader meets early. The one summary field table at `docs/SPEC-CONFIG.md:49` is stale beside the descriptors: the fleet row omits `bus` and `loops_dir`, the loop row still lists `width` that migration 0017 removed, and the route row omits `usd` and `first`. The schema sketch repeats the drift at `docs/SPEC-CONFIG.md:522` (`config.routes ... tier flash|pro`, omitting heavy) and `docs/SPEC-CONFIG.md:532` (`config.tiers ... name PK flash|pro ...; the two rows`), while the descriptor and `migrate` make three rows, `flash`, `pro` and `heavy`. `docs/CLI.md:2540` prints `tier set flash|pro`, omitting heavy, and the kinds paragraph at `docs/CLI.md:2544` repeats the removed loop `width` and omits the route's `usd` and `first`. `README.md:30` still ends "This is the Nova fleet configuration model.", naming the page instead of the tool. The friend kind's doc and every field help say "her" and "she" for every friend (`pkg/config/kind.go:432`, `:434`), a pronoun the tool cannot know, and `sprint set -h` carries calibration history ("at 0.8 24 of the calibration's 39 flaky failures would have been reported pre-existing", `pkg/config/kind.go:465`) in the help a caller reads to set one bar. `help route`, `help tier` and `help friend` print usage, effect and the exit table but no verb line and no example, where `help machine` prints six example lines. `nova-config frobnicate` answers with a `want` list that omits `help` and `version` (`cmd/nova-config/main.go:391`). The banner's first-run sentence breaks around the `export NOVA_PG_DSN=...` shell line and reads as a run-on (`cmd/nova-config/main.go:72`).

USE. The `--file` store does the job the help promises, with no database: `migrate --file f.json` printed `from=0 to=35 applied=35` and a second run `applied=0`; machine add, set, list, show, history and width, the fleet row, friends, the sprint row, loops, routes and tiers all wrote, read back and kept history with actor and before/after; `--dry-run` printed `CONFIG DRY-RUN` and wrote nothing; `kinds` printed the seven kinds and their fields. `inventory --example > inv.yml` then `inventory --fixture inv.yml --list` printed the full Ansible inventory with `all`, `benches`, `coordinator`, `store`, `store_deployer`, `runners` and `tla`, and `--host m1` printed the same variables as one object. The refusals are strong: a missing required set names every one with what it wants; a duplicate names the set to run; `route add` refuses a headless harness on the wrong provider word with the reason; a disabled route with no note is refused with `say why`; and a `--json` refusal is now the same result object on stdout with stderr quiet.

What holds USE at 6. Two generated writes are dead ends. `nova-config tier add -h` exits 0 and advertises "store write: one row and its history row", but every name is refused: the three rows are made by `migrate`, `add` is gated for a singleton kind only (`cmd/nova-config/kindverbs.go:55`), and `tier add frontier` answers `want one of flash, pro, heavy`. A machine's or loop's `seat` is a record field, but on `set` and `remove` `--seat` is the seat-profile store flag (`cmd/nova-config/kindverbs.go:134` skips the field on set), so `machine set m1 --seat s9 --file f.json` exits 2 with `--seat and --file are exclusive` and the seat a row was added with can never be changed. `route add hh --tier heavy --harness opencode --provider p --model m --deadline 60` exits 0, although `docs/SPEC-CONFIG.md:308` says a heavy route names a headless harness and the harness help calls the headless ones the heavy tier: `checkRoute` checks the `subscription-<harness>` prefix only once the harness is already headless (`pkg/config/kind.go:625`). The smaller gaps: `machine list` prints `width=-` for a machine with no width where `machine width` and the add NOTE say `width=default`; every `<kind> list|show --json` prints every field as a string (`"slots":"4"`, `"usd":"0.5"`) while `machine width --json` gives numbers; the rows `migrate` seeds carry `created=2023-11-14T22:13:20Z`, the in-memory store's fixed test clock (`pkg/config/store.go:271`), because the seed rows are stamped before the file store installs its wall clock (`pkg/config/file.go:49`); `status --redis 127.0.0.1:1` prints four `redis: ... pool.go:762: ... failed to dial after 5 attempts` library lines before the one REFUSED line; `machine add m9 --slots no --bogus 1` names only `unknown flag --bogus`, though `--slots no` alone is named, so the two checks are not collected; a fixture missing the fleet endpoints is refused with `nova-config fleet set ... then nova-config apply --kind fleet` (`pkg/config/inventory.go:208`), a store write the fixture never reads; and the wrong-shape message's wanted mapping names the fleet as `(store, coordinator)` while omitting the required `redis_port` and `pg_dsn` that `--example` prints (`pkg/config/inventory.go:431`).

## Good, keep

- The `--file` store runs every verb but `apply`'s write and `inventory` with no database, and the banner's first-run example runs as printed.
- The refusal grammar on a store write: one line, every independent problem named (missing flags, two bad values, a bad ref and a missing mode together), the reason, and a runnable next command that repeats the same `--file`.
- The kinds as descriptors: `kinds` prints each field and the required ones from the same source that generates the verbs, so the verbs cannot drift apart.
- The password discipline: a `--pg_dsn` carrying a password is refused without echoing it, and a seat profile is refused with the path it wanted.
- `inventory --example` is a store-free fixture generator, and `--fixture`/`--host`/`--list` print the full Ansible inventory with the groups and `_meta.hostvars`.
- The `--json` refusal is now the same result object on stdout (`status`, `exit`, `remedy`, `why`) with stderr quiet, which the 1.1.0 pair asked for.
