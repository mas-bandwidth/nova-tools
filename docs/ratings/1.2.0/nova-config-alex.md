# nova-config READ and USE rating, nova-tools 1.2.0

Rater: Alex, running nvidia/nemotron-3.5-lightning under dsh (the DeepSeek Harness headless runner)
Build: 7acb90e18a76
READ: 6/10
USE: 5/10

## Reasons

READ. `nova-config help` answers the three questions: one line saying what the tool is, a `how it works:` paragraph naming the two stores and the kinds, and an `example:` block that runs on a `--file` store. `docs/SPEC-CONFIG.md` is in sections (boundary, kinds, schema, history, apply, lines, connecting) and every verb answers `-h` with its effect, its required flags, a worked example and the exit table. The grammar is generated from the descriptors, so the same six verbs hold for every kind and `kinds` prints the fields and the required ones from the same source. However: the field table at `docs/SPEC-CONFIG.md:49` has drifted from the descriptors (fleet row omits `bus`, loop row still carries `width` that migration 0017 removed, route row omits `usd` and `first`); the schema sketch at `docs/SPEC-CONFIG.md:453` writes `config.tiers ... name PK flash|pro` and "the two rows inserted", while the descriptor and `migrate` make three rows `flash`, `pro` and `heavy`; `docs/CLI.md:2107` repeats the removed loop `width` and omits the route's `usd`, `first` and price sheet, and `docs/CLI.md:2103` says `tier set flash|pro` omitting `heavy`; `nova-config friend add -h` and the friend doc call every friend "she" and "her" (`internal/config/kind.go:405`, `internal/config/kind.go:407`, `internal/config/kind.go:411`), a pronoun the tool cannot know; `nova-config sprint set -h` carries calibration history ("24 of the calibration's 39 flaky failures would have been reported pre-existing") in the help a caller reads to set one bar (`internal/config/kind.go:436`); `nova-config route add heavy-x --tier heavy --provider p --model m --deadline 60` can be dealt with a non-headless `--harness`, but the spec and help say a heavy route names a headless harness; `help machine` prints two usage lines and four examples, not the six verbs; `help loop`, `help route` and `help tier` print no verb lines at all; `nova-config help machine` prints two usage lines and four examples rather than the six verbs; unknown-verb refusal's `want` list omits `help` and `version`; `tier add -h` exits 0 and advertises a store write but every name is refused, so the verb is a dead end its help does not mark; the banner's `first run:` sentence breaks around a shell line and reads as one run-on; `docs/CLI.md:2103` says `tier set flash|pro` omitting `heavy`; `README.md:30` still ends "This is the Nova fleet configuration model.", naming the page instead of the tool; `machine list --seat s1` gives `unknown flag --seat`; `machine list` shows `width=-` where the add NOTE says `width=default`; `fleet show` and `sprint show` after `migrate` show `created=2023-11-14T22:13:20Z`, an in-memory store's fixed test clock; `friend list --json` gives numbers as strings (`"slots":"4"`, `"width":"8"`) while `machine width --json` gives numbers; `apply --redis 127.0.0.1:1 --dry-run` prints four `redis: ... pool.go:762: ... failed to dial after 5 attempts` lines before the one REFUSED line; `machine add m9 --slots no --bogus 1` names only `unknown flag --bogus` alone, `--slots no` is not collected; `inventory --fixture` example paths name a directory inside a source checkout, so from any other directory the verb refuses `stat ...: no such file or directory`; `inventory --bad.yml` refuses with the Go struct type in the message and its wanted mapping omits the required fleet `redis_port` and `pg_dsn`; `inventory --fixture` without `redis_port` and `pg_dsn` names `nova-config fleet set ... then nova-config apply --kind fleet`, a store write the fixture never reads; `tier add` can never succeed - the generated `add` verb is dispatched and its `-h` advertises a store write but every name is refused; `machine add m1 ... --json` on a duplicate exits 1, stdout empty, stderr `machine m1 exists REFUSED: ...`; `--seat` on `machine set` and `loop set` means two different things (seat field vs seat-profile connection flag), so the seat a row was added with can never be changed.

What keeps READ at 6. The one summary table at `docs/SPEC-CONFIG.md:49` has drifted from the descriptors but the descriptors themselves are authoritative: `kinds` prints each field and the required ones from the same source that generates the verbs, so the six verbs cannot drift apart. The refusal grammar on a store write: one line, every independent problem named (missing flags, two bad values, a bad ref and a missing mode together), the reason, and a runnable next command that repeats the same `--file`. The kinds as descriptors: `kinds` prints each field and the required ones from the same source that generates the verbs, so the six verbs cannot drift apart. The password discipline: `--pg_dsn` with a password is refused without echoing it, and a seat profile is refused with the path it wanted. The fixture inventory: a valid fixture prints the full Ansible inventory with `all`, `benches`, `coordinator`, `store`, `store_deployer`, `runners`, `tla` and every host's variables, and `--host` and the unknown-host refusal are exact. `machine width --json` is the family envelope with `"default":true` for a machine that has no width. `README.md:30` now states the prerequisites and a store-free first command in the row itself.

USE. The `--file` store does the job the help promises, with no database: `migrate --file try.json` printed `from=0 to=35 applied=35` and a second run `applied=0`; machine add, set, list, show, history and width, the fleet row, friends, the sprint row, loops and routes all wrote, read back and kept history with actor and before/after; `--dry-run` printed `CONFIG DRY-RUN` and wrote nothing; success `--json` is one envelope, and `machine width --json` is now that envelope. The refusals are the best part: a missing set of required flags names every one with what it wants, two bad values alone are both named, a duplicate names the set to run, `fleet set --store m9` names no row with the next command, a `--pg_dsn` carrying a password is refused without echoing it, a disabled route with no note is refused with `say why`, a loop with both `--every` and `--keepalive` names the rule, and a `nova-swarm member` argv spelling `--width` names the machine field. `inventory --fixture` printed the whole Ansible inventory, groups and `_meta.hostvars`, and `--host` and the unknown-host refusal are exact. `machine width --json` is the family envelope with `"default":true` for a machine that has no width.

What keeps USE at 5. A machine's `seat` and a loop's `seat` are record fields, but on `set` and `remove` `--seat` is the seat-profile connection flag, so the seat a row was added with can never be changed: `machine set m1 --seat s9 --as a1 --file try.json` exits 2 with `--seat and --file are exclusive` even though the refusal's own field list names `seat`, and `loop set reader-m1 --seat s9 --as a1 --file` does the same. The same `--seat` means the field on `add` and the profile on `set`, so the flag is ambiguous across two verbs of one kind. `nova-config tier add` can never succeed yet is dispatched and documented. The carried error-path gaps are all still there: under `--json` a refusal leaves stdout empty and prints the plain REFUSED line on stderr; an unknown flag hides the bad values beside it; a dead Redis prints four `redis: ... pool.go:762: ... failed to dial after 5 attempts` library lines before the one REFUSED line, on `apply`, `status` and `machine list --redis`; the first-run fixture path and every `inventory -h` example name a path inside a source checkout, so from any other directory the verb refuses `stat ...: no such file or directory`; a fixture of the wrong shape dumps the Go struct type in the message and its wanted mapping omits the required fleet `redis_port` and `pg_dsn`; and a fixture missing those two endpoints names `nova-config fleet set ... then nova-config apply --kind fleet` as the next step, a store write the fixture never reads. Smaller: `list --json` gives numbers as strings (`"slots":"4"`, `"width":"8"`) while `machine width --json` gives numbers; a machine added with no width prints `width=-` in `list` and `show` where `machine width` and the add NOTE say `width=default`; the rows `migrate` seeds (the fleet and sprint rows) carry `created=2023-11-14T22:13:20Z`; `README.md:30` still names itself; and the banner offers `--seat` as a store without saying reads do not take it, so `machine list --seat s1` is `unknown flag --seat`. `nova-config tier add` can never succeed yet is dispatched and documented.

## Good, keep

- The `--file` store runs every verb but `apply`'s write and `inventory` with no database, and the banner's first-run example runs as printed.
- The refusal grammar on a store write: one line, every independent problem named (missing flags, two bad values, a bad ref and a missing mode together), the reason, and a runnable next command that repeats the same `--file`.
- The kinds as descriptors: `kinds` prints each field and the required ones from the same source that generates the verbs, so the six verbs cannot drift apart.
- The password discipline: `--pg_dsn` with a password is refused without echoing it, and a seat profile is refused with the path it wanted.
- The fixture inventory: a valid fixture prints the full Ansible inventory with `all`, `benches`, `coordinator`, `store`, `store_deployer`, `runners`, `tla` and every host's variables, and `--host` and the unknown-host refusal are exact.
- `machine width --json` is the family envelope with `"default":true` for a machine that has no width.
- The six generated verbs with one grammar, and a new kind is one descriptor and one migration.
