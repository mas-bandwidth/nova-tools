# nova-tokens READ and USE rating, nova-tools 1.2.0

Rater: qwen3.8-flash in opencode, a worker dealt a friend's re-rate card
Build: c76fcb249cc1
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge and the CHANGELOG's newest entry is v1.1.0, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. A binary built from it with `go build` says `nova-tokens v1.0.1-0.20261007015429-c76fcb249cc1 darwin/amd64 go1.26.6`. The help was read cold first (`nova-tokens help`, nine verbs' `-h`, `help <verb>` and `--help` too), then docs/SPEC-TOKENS.md, then the tool was used on a darwin bench in a scratch directory made for the trial: no live store, no server. Every verb ran: fold over a transcript, a fake bus lane, a swarm pool, a grok usage JSON export and a hand-built OpenCode sqlite database; check, sum, sources; report local (plain, `--json`, `--dry-run`, `--note`, a symlinked note); session with and without `--out`, with `--role`, `--weights` and a model-less transcript; ledger `--dry-run`, and ledger and report --redis against a closed port to watch them fail. The Redis happy path was not run, because it needs a store.

## Reasons

READ. The banner's first line is the tool's one sentence and the README's row. What it does, how it works and how to use it are all answered, and the rules an AI needs to trust a number are said in plain words: a dash is not a zero, exit 1 still writes, a day that would shrink is refused, two sources of one provider sharing message ids are refused, the bus lane orders its notes only by `supersedes=`. Every verb's `-h` carries its usage excerpt, an `effect:` line naming what it writes, its flags and the exit table; `help <verb>` and `--help` answer the same and exit 0. The spec is normative, numbered 1 to 21, and ends with the tests each rule demands — reading it told me what every refusal should say before I saw one.

What keeps READ at 7. The banner is 161 lines and its own first run is buried in it: `first run:` (cmd/nova-tokens/main.go:50) points at a `setup:` block at main.go:170, a hundred and twenty lines down. Three sentences in it are not true. "the one flag with a default" (main.go:105) is contradicted in the same tree by `--weights`, which defaults to `1,1.25,0.1,5` (docs/SPEC-TOKENS.md:424), and by session's `--day`, which defaults to every stamped day (cmd/nova-tokens/session.go:56). The bare-verb refusal says "sources is the one that only looks" (main.go:249) when sum, check and profiles also write nothing — and sources itself copies a database under `--scratch`. The report mode line (main.go:64) says one routing rule three ways in one sentence: "giving both --who and --redis selects the store mode (--redis wins); a mix of --who and --redis prints the store summary". The docs drift from the binary: docs/CLI.md:1829 says the help holds "one setup command" (its `setup:` block is ten lines) and "two exceptions" for the environment (the banner, main.go:101, says three); docs/USAGE.md:186 says "there are no defaults and no environment variables are consulted"; README.md:55 still calls these "the Nova Tools 1.0.0 commands" and installs `@v1.0.0`; docs/CLI.md:1825 is one 2,631-character paragraph. The spec's own sources usage (docs/SPEC-TOKENS.md:413) still writes `--provider <label>=<file>` while the binary refuses anything but `<kind>:<label>=<file>`. Every verb's `-h` repeats the whole seven-line global exit table, `version -h` included, whose verb fails none of those ways; `report -h` lists `--bus` and `--swarm` that the usage line never names; `session -h` does not say that `--role` lands in the repo cell too (only docs/SPEC-TOKENS.md:489 says it); `--timeout <int>` shows no default.

USE. The setup block and all six example lines ran exactly as printed and each ended in a typed OK line with its exit 0. All five source kinds worked from the documentation alone, including a hand-built OpenCode database read through the system `sqlite3` and a grok usage JSON folded with its cost ticks into `usd=0.00025` and `unpriced=`. The safety rules held under every probe I could stage: two `--claude` sources sharing a message id were refused before anything was written; a source that went unreadable left the day file byte-identical with four named `TOKENS SHRANK` lines and exit 1, and `--allow-shrink` then wrote a real smaller value with `written=true`; swapping the declared label over a written row gave `TOKENS PARTIAL` and exit 1; a lane-day with two notes gave `TOKENS CONFLICT` naming every tip, and one replacement note whose `supersedes=` set named both tips cleared it to exit 0; a row fed two day bases gave `TOKENS MIXED`, wrote nothing, and said so; `HOME`, `XDG_DATA_HOME` and `TMPDIR` set to junk changed nothing. Refusals name every independent problem in one run and say what each flag wants. `check` gates honestly: an empty `--out` is `CHECK FAILED`, gaps and notes ride on the OK line, `--strict` names them, `--through` catches a stale ledger, `--max` cuts with a `CHECK MORE` line carrying a pasteable remedy, and `--no-spend` plus `--strict` is refused as two answers to one question. Since the 1.1.0 rating the word and the exit agree: an unreadable declared source now ends `REPORT FAILED` with exit 1 and `--json` carries `"status":"failed"`, and the subject travels quoted.

What keeps USE at 7. The banner's own example still double-counts. Fold the fixture transcript, then run the help's second example, `session --claude-session ./session.jsonl --out ./out`: message `example-1` lands a second time as a `claude-session` row on `unattributed`, `check` says `CHECK OK`, and `sum` prints `input=1624` for a day that spent 812 — against main.go:131's promise that "check and sum never see a doubled day", because the shared-id refusal covers two `--claude` flags but not fold-then-session. An AI that does what the help says, then gates with the tool's own gate, trusts a doubled month. `--allow-shrink` can lie the same way: when the declared source is gone entirely, the day would hold no rows, fold prints four `written=false` lines, exits 0 with `TOKENS OK`, and the NOTE (cmd/nova-tokens/main.go:625) claims "a day was written smaller at your word" while the file still holds the old larger totals — fold never writes an empty day and never removes a file, so the only honest exit here is a named failure, not an OK. `--json` gives one fact two types: `sum`'s items print `"input":"812"` and `"turns":"1"` beside `"days":1`, fold's source item `"files":"1"` (cmd/nova-tokens/sum.go:74, `Counts.Cell`), while session and ledger print numbers — a typed reader cannot write one schema. An assistant message whose json names no `modelID` folds a row with an empty model cell (internal/tokens/opencode.go:59) and `check` passes it, while session refuses a transcript naming no model, "never booked under a guess" — the fold path books the blank. A refusal after a missing flag still ends `run: nova-tokens help` (the 161-line page) while the unknown-flag refusal and session's no-model refusal correctly end `run: nova-tokens <verb> -h`. The overlap refusal's remedy, `run: nova-tokens fold ... without --claude b` (cmd/nova-tokens/fold.go:384), cannot be pasted. session's `TOKENS DAY` says `day=` (session.go:192) where fold's says `date=`. And a `report --note` pointed at a symlink prints the whole body to stdout first, then refuses with exit 2: the artifact leaves the tool before the refusal does.

A ten needs: the overlap rule carried across fold and session so the help's own example cannot double a day; a shrink that cannot write a truth to print a false OK; one JSON type per fact; every refusal pointing at the verb's `-h`; a banner whose first run sits above its rules; docs that say what the binary does.

## Good, keep

The word and the exit now agree everywhere I could reach: an unreadable source ends `REPORT FAILED` exit 1 with `"status":"failed"` in the JSON, and the subject travels quoted (`subject="tokens ... at=... build=..."`), which fixes the worst of the 1.1.0 machine-interface complaints about report. The bus conflict rule is a model of a refusal: `TOKENS CONFLICT` names the lane, the day and every tip id, the remedy carries those ids sorted, and one replacement snapshot naming all tips turns exit 1 into exit 0 with two `SUPERSEDED` lines. `check` is a real gate in both directions — red on an empty `--out`, green that counts gaps and notes on the OK line instead of hiding them, `--strict`, `--no-spend`, `--through` each doing exactly the one job, and the two answers to one question refused. Every `MORE` line prints the full command that shows the rest. `fold --dry-run` carries `dry_run=true` and `would_write` on stdout, from the same reads and the same refusals. `report --json` keeps the note body as a `payload` beside the facts, so one call answers both readers. The dash-not-zero rule held in every source I built: `reasoning=-` for a Claude transcript, `dashes=`, `unpriced=`, `nousage=1`, `unknown=` and `other=` shares printed. `ledger --dry-run` dialed nothing and told the truth against a closed port when not dry. Refusals name every independent problem in one pass and say what each flag wants — the `participants.json` refusal even wrote its shape out when mine was wrong.
