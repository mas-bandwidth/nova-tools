# nova-tokens READ and USE rating, nova-tools 1.2.0

Rater: deepseek-v4 in dsh (the DeepSeek Harness headless runner), a sprint worker on a friend's re-rate card
Build: 9c9b2ebc49fd
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet (the newest is v1.0.0), so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-tokens version` prints `nova-tokens v1.0.1-0.20261007202756-9c9b2ebc49fd linux/amd64 go1.26.6`. The help was read cold first (`nova-tokens help` and every verb's `-h`), then the spec, then the tool was used for real on a Linux bench machine in a scratch directory made for the trial: no live store, no server started on the working machine. The banner's setup and all six example lines ran as printed, then every verb: fold, report (local mode, with and without `--note`, `--dry-run` and `--json`), sum (with `--max`), check (empty, a stray, `--strict`, `--through`), sources (with `--unattributed`), session (with and without `--out`, and with `--role`), profiles (an empty root), ledger `--dry-run`, and ledger against a closed port. The store summary mode of report was not run, because it needs a store.

## Reasons

READ. The banner answers what the tool is in its first line, then how it works, a usage block for all nine verbs, the exit table, the environment rule, the dash rule, the shrink rule, the overlap rule, a setup block and six example lines. Every rule an AI needs to trust a number is in plain words: a dash is not a zero, exit 1 still writes, a day that would shrink is refused, two declared sources of one provider that share message ids are refused before any file is written. Every verb answers `-h` with its usage excerpt, an `effect:` line that says what it writes, and its flags. That is the right shape.

What keeps READ at 7. The banner is about 160 lines (cmd/nova-tokens/main.go:43 to main.go:205) and the reader must finish it before the first command, because the `first run:` line sits at main.go:50 but the `setup:` and `example:` lines it points at sit at main.go:171 and main.go:183. Several sentences are not true. `--timeout is the one flag with a default` (main.go:105) while `--weights` defaults (session.go:59), session's `--day` defaults to every stamped day (session.go:57) and `fold -h` itself prints `--max-files ... (default 20000)`. The report mode line (main.go:64) says one rule three ways in one sentence: "giving both --who and --redis selects the store mode (--redis wins); a mix of --who and --redis prints the store summary". The bare-verb refusal says "sources is the one that only looks" (main.go:250) when sum, check and profiles also write nothing, and docs/CLI.md:1941 repeats it. Every `-h` ends with the whole seven-line exit paragraph (main.go:85), including `version -h`, whose verb can fail for none of those ways. `report -h` lists `--bus` and `--swarm`, which the report usage lines (main.go:57 to main.go:60) do not name. `session -h` says `--role` books the row as `<model>/<role>` but not that the role also replaces the repo cell, which a run with `--role w` showed. `--timeout <int>` in `-h` does not show its 120-second default. The docs drift from the binary: docs/CLI.md:1928 says the help has "one setup command" (it is ten lines) and "two exceptions" where the banner names three things; docs/USAGE.md:186 still says "there are no defaults and no environment variables are consulted"; README.md:86 still calls the commands 1.0.0 and installs `@v1.0.0` in a 1.2.0 tree. docs/CLI.md:1924 is one 2,631-character paragraph on check.

USE. The setup and all six example lines ran as printed and each exited 0 with a typed line. The safety rules hold when tested. Two declared sources over copies of one transcript were refused before anything was written (`TOKENS REFUSED: two declared sources fed the same 1 message ids (claude:bench and claude:dup)`, exit 2), which fixes the 1.1.0 rating's top finding. Making a declared transcript unreadable left the day file byte-unchanged with four `TOKENS SHRANK` lines and exit 1, and `--dry-run` printed the same plan with `written=false would_write=true`. `check` on an empty `--out` is `CHECK FAILED`, not a green over nothing, and `--strict` and `--through` named the stray and the stale end. `sum --max 1` printed a `SUM MORE` line with the command that shows the rest. A refusal names every missing flag in one run, and a bad `--weights` names what it wants and what it got. The `--json` renderings now carry one number type per fact: `sum --json` prints `"input":812` and `"reasoning":null`, not strings, which fixes the 1.1.0 use rating's first finding. `report` with an unreadable declared source now prints `REPORT FAILED` and exits 1, with `"status":"failed"` in the JSON, which fixes the earlier 1.2.0 finding.

What keeps USE at 7. The banner's own first run double-counts. The setup copies the transcript to `./session.jsonl`, the example folds the transcript, then the second example runs `session --claude-session ./session.jsonl --out ./out`, which adds the same message (id `example-1`) a second time as a `claude-session` row on repo `unattributed`. `check` then says `CHECK OK` and `sum` says `SUM TOTAL input=1624` for a day that spent 812, against the banner's promise at main.go:131 that "check and sum never see a doubled day". The overlap refusal works between two `--claude` flags but not between fold and session, which merge into one day file. `report --dry-run` puts the body on stdout and `dry_run=true` on the REPORT OK line on stderr, so a caller capturing stdout never sees the marker. A missing-flag refusal still points at `run: nova-tokens help` (main.go:250 and the fold and session refusals) while the unknown-flag path names the verb's own `-h`. `sum` over an `--out` with no day file is `SUM OK days=0` exit 0, and `profiles` over an empty root is `PROFILES OK models=0` exit 0, while `check` calls the same emptiness a failure. `version --json` refuses `takes no flags and no arguments, got 1` without naming `--json`. The overlap refusal's remedy is `run: nova-tokens fold ... without --claude dup`, with a literal ellipsis, so it cannot be pasted.

A ten needs: the overlap rule across fold and session so the banner's own example cannot double a day; one status word per exit; every refusal pointing at the verb's own `-h`; a `--dry-run` marker in the payload; a banner whose first run comes before its rules; and docs that say what the binary does.

## Good, keep

The overlap rule now refuses two declared sources that share message ids before any file is written, naming both labels and the count. The shrink rule held under an unreadable transcript: the day file was left byte-unchanged and each type was named with what the file said and what the sources say now. `--dry-run` is the real run's plan, refusals included. `check` cannot go green over an empty directory, and `--strict`, `--through` and `--no-spend` turn gaps and strays into findings only when asked. A dash is never a zero, in the day file, in sum and in report's `usd=`. The `--json` renderings carry one number type per fact now, `reasoning` as `null`. The verbs live in their own files: main.go is 750 lines, down from 1,563, and fold, report, sum, check, sources, session and ledger each have their own.
