# nova-tokens READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card; this is not that friend's own reading
Build: 193a6f8002d0
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-tokens version` prints `nova-tokens v1.0.1-0.20261006150140-193a6f8002d0 linux/amd64 go1.26.6`. Nothing under cmd/nova-tokens, internal/tokens or docs/SPEC-TOKENS.md changed since the build the other 1.2.0 nova-tokens rating in this directory rated (e26adab23ab1); this is a second, separate reading of the same binary. Built and run on a Linux bench machine, in a scratch directory made for the trial; no live store, no server. Ran: the banner's setup and all seven example lines as printed, then fold (one day, `--all`, `--dry-run`, an unreadable transcript, two overlapping sources, a duplicate label, a bad label, a bad provider kind, `--opencode` without `--scratch`, an unreadable swarm pool), check (empty, missing, `--strict`, `--through`, `--strict` with `--no-spend`), sum (`--json`, `--max 1`, empty `--out`), sources (`--unattributed`, a binary file, a bad rules regexp), report (local, `--json`, `--note`, `--note` onto a symlink, `--dry-run`, an unreadable `--swarm`, store mode against a closed port), session (`--role`, `--dry-run`, bad and negative `--weights`, a binary and a TSV as the transcript), ledger (`--dry-run`, and against a closed port), profiles (empty and missing root), version and every verb's `-h`.

## Reasons

READ. The first ten lines say what the tool is (token spend per day, model and repository), how it works (fold reads named logs into one day file per day, the repo comes from a rules file, a count a source never gave is a dash), and how to start. The rules an AI must know before it trusts a number are each stated once in plain words: a dash is not a zero, exit 1 still writes, a day that would shrink is refused, two sources of one provider sharing ids are refused, a fold merges by source, check cannot go green over nothing, the tool removes nothing it was given. Every verb's `-h` carries its usage excerpt, its example, an `effect:` line saying exactly what it writes, and its flags. That is the right shape and most tools in the set do not have it.

What keeps READ at 7. The banner is about 160 lines and the "first run" sentence at cmd/nova-tokens/main.go:50 points at setup and example lines 120 lines below it. Some sentences are not true: `--timeout is the one flag with a default` (main.go:105), while `--weights` has a default and session's `--day` defaults to every stamped day; "check and sum never see a doubled day" (main.go:131), while the banner's own example makes one (see USE); "sources is the one that only looks" (main.go:249), while sum, check and profiles only look too. The report mode sentence (main.go:64) says one rule three ways. Every `-h` starts `usage: nova-tokens <verb> [flags]`, a line that names no flag, and ends with the whole seven-line exit paragraph, `version -h` included. Defaults are not shown (`--timeout`, `--weights`). `report -h` lists `--bus` and `--swarm`, which report's usage line does not name, and nothing in the help says what a swarm pool holds; a pool without `usage/` is only explained by the refusal `open usage: no such file or directory`. The spec heads the provider source `--provider <label>=<file>` (docs/SPEC-TOKENS.md:756) where the flag is `<kind>:<label>=<file>`. The docs drift from the binary: docs/CLI.md:1746 says "one setup command" and "two exceptions", docs/USAGE.md:186 says there are no defaults and no environment variables, README.md:54 still installs `@v1.0.0`, and docs/CLI.md:1742 is one 2,631-character paragraph.

USE. Every setup and example line ran as printed and said what happened in a typed line (`TOKENS OK`, `CHECK OK`, `SUM OK`, `SOURCES OK`, `REPORT OK`, `SESSION`). The safety rules held when I tried to break them: two `--claude` sources over copies of one transcript were refused before anything was written, naming both labels and the remedy; an unreadable transcript left the day file byte-unchanged with four `TOKENS SHRANK` lines, a `TOKENS QUIET` line and exit 1, and `--dry-run` printed the same plan with `dry_run=true`; a duplicate label, a bad label, a bad provider kind, a bad regexp in the rules file, `--strict` beside `--no-spend`, and a binary or TSV given as a session transcript were each refused with the reason and exit 2; `check` on an empty `--out` is `CHECK FAILED`; `report --note` refuses a symlink; `sum --max 1` prints a `SUM MORE` line carrying the command for the rest. A bare `fold` names all four missing flags in one run.

What keeps USE at 7. The banner's own first run doubles a day: it folds the transcript, then runs `session --claude-session ./session.jsonl --out ./out` over a copy of it, and the day file gets a second row for message `example-1` on repo `unattributed`. `check` then says `CHECK OK` and `sum` says `SUM TOTAL input=1624 ... turns=1`, one turn carrying twice its tokens. `sources` over a file it cannot read prints `SOURCES OK ... unreadable=1` at exit 0, then the `SOURCES UNREADABLE` line after the OK, so the preview says green where the fold it previews will say FAILED. `report` with an unreadable `--swarm` pool prints `REPORT OK` and exits 1. `report --note` onto a refused path prints the whole note body on stdout first and then refuses with exit 2, so a caller that captures stdout has a body for a note that was never written. `fold --day` of a day no source touches prints `TOKENS OK days=0` with no line naming the day, and a later `check --through` that day is stale. `ledger --dry-run` prints `LEDGER day=2026-09-11 rows=1`, a count, where its flag text promises "the rows that would be written". `session --weights -1,1,1,1` is accepted and prints a weighted total. `sum` over an `--out` with no day file is `SUM OK days=0` at exit 0 while `check` on the same directory is FAILED. The 1.1.0 machine-interface findings are still there: `--json` numbers as strings (`"input":"812"` beside `"days":1`), the missing-flag remedy is `nova-tokens help` where the unknown-flag remedy is `<verb> -h`, and `version --json` is refused as `got 1` without naming the flag.

## Good, keep

Two declared sources of one provider sharing message ids are refused before any file is written, with both labels, the count and the flag to drop. The shrink rule held under an unreadable transcript: the day file stayed byte-unchanged, each type was named with what the file said and what the sources say now, and a `TOKENS QUIET` line named the source that went silent. `--dry-run` is the real run's plan, refusals and exit code included. `check` cannot go green over an empty directory, and `--strict`, `--no-spend` and `--through` turn gaps into findings only when asked, and `--strict` with `--no-spend` is refused as two answers to one question. A dash is never a zero. Every refusal names every problem in one run, and the `effect:` line on each `-h` says exactly what the verb writes and where.
