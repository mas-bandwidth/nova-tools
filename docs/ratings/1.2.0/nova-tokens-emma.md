# nova-tokens READ and USE rating, nova-tools 1.2.0

Rater: deepseek/deepseek-v4.1-flash under dsh (the DeepSeek Harness headless runner), a cold reader on a one-shot re-rate card
Build: 0389f76634ec
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of `sprint/mechanical-2026-10-02`, `0389f76634ec`. `nova-tokens version` prints `nova-tokens v1.0.1-0.20261007224659-0389f76634ec linux/amd64 go1.26.6`. It was built and used cold on a Linux bench, in throwaway directories made for the trial. The banner's setup and all seven example lines ran as printed; Claude, OpenCode (a minimal database through `sqlite3`), a Google CSV export, a `grok usage` JSON export, a swarm usage file and a bus note each folded a real fixture; `check`, `sum`, `sources`, `report` with and without `--note` and `--dry-run`, `session`, `profiles` and `ledger --dry-run` ran. The two Redis verbs were run only against a closed loopback port, so no live store was dialled and no server was started on any machine. Nothing was removed outside the trial directories.

## Reasons

READ. The banner leads with the README's own sentence for the tool, answers the three questions in order, and ends with a `setup:` block and seven `example:` lines a stranger can paste. Every verb has its own file (`cmd/nova-tokens/` is 67 files; `main.go` is 750 lines), and every verb answers `-h` with its usage excerpt, its example, an `effect:` line saying what it writes, its flags and the exit table. `check`'s paragraph is the best writing here: a gap is counted, a person's `README.md` is a note and not a stray, and both counts stay on the line so neither door can lie. The dash rule, the shrink refusal and the same-provider overlap refusal are all stated where a reader meets them.

What keeps READ at 7. The normative documents disagree with the binary and with each other on the one rule the tool is built around. The banner (`cmd/nova-tokens/main.go:127-131`) says two declared sources of one provider that feed the same message ids are refused before any day file is written; `docs/CLI.md:1942` says a fold that sees that case is "a warning, not a correction: the numbers are still doubled and `check` and `sum` are all green about it"; and `docs/SPEC-TOKENS.md:1055`, repeated at `docs/SPEC-TOKENS.md:443`, says flatly "It does not detect overlap between sources". The binary refuses two `--claude` flags sharing an id with `TOKENS REFUSED: two declared sources fed the same 1 message ids (claude:a and claude:b)` at exit 2 before writing anything, so the spec's "what it deliberately does not do" and the CLI guide's warning both describe behaviour the code removed. The provider flag drifts three ways too: `docs/SPEC-TOKENS.md:756` (and the demand at `:1271`, and the prose at `:374`) writes `--provider <label>=<file>` and `report ... --provider g=<export>`, while the usage lines at `docs/SPEC-TOKENS.md:401` and `:403` and the binary require `--provider <kind>:<label>=<file>` and refuse a bare label. The banner says "`--timeout` is the one flag with a default" (`main.go:105`) while `--weights`, session's `--day` and `--max-files` all default; `docs/CLI.md:1933` says the help names "two exceptions" where the banner names three environment reads, and calls its setup block "one setup command"; `docs/CLI.md:1946` says "`sources` is the one verb that only looks" while `sum`, `check` and `profiles` also write nothing; `docs/USAGE.md:186` still says there are no defaults and no environment variables; `README.md:86` still calls the commands 1.0.0 and installs `@v1.0.0` in a 1.2.0 tree; and `docs/CLI.md:1929` is one 2,631-character paragraph on `check`. The help itself is dense: `main.go:50` says "first run" a hundred and twenty lines before the lines it points at, `report -h` lists `--bus` and `--swarm` that the report usage lines (`main.go:57-60`) omit, `fold -h` prints no default on `--timeout` while it prints `(default 20000)` on `--max-files`, and every verb's `-h` ends with the whole seven-line exit paragraph, including `version -h`, whose verb can fail for none of those ways.

USE. The machine interface is good and mostly honest. Every verb but `version` takes `--json`, and the JSON is one envelope with one type per fact: `sum --json` prints `"input":812` and `"reasoning":null` beside `"days":1`, so the 1.1.0 string-typed-numbers finding is fixed. `--dry-run` is the real run's own plan, refusals included (`TOKENS DAY ... written=false would_write=true`, `TOKENS OK ... dry_run=true`), and a dry fold writes no file and takes no lock. A missing input names every problem at once and what it wants; an unknown flag names the verb's own flags and `-h`; a missing file, a malformed export, a wrong swarm header and a no-id transcript each get a named line and the right exit. The same-provider overlap refusal fires before any write. The banner's setup and all example lines ran as printed and exited 0. `check` cannot go green over an empty `--out`, counts the lock file as neither a day file nor a stray, and `--strict`/`--through`/`--no-spend` are distinct doors. `sum --max` prints a `SUM MORE` line with the command that widens it; `report --note` writes exactly the note body rows; `ledger --dry-run` over an empty month is `LEDGER FAILED` exit 1; `report --redis` against a closed port is `REPORT FAILED ... connection refused` exit 1. The OpenCode, Google, xai, swarm and bus readers all folded a real fixture, and `profiles` printed a median and an overshoot from a real card.

What keeps USE at 7. The banner's own first run is wrong. The setup copies the transcript to `./session.jsonl`, the first example folds it into `./out`, and the `session` example adds the same message id `example-1` a second time as a `claude-session` row on `unattributed`, so `check` says `CHECK OK` and `sum` prints `input=1624` for a day that spent 812, against `main.go:131`'s promise that check and sum never see a doubled day. The overlap rule covers two `--claude` flags but not `session --out` against a source already in the day file. `sum` over an `--out` with no day file is `SUM OK days=0` exit 0 and `profiles` over an empty root is `PROFILES OK models=0` exit 0, while `check` calls the same emptiness `CHECK FAILED` exit 1. `report --dry-run` puts the body on stdout and `dry_run=true` on stderr, so a caller capturing stdout never sees the marker the help promises. `version --json` refuses with `takes no flags and no arguments, got 1`, never naming `--json`, and sends the reader to the global help. `sources` prints `SOURCES OK ... unreadable=1` at exit 0 while the shared exit table it prints says exit 1 covers an unreadable source. The overlap refusal's remedy, `run: nova-tokens fold ... without --claude b`, carries a literal ellipsis and cannot be pasted. A `--role w` session books the row as `claude-fable-5-1/w` with `w` in the repo cell, which only the spec says. The `TOKENS SHRANK` line names the field `date=` where every `TOKENS DAY` line names it `day=`. A repeated `--month` is silently the last value, so `--month 2026-09 --month 2026-08` answers for 2026-08 with `days=0`, while a repeated source label is refused. Missing-flag and bad-value refusals end `run: nova-tokens help` instead of the verb's own `-h`. A ten needs: the overlap rule to cover `session --out` so the banner's own example cannot double a day; one status word per exit; one field name per fact; every refusal pointing at the verb's `-h`; and docs that say what the binary does.

## Good, keep

The banner's first line is the README's sentence for the tool, word for word.

The same-provider overlap refusal fires before any day file is written, names both labels and the duplicate count, and is the one rule the 1.1.0 rating asked for.

`check` cannot go green over an empty directory, counts a calendar gap without calling it a finding, counts a person's note without calling it a stray, and keeps both counts on the line.

A dash is never a zero, in the day file, in `sum`, and in `report`'s `usd=`; a day that would shrink is left byte-identical and the types that moved are named with both numbers.

`--dry-run` is the real run's plan with the real refusals, and `--json` renders the same one value with the same types as the lines (`sum --json` prints `"input":812` and `"reasoning":null`, not strings).

`report --note` writes exactly the note body rows through an atomic file, and the `REPORT OK` line now quotes `subject=`.

Every source kind folded a real fixture: Claude, OpenCode through a minimal database, Google CSV, `grok usage` JSON with its `costUsdTicks`, a swarm usage file with its sixteen columns, and a bus note. `profiles` printed a median output and an overshoot from a real card.
