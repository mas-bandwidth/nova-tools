# nova-table READ and USE rating, nova-tools 1.2.0

Rater: an AI worker, mercury-2.5 in opencode, on a friend's re-rate card
Build: e49a14260c88
READ: 8/10
USE: 7.5/10

This rates the release candidate at the head of sprint/mechanical-2026-10-02, because no v1.2.0 tag exists on the forge yet. `nova-table version` prints `nova-table v1.0.1-0.20261007015429-e49a14260c88 linux/amd64 go1.26.6`. Built and run on a Linux bench. The root help, `help <verb>`, `help <group> <subverb>` and all 35 verb, subverb and version `-h` pages were read cold. Then the banner's `example:` lines and every verb's `example:` line ran store-less under `--dry-run`, with about sixty further calls: bad values, missing values, missing arguments, unknown verbs, unknown flags, unknown subverbs, and the reads with no store at all. No store was started on this machine, as the card requires, and no live store was touched.

## Reasons

READ. The banner answers what it does, how it works and how to use it before its usage lines, and each `-h` page carries usage, an example, its flags grouped as product, connection and write epoch and receipt, the exit table and an `effect:` line. The help forms work with no store: `help`, `help cell`, `help cell add`, `cell -h` and `--version` all exit 0, and an unknown verb, flag or argument count is refused with the full verb list and a `run:` line. The trust is real: the first-run transcript at docs/CLI.md:2784 is pinned line for line by cmd/nova-table/firstrun_test.go, every refusal carries a copy-paste remedy, one round trip is printed as `trips=`, the epoch and receipt model is stated honestly, and the guide now opens with a design statement (docs/nova-table/README.md:3), not transcribed chat.

What keeps READ at 8. The banner is 127 lines and still puts the column grammar, the fold table, the epoch rules and the shell rules before the `example:` block at cmd/nova-table/main.go:120. The same 385-character `effect:` sentence is printed on every write page (cmd/nova-table/help.go:266), and on the view verbs it names "the table, its epoch, its rows and columns, a bound cell", none of which a view has. Three things a reader wants are missing: `check -h` never says what it checks, the `member find` help never says a member id is shared by every table on the default prefix, and `--score` and `--at-epoch` print as `<string>` where they take a number. A missing flag value can read "it wants inspect a materialised epoch" (cmd/nova-table/table.go:283 with pkg/nsprint/verbflag/verbflag.go:117), because the grammar concatenates "it wants " with a flag help written as an imperative. `nova-table help -h` is refused as the unknown verb "-h", though the onboarding standard says every verb answers `-h` at exit 0. The guide still claims pkg/ntable gives five verbs that pkg/ntable/oset.go no longer has. Dated quotations of the owner remain in the package's comments (pkg/ntable/render.go:26 and seven more; cmd/nova-table/order.go:15), against the tree's own generality rule, and the general renderer still imports the card-cost cents formatter (pkg/ntable/render.go:12, used at :590).

USE. Cold use with no store permitted on this machine: help and `-h` answer, and the store-less form the banner offers, every write verb under `--dry-run`, is real enough to run jobs end to end. The banner's own `--dry-run` example ran first time, and every write verb's example ran under `--dry-run`, printing the exact call it would send (`TABLE DRY-RUN verb=create arg1=demo columns=ready,working,done sends="FCALL ns_table_create" redis=- dialled=0 written=0`). The dry-run path refuses exactly where the real run would before sending: a bad projection, a bad `--score`, a bad `--every`, a missing flag value, a missing argument count, a missing `--columns`. A read or a real write with no store refuses at exit 2 naming the address it tried and printing the whole throwaway-store recipe with the redis-server path filled in. A refusal from a verb that answers `--json` comes back as the one JSON object (member read and batch). Unknown flags list the verb's flags and a `run:` line.

What keeps USE at 7.5. No store could be started here, so every read, `watch` and `shell` was judged from its help and its dry-run plan alone. `--json` reaches only `batch` and `member read` (cmd/nova-table/main.go:230), against docs/STANDARD.md:56 ("Every verb accepts `--json`"), so the reads' output must be parsed as drawn text. A malformed batch manifest is refused at exit 1, not the 2 usage gets, and names only the first missing key. The `cell remove -h` example removes b2 and the `cell move -h` example then moves b2, so the two cannot both run in help order. The `view set --summary` help promises `x/y z% -> ETA`, and the guide says ETA has no value until rate sampling exists, so the frame prints a literal `-> ETA`. `cell add` and `cell remove` share one output line, so a remove of an id that was not in the cell is indistinguishable from a real one. `shell --dry-run` with no store refuses with a short remedy, unlike every other store-requiring verb, which prints the throwaway-store recipe. A 10 needs `--json` on every verb from the value it already builds, one manifest refusal naming every fault, examples that compose, and a refusal grammar that reads as English.

The reading says: a careful tool whose writes can be trusted and whose refusals nearly always point the way, held back from 10 by a banner that asks for patience, a help page or two that hide what a verb does, and reads that still speak only prose.

## Good, keep

The banner's store-less `--dry-run` example runs as printed, and a verb that finds no store prints the whole throwaway-store recipe with the redis-server path filled in. `--dry-run` runs the real run's own call up to its first command: it refuses a bad projection, a bad `--score`, a bad `--every`, a missing value and a missing argument count exactly where the real run would, with `dialled=0 written=0`. Every verb and subverb answers `-h` at exit 0 with usage, an example, its flags, the exit table and an effect, and the examples of the write verbs are real commands. An unknown verb, flag, subverb or argument count is refused with the names there are and a `run:` line. The reads refuse at exit 2 with the address they tried and the recipe that fixes it, and a `--json` verb answers its refusal as the one JSON object. The epoch and receipt model is stated honestly (no claim of retry deduplication), and docs/CLI.md's first-run transcript is executed by the tool's own test.
