# nova-secrets READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 43b487125e85
READ: 7/10
USE: 6.5/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-secrets version` prints `nova-secrets v1.0.1-0.20261006145252-43b487125e85 linux/amd64 go1.26.6`. Built and run on a Linux bench machine with the real `sops` and `age-keygen` on PATH, under a scratch `HOME` made for the trial: a new store, a local bare remote, three keys (recovery, ada, bo), no live store, no network, and a stand-in `ssh` script for `place`. Every verb was run for real, including a real decrypt with the wrong key.

## Reasons

READ. The banner says what the tool is in one line, what a store and a seat are in five, and then gives a `setup:` block that makes a store from an empty directory and a `first value:` line. Every verb answers `-h` and `help <verb>` with its usage excerpt, an example, an `effect:` line (inspection, local write, store write, delivery), flags with `(required)` and defaults, and exec's and check's `-h` spell out the store prerequisite with the three git commands that repair it. The verb list in the unknown-verb refusal is complete, and `rotate` and `edit` are refused by name with where they live.

What keeps READ at 7. The banner's own first run does not finish: `first value:` runs `seal` on the seat `setup:` just made, and seal refuses a seat with no file, by the spec's own rule 12 (docs/SPEC-SECRETS.md:1213); nothing in the help says how the first seat file comes to exist (`seat add` needs a `--from` seat that already has one). The `first value:` line and eight `example:` lines still name `/opt/homebrew/bin/sops` and `/opt/homebrew/bin/age-keygen` (cmd/nova-secrets/main.go:116-128) while `setup:` and every `--sops` flag text say `command -v`. Every verb's `-h` prints the whole tool's exit table, so `version -h` and `names -h` describe exec's 125 and check's red; `place -h` describes `--dry-run` with a sentence about seal and seat inject. `seat -h` prints the full banner instead of the two subverbs. The banner's flag glossary disagrees with the verbs: `--only` is "exec only" (seat add and seat inject take it too), `--require` says "present in the file" where exec also requires it in `--only`. `gate -h` still does not say the registry row shape, and `placed -h` does not say the receipt shape. The spec still opens with "Five verbs" and "about two hundred lines of Go" (docs/SPEC-SECRETS.md:10, :34) over 5,162 non-test lines in internal/secrets and 960 in cmd/nova-secrets, and the package doc still says four verbs (internal/secrets/secret.go:2).

USE. Once a seat file exists the tool is very good to use. `names` lists without a key; `check` proved the store and went red, exit 1, with a remedy, on HEAD ahead of its upstream and on a file in the clear; `exec` handed exactly the `--only` values to the child, passed the child's exit 7 through, refused a missing command, an unknown command, a missing `--only` name and a missing `--require` name at 125 with a next command; a wrong key's real decrypt failure withheld the transcript. `seal --stdin --no-pr` committed on a `seal/` branch, returned the store to `main`, and said in a NOTE that exec will not see the value until the branch is merged. `seat add` re-sealed one value into a new seat whose own key then opened it in exec; `gate` approved the seat pull request; `seat inject` planned and committed; `place` sent the value on ssh's stdin (5 bytes, no argument) and wrote a 0600 receipt that `placed` listed. Every refusal named every missing flag at once and a `run:` line; `--dry-run` printed PLAN lines ending in `DRY-RUN OK` and never a value.

What keeps USE at 6.5. The first run is a dead end: after `setup:`, `first value:` is `SECRETS SEAL REFUSED: ada.yaml does not exist in the store; a new seat is given its first values by seat add, never by seal`, and `seat add` cannot run because no seat exists to re-seal from; the only road is a hand `sops -e` the help never shows. Three refusals send the reader down the wrong road: exec on an absent seat says `seal starts a new seat: run: nova-secrets seal ...` (internal/secrets/seatfile.go:193), the opposite of rule 12; a missing `--require` name or `place --secret` name says `run: sops <file>` (internal/secrets/exec.go:98, internal/secrets/place.go:289), a hand edit around the tool's own `seal`; and `check` on a plaintext yaml prints `run: sops updatekeys clear.yaml` (internal/secrets/invariants.go:145), which cannot work on a file with no sops metadata and no rule. The 1.1.0 carry-overs are still there: `place` reads the gate's seven-field registry row as its own three-field row and plans `path=linux/amd64/.config/nova-secrets/GH_TOKEN.env`; `gate` refuses as `GATE REFUSE rule=0 file=: ...` with no `run:`; only `names` takes `--json`; seal's and seat's progress lines (`seal: reading ada.yaml`) sit outside the grammar, and `seal: returning the store to its branch` prints after the OK line. `placed` over a receipts directory that does not exist is `SECRETS PLACED OK count=0` exit 0, and prints its OK line before its ITEM lines, where names prints it last.

A 10 would make the banner's setup and first value run end to end as printed (a `seat add` or `seal` that can start the first seat file, or a setup line that does), make every refusal's remedy a road the tool itself takes, print one exit table per verb, name tools by `command -v` everywhere, give `place` and `gate` one registry shape or refuse the other, keep gate's refusals and the progress lines in the house grammar, add `--json` to check, exec and gate, and bring the spec's and package doc's counts to the code.

## Good, keep

The value never shows: not in an argument (place's stand-in ssh got the value's 5 bytes on stdin and only the target and a `umask 077 ... cat >` command in argv), not in a dry run (`value=not read (dry run)`), not in a refusal, not in a receipt. exec hands the child exactly the `--only` names and passes its exit status through, and refuses with 125 so a caller can tell exec's refusal from the command's. check and exec read the store's HEAD against its upstream with no network and refuse ahead, behind and detached with the git command that repairs each. seal `--no-pr` leaves the store on its own branch and says exec will not see the value until the merge. seat add puts back `.sops.yaml` and writes nothing on a refused run. Missing-flag refusals name every missing flag at once, and unknown flags list the verb's flags.
