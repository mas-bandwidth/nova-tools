# nova-decide READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: 361d4451bcd8
READ: 7/10
USE: 8/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-decide version` prints `nova-decide v1.0.1-0.20261006144651-361d4451bcd8 linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch directory made for the trial, with the fixed backend only: no live store, no server, and the model backend run only with its key absent from the environment, so nothing left the machine. Every verb was run: the banner's ten examples against a scratch record, each again to see the replay, then `--dry-run`, `--json`, standard input, an empty state, a system binary as schema, state and diff, missing and wrong answers files, an unknown backend, unknown and missing flags, an unknown verb, a directory of cards for `brief` with `--max 1`, a green go test output and both `--bars` refusals for `gate`, `import` of a HOLD report and an ACCEPT verdict twice, a glob that matched nothing, `score-grades` over a log of the wrong shape, and a record with one corrupt line.

## Reasons

READ. The banner names every verb with its full usage line and a runnable example, states the exit table once, and says `exit 0 means recorded, never approved`, which is the one sentence a caller most needs. The per-verb help is the best part of the read: each `-h` quotes its usage and example from the banner, then says in two to eight lines what the decision is, what its state holds and what it prints, then gives an `effect:` line naming exactly what leaves the machine with `--backend jev`. The score's escalation classes, the gate's routing rule and the brief's batch deadline are all stated where a caller looks for them.

What keeps READ at 7. The how paragraph, the first thing a cold reader parses, is still the compressed pseudo-run the 1.1.0 read rating reported: `state R?` means nothing, and its printed line `ASK OK id=f decision=q backend=fixed recorded=new` is not the line the tool prints, which carries `tokens_in=0 tokens_out=0` (cmd/nova-decide/main.go:56-60). The help never says what `jev` is or how it gets its key: the banner names `jev or fixed`, `score-grades -h` says "Jev's grades", and the key's variable and the `nova-secrets exec` recipe appear only in the refusal a reader meets after trying (cmd/nova-decide/main.go:358). Every verb's `-h` opens `usage: nova-decide <verb> [flags]` and ends with the tool's exit table, so `version -h`, `calibrate -h` and `findings -h` each promise an exit 1 for "an outcome conflicts with the one recorded" that they cannot reach. The banner says "a verb that lists takes --max" and `findings`, which lists, has none. `grade -h` documents `--examples`, `--held-out` and `--seed` that its usage line omits (cmd/nova-decide/main.go:137), and `import` and `score-grades` have no example at all. The 1.1.0 doc defects are mostly still there: docs/CLI.md's reference uses `noul` unglossed (docs/CLI.md:2556), its first run writes `./decisions.jsonl` into the checkout root (docs/CLI.md:2542) while the README's row uses `./trial-decisions.jsonl`, and docs/USAGE.md still never names the tool. The spec's output section (docs/SPEC-NOVA-DECIDE.md:190-192) says a refusal is one line carrying every problem and a backend failure prints `FAIL`; the binary prints one REFUSED line per missing flag, stops at the first unknown flag, and prints `FAILED`.

USE. The first run is clean and every number on it is reproducible: each example ran, each `--op` replay printed `recorded=existing` with the same answers, `outcome` with the same label printed `changed=false` and with another label `OUTCOME FAILED ... an outcome is attached once` at exit 1, exactly as the help says. `--dry-run` on a recorded op shows the recorded answers, and on a new op shows the plan (`questions=2 state_bytes=101 recorded=no`). `--json` carries the same facts and items, and a refusal under `--json` is one JSON object. Missing required flags are all named in one run with what each wants; an unknown flag lists the verb's flags; an unknown backend says the two it wants; the model backend with no key refuses before sending anything and names the recipe; a corrupt record is refused naming the file and line, by every verb that reads it. `gate` refused a green test output and a `--bars` pair summing to 1 or less with the reason; `brief` over a directory said MORE at `--max 1` and named the remedy; `import` twice added nothing the second time.

What keeps USE at 8. A system binary is accepted as state (`ask --state /usr/bin/ls`) and as a diff (`read --diff /usr/bin/ls`), recorded, and with `--backend jev` would be sent to the model. An empty state fails with the remedy "make --answers answer every question of the schema", which is the remedy for a different fault, and it is labelled `FAILED` (a backend fault) when it is an input refusal (cmd/nova-decide/main.go:778, internal/decide/decide.go:184). `ask` with no `--op` still folds the clock into its id (cmd/nova-decide/main.go:751), so the same ask a second later is a second decision, while `gate` with no `--op` derives a stable id and replays: the two verbs disagree on what an unnamed ask means. `import --reports` with a glob that matches nothing prints `IMPORT OK` with every count 0 at exit 0, so a typo is a green (internal/decide/import.go:136). `outcome --record` naming a file that does not exist says "no decision with that id in the record" (internal/decide/record.go:82), which sends the caller hunting for an id when the path is wrong. `calibrate` asked of a question the schema lacks answers "its questions are in the schema 057e570dea7d49fc", a hash, not the names (internal/decide/calibrate.go:58). `score-grades` over a log of the wrong shape prints the Go type `struct { Lines []decide.LogLine "json:\"lines\"" }` (internal/decide/gradescore.go:55). Most refusals point at `nova-decide help`, the whole banner, where the unknown-flag refusal points at `<verb> -h`; the model backend's key refusal carries two `run:` remedies in one line.

## Good, keep

- Replay by op id: every deciding verb given the same `--op` returns the recorded answers with `recorded=existing` and asks nothing; `--dry-run` of a recorded op shows those answers.
- `outcome` is attach-once: the same label is `changed=false`, another label is exit 1 with when the first was recorded.
- The `effect:` line on every verb says exactly what leaves the machine with the model backend, and the model backend refuses before sending when its key is absent.
- A corrupt record is refused by every verb, naming the file and line, and nothing is written.
- `gate`'s `--bars` rule (an unset bar routes nothing; two bars summing to 1 or less are refused because one failure could meet both) is stated in its help and enforced.
