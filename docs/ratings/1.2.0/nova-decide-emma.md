# nova-decide READ and USE rating, nova-tools 1.2.0

Rater: a re-rate worker on deepseek/deepseek-v4 through dsh, the DeepSeek Harness headless runner
Build: 9c9b2ebc49fd
READ: 7/10
USE: 7.5/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-decide version` prints `nova-decide v1.0.1-0.20261007202756-9c9b2ebc49fd linux/amd64 go1.26.6`. It was built and run on a Linux bench machine, in a throwaway directory under the job directory, with the fixed backend only: no live store, no server, and the model backend reached only as far as its key refusal and a dry run, so nothing left the machine. The banner, every verb's `-h`, the spec's sections 1 to 7 and the command reference's nova-decide section were read cold; the banner's examples and every verb were then run for real on records this rating made, and about forty refusals were provoked.

## Reasons

READ. The banner answers what the tool is in one line, glosses noul and choice before it uses them, and its ten example lines run as printed from a checkout root. Every verb answers `-h` and `help <verb>` with its banner excerpt, a paragraph on the decision it asks, its flags with a required marker, the exit table and an `effect:` line naming exactly what leaves the machine. The jev key refusal is the best line in the tool: it names the variable, the one command that sets it, and that the key is never a flag or a file. `--json` carries the same value as the typed lines, refusals included.

What keeps READ at 7. The how paragraph, the first thing a cold reader parses, is still the compressed pseudo-run the 1.1.0 read reported: `state R?` is unparseable shorthand and its `ASK OK id=f decision=q backend=fixed recorded=new` is not the line the tool prints, which carries `tokens_in=0 tokens_out=0` (cmd/nova-decide/main.go:56-60). The help never says what `jev` is or how it gets a key; `jev or fixed answers` is the whole gloss (cmd/nova-decide/main.go:57), and the sentence `TypeSafe's System One model` lives only in the spec (docs/SPEC-NOVA-DECIDE.md:52). `grade`'s usage line omits the `--examples`, `--held-out` and `--seed` that its `-h` documents (cmd/nova-decide/main.go:137), and `import` and `score-grades` carry no example. The banner promises "a verb that lists takes --max" (internal/tool/tool.go:522), and `findings`, which lists FINDING and SHADOW lines, refuses `--max`. Calibrate's default bars 0.5,0.7,0.9 (cmd/nova-decide/main.go:240) and findings' default bar 0.5 (cmd/nova-decide/main.go:317) are set by the code and printed by neither help. `help --json` is refused as `unknown verb "--json"`, and `help ask --json` ignores the flag, while the banner says every verb takes it. The spec's output section (docs/SPEC-NOVA-DECIDE.md:189-195) says a refusal is one line and a backend failure is `<VERB> FAIL`; the binary prints one REFUSED line per problem and `FAILED`, and its dry-run list omits score and import. The spec's first line still says "trained from its own record" while section 1 says the export and training verbs are not built, and the record's model `tla/DecideRecord.tla` is owed (docs/SPEC-NOVA-DECIDE.md:107), so the one-writer and one-outcome claims the tool's trust rests on are unchecked.

USE. The first run is clean and reproducible. The banner's ten examples each exit 0 on the fixtures, and every verb was driven for real on a record made for this rating: ask over a schema written here, read, score, attempt, grade, gate, brief on a card and on a directory, outcome, calibrate, import and score-grades. `--op` replay is exact: the same op returns `recorded=existing` with the same answers, and the same op over another state is refused naming the op. A second label is exit 1, the same label is `changed=false`, and a bad record line is named by file and line before any read or write. The record is created mode 0600. `--dry-run` on a fresh ask writes nothing, `--json` is one object for both OK and REFUSED, an unknown flag lists the verb's flags, missing required flags are all named in one turn with what each wants, and `--timeout 0`, `--width 0`, a bad `--backend`, an unknown option, a p outside [0, 1] and a missing answer are each refused with the problem named.

What keeps USE at 7.5 is a set of things that should fail and pass, and remedies that do not run. `ask` with no `--op` folds the RFC 3339 clock into the id, so the same ask a second later is a second decision (`shipit-5ba29b2b6ef5`, then `shipit-cc9072cb9e2d`), while `gate` with no `--op` hashes content only (cmd/nova-decide/main.go:751): the two verbs disagree on what an unnamed ask means. A choice's probabilities are checked only one by one in [0, 1], never as a distribution: `p=small:0.9,large:0.9` is recorded, and a choice of `large` whose own highest p is `small:0.5` is recorded and printed `value=large`, so the value can disagree with its probabilities (internal/decide/decide.go:162-166). `read --diff /dev/null` is `READ OK verdict=LAND`, recorded, while ask refuses an empty state: a diff that says nothing is read as a clean one. `outcome --dry-run` on a labelled decision with another label prints `OUTCOME OK ... recorded=no dry_run=true` at exit 0, where the real run is exit 1 (cmd/nova-decide/main.go:847). A named record that does not exist loads as empty (internal/decide/record.go:82), so `findings --record ./missing.jsonl` is `FINDINGS OK scored=0` and calibrate on it says "the record holds no decision named read" rather than that the file is absent; `import --verdicts 'nomatch/*'` is `IMPORT OK` with every count 0; and `score-grades --log` of the wrong shape prints the Go type `struct { Lines []decide.LogLine "json:\"lines\"" }` (internal/decide/gradescore.go:55). The gate's `--bars 0.3,0.3` refusal names sprint-row keys `decide_gate_flaky` and `decide_gate_preexisting` (internal/decide/gate.go:321), and with no bars every failure prints `class=flaky` beside `route=caused` with no `bars=unset`. Most refusals end `run: nova-decide help`, the whole banner, where the unknown-flag refusal points at `nova-decide ask -h`; a run naming a missing schema and a missing state still does not name a missing `--answers` file.

A 10 would make the banner's how lines the example's own printed lines, gloss jev in the help, make every remedy a runnable `nova-decide help <verb>`, drop the clock from the default id, check a choice's probabilities and its value, refuse an empty diff, refuse a named record or glob that does not exist, check a dry-run outcome against the recorded label, print the flags' defaults and the minutes options, give findings `--max`, bring the spec's output grammar and title to the built tool, and land the record's model.

## Good, keep

The jev key refusal (`reason=key_absent: JEV_API_KEY is absent from this environment; run under nova-secrets exec --only JEV_API_KEY -- nova-decide ...`) is the model every refusal should follow. `--op` replay is real idempotency: the same op over the same state returns the recorded answers with `recorded=existing` and asks nothing, and the same op over another state is refused naming the op. A repeated label is `changed=false` and a conflicting label is exit 1, with the recorded label named. A corrupt record line is refused by file and line before any read or write, and the record is created mode 0600. Missing required flags are all named in one turn with what each wants, an unknown flag lists the verb's flags, and a near flag gets `did you mean`. The fixed backend makes the whole tool runnable with no network and no key, and every verb's `-h` carries an `effect:` line that says what touches the world. `--json` is the same value as the typed lines, for OK and REFUSED alike, and `--dry-run` provably writes nothing.
