## Reasons

README line: see what is installed and at which version, over the row whose sentence is "which version of each tool is installed, recorded and compared" (README.md:41) — and that sentence is the banner's own first line (internal/update/versiontool.go:21), so the page and the tool open as one.

Before any code, the first place I was confused is README.md:41: the row promises "recorded and compared" but never says compared with what, and the one command it shows reads only the installed half; a reader learns from the banner's next lines (internal/update/versiontool.go:23-26) that the comparing verb is diff and that latest is another tool's. The first place I was bored is README.md:46: the third telling of the same reassurance (README.md:12-14, README.md:46, README.md:89-91), beside the second "pick the row" (README.md:46, README.md:73). The first claim I doubted is README.md:41's "runs go version using the included local manifest"; I checked cmd/nova-version/testdata/example.tsv:2 and the doubt dissolved — the go row is there, and the command runs at exit 0 with Go on PATH.

The verbs are the good part, and the reading bears the tool out. The first run is the binary alone: example writes a one-tool manifest, refuses to overwrite anything else, and names the next command (internal/update/example.go:39, internal/update/example.go:60), and the transcript in docs/TESTS.md:675 is executed line for line by a test (cmd/nova-version/firstrun_test.go:75). Every verb states its effect; snapshot's two shapes are refused when mixed, naming both (internal/update/versiontool.go:80); a missing --file names the manifest's shape and the example that writes one (internal/update/snapverb.go:274). Snapshot's thirty-second bound is argued from measurement, in the present tense, with the warm-up alternative weighed and rejected (internal/update/snapverb.go:21-39); the ladder that asks version, then --version, then bare is explained by the case that forced it (internal/update/read.go:295-307). One manifest read names every problem at once, capped and counted, each with its line (internal/update/manifest.go:39-54), and the spec states each rule with the mistake it prevents and the tests that hold it (docs/SPEC-VERSION.md:40-42, docs/SPEC-VERSION.md:127-143).

What the score pays for is where the tool lives and how its prose counts. nova-version is a tenant of package update: its main is one line over that package (cmd/nova-version/main.go:22), the package carries both binaries' verbs beside the updater's release pipeline, adoption ledger and fleet beat reader — 4,148 lines of non-test Go — and the shared dispatch branches on the binary's name (internal/update/cli.go:292). One verb's body sits across four files: report's flags at internal/update/versiontool.go:156, its checks at internal/update/cli.go:411, its body at internal/update/report.go:26, its rendering at internal/update/out.go:37. Two of six verbs print through that private renderer and take no --json (internal/update/versiontool.go:137), and the renderer's wait-out reason no longer holds: the skeleton added the prose tail it was waiting for (internal/tool/out.go:148). The docs explain a general count with one fleet's numbers — "the adopted 16" and "the 32" (docs/CLI.md:1736, docs/CLI.md:1777) — while nineteen directories sit under cmd/, and the shipped example those docs hold up still names two deleted binaries and omits nine live ones (cmd/nova-version/testdata/nova.tsv:6, cmd/nova-version/testdata/nova.tsv:13). A 10 is this tool in its own small package, one file per verb, --json on every verb, every verb's home findable in a minute, and every count in the docs either gone or held by a test.
