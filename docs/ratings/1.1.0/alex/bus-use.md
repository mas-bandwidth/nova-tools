## Reasons
Used cold from the help alone, every command against a bare origin and three clones under the job's own scratch, nothing real touched: no network remote, no store, no credentials. The banner's example block runs as printed: a copy of the example bus, given a repository of its own, passed names, check --full, inbox --full --open and draft, and draft's standard output is a file as the banner claims, its NOTE line going to the error stream. Two sittings ran end to end through the origin: draft, send, fetch, inbox, receipt, with the receipt closing the note and the open list emptying on the next walk; then reply with a re line beside a wait that returned the moment a note landed mid-wait, one poll later, handing back the exact rearm command. All ten verbs ran for real, and none needed a service beyond the bare git origin, so no verb went untried.

The refusals are the best I have used as a reader. A send missing two flags names both in one run; an unknown flag lists the verb's flags and names the nearest; a zero where a count belongs says what it wants and the three places the value may live; the first advance on a bus with old notes hands the exact line to run, which ran verbatim; moving a switch-day line earlier is refused with the reason and the exact command; two writers on one checkout serialised with both runs green. Dry runs were proved dry: HEAD and the origin unmoved after send, reply and close --dry-run, and send's dry run prints the whole note it would send, clearly marked.

What holds the score down is the read path walking a checkout that stands still. Every inbox run walks the checkout as it stands at run start: the fetch the run makes feeds the cursor push and its recovery, not the walk, so the documented backlog-clearing run on a clone that sat behind prints changed=0, moves the cursor onto the stale tip and says nothing, and the note arrives on the next run; a reader polling with inbox alone reads every note one turn late, while the wait path, which polls the fetched tip, reads current. Beside that: with --bodies an advance that prints nothing new does not move the cursor at all and prints no cursor line; no verb takes --json, so a consumer of the listings parses line grammar; the receipt path given absolutely is refused as a note that does not exist, with no remedy on the line; and three guesses stayed open: wakes= on every send is named in the spec's grammar and explained nowhere, subjects arrive escaped as \x20 with the rule in no help, and the switch-day remedy line hands back placeholder values where the first-advance refusal fills in the real ones. A 10 needs the walk on the fetched tip or one NOTE naming the stale checkout and how to move it, the bodies advance kept, a JSON rendering for the listing verbs, and the receipt path's scope named in its help.
