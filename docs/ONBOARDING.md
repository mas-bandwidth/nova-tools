# ONBOARDING — a newcomer's first run

**A newcomer's first stumble is the spec for the onboarding points.** Two
newcomers ran two of these tools for the first time on one day, and both
stumbles were ours: a usage banner with no runnable line in it, and a refusal
that named what was wrong without saying what it wanted.

The five points every command meets are in [STANDARD.md](STANDARD.md), under
**Help and refusal: the five onboarding points**, numbered as code cites them
("ONBOARDING point N"). A newcomer starts with `<tool> help`, pastes a line of
its `example:` block, and reads the tool's `### First run` in
[CLI.md](CLI.md).

## How feedback arrives

From Glenn, through Emma, on the day nova-bus went live:
*"We get better tools this way."* When you try a tool, say
three things, in this order: what works, so the author knows what to protect; where it catches or surprises you,
plainly, with the exact sentence it printed; and the fix you would make, a README line, a hint, a flag. Pure
criticism reads as an audit; pure praise leaves rough edges rough. Every stumble named this way became a fix within
the hour on the first day, and the author was glad of each one.
