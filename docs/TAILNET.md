# The tailnet of the node `rowan`

GENERATED by `nova-pulse fleet net init`. Re-run it when the machines registry changes;
edit the registry, not this file.

## One tailnet per node

Glenn, 2026-09-18: *every NODE -- a team of humans and AI seats -- has its OWN Tailscale
network.* A node is not a subnet of somebody else's tailnet and never joins one. Cross-node
reach is **node sharing**: one machine is offered into another node's tailnet, accepted
there, and written down in that node's machines registry as `provider=shared-from:<node>`.
There is no merged tailnet, no shared admin console and no shared API key.

The reason is that **the bus is the federation**. Two nodes work together through git --
the bus, the queues, the pull requests -- and git needs no tailnet at all. A node with no
tailnet is still a node: it writes `provider=lan` in its registry and everything else in
nova-tools works unchanged. Nothing in the tools may hardcode a tailnet address, which is
why the registry carries a provider column and the verbs ask it.

A machine advertises ONE TAG PER ROLE when it joins, and the policy is written about the
tags rather than about the names -- so a new bench needs a tag and no edit to the policy:

| machine | provider | `tailscale up --advertise-tags` |
| --- | --- | --- |
| `studio` | `tailnet` | `tag:coordination` |
| `hulk` | `tailnet` | `tag:bench` |
| `vision` | `tailnet` | `tag:bench` |
| `space` | `tailnet` | `tag:bench,tag:services` |
| `mini` | `tailnet` | `tag:runner` |
| `batman` | `tailnet` | `tag:runner` |
| `superman` | `tailnet` | `tag:runner` |
| `air` | `tailnet` | `tag:bud` |

**An owner's own laptop joins UNTAGGED.** This is the one trap in the table above: a tag
replaces a device's user identity, so a laptop that joined with `--advertise-tags=tag:bud`
is a bud to the ACL and reaches benches and nothing else, whoever is typing on it. An
owner's own machine runs plain `tailscale up`, is covered by `group:owners`, and reaches
everything. Tag a bud only when it is somebody's machine and not one of the node's own
people's -- a seat's bench-runner, a contractor's laptop.

**`tag:runner` is advertised only by a machine that is a runner and nothing else.** A host
that runs CI shards beside its cards is `tag:bench`, full stop: CI is a process on that
machine, not a way of reaching it. Johnny's security read of 2026-09-18 is the reason:

> A Tailscale ACL grants when any rule accepts, so `tag:bench`+`tag:runner` is reachable
> as a bench and R3 is false for that host. The dated `allow-shared=` note is a hole with
> a calendar, not a shape. One reach-role per machine.

So the denial is TRUE rather than true-with-a-note: every machine carrying `tag:runner` is
one nothing tagged reaches, and there is no overlapping accept to defeat it. The registry's
`allow-shared=` note keeps its own job -- it is what stops a CARD being placed on a runner
host -- and the two rules no longer have to agree for either to hold.

## The ACL is code, and Tailscale applies it

The policy file is Tailscale's own HuJSON, in this repository, with its own `tests` section.
`.github/workflows/tailnet-acl.yml` runs Tailscale's official GitOps action: `tailscale acl
test` on every pull request that touches the policy, `apply` on a push to the default
branch. We wrote no ACL language, no applier and no etag check -- the action has all three,
and an apply over a policy somebody edited in the console fails instead of clobbering it.

The invariants live in the `tests` section, so the thing that enforces the policy is the
thing that checks it:

* a **bud** may ssh to `bench` machines and to nothing else;
* nothing reaches the **coordination** machine but the node's own people;
* a **runner** host accepts nothing TAGGED -- no bud, no bench, no seat's machine. It talks
  out to the forge and that is its whole network life (the lock of 2026-09-18: runner hosts
  are CI-only). The node's own people are not a tagged thing and do reach it;
* the node's own **people** reach every machine they own, on every port, over ssh, with no
  check. Glenn, 2026-09-18, travelling: *"I want to work with all friends, including keeper
  you and all fleet machines from the air with no restrictions."*
* **services** are reachable from benches on the named ports only, never on ssh.

## One secret, in the forge

`TAILSCALE_API_KEY` in this repository's secrets: a Tailscale API key for this node's
tailnet and no other. Per-node tailnets mean per-node keys -- a key that could reach two
nodes would be the merged tailnet by another road. The key reaches nothing outside the
workflow: not a flag, not a file in the tree, not a line any verb prints. On a machine, an
auth key reaches `tailscale up` through `nova-secrets exec` and the remote shell's stdin,
never an argv.

## Tailscale SSH, Serve, MagicDNS

**SSH**: the tailnet identity is the authorization. The `ssh` section of the policy decides
who may connect as whom; no `authorized_keys` is distributed to any machine, and a person
who leaves is removed from the policy rather than from every host's key file.

**Serve**: something that has to be reachable in a browser is `tailscale serve`, which is
private to the tailnet and gets its certificate from Tailscale. **Funnel** -- the same thing
on the public internet -- is never on by default, and is a decision somebody makes out loud.

**MagicDNS**: on. Every machine is reachable by its name, so there is no `/etc/hosts` block
to write on any machine and no name list to keep in step with the registry.

## What certify probes

`tailscale status --json`, parsed, crossed with the machines registry: a machine the
registry calls `tailnet` with no node is a finding, and a node the registry does not carry
is a finding. That is `nova-pulse fleet net status`, which runs read-only and opens no
socket in any test. The ssh workload proves a connection through the tailnet identity with
no `authorized_keys` on the far side.

## A new node

```
nova-pulse fleet net init --machines <registry> --node <name> \
    --tailnet <tailnet> --owner <login> --out .
```

Three files, from the registry the node already keeps: the policy, the workflow and this
page. Then add `TAILSCALE_API_KEY` to the repository's secrets and merge.
