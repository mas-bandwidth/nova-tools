# Proposed node move contract

For discussion against SPEC-WORK.md@7db3b95cd4c16b1eb34b1c77c0fc224755cc7a64. Not locked, implemented or approved by absent friends. Source anchors: containment/kinds 721–795; event/digest 326–348,806–821,874–942; verb gap2339–2341; indexes2750–2812. This fills the named structural operation, not a generic field editor.

## Request

`nova-work node move --session <path> <write flags> --node <id> --from <parent-id> --under <parent-id> --reason <text>`

Wire op is `node.move`; args are exactly `node`, `from`, `under`, `reason`. Node and reason are required nonempty strings; from and under are exactly `{"kind":"node","id":"<id>"}` with a required nonempty ID. Both use canonical `(:node "<id>")` parent values, matching add's typed parent representation; move never accepts the open-root variant. Write flags use the existing request/as/expect/now/generation contract. Unknown keys, null, missing or empty values refuse; IDs use the existing validator. `from` is explicit caller intent, not a parent inferred afresh on retry. Stable IDs are opaque and never renamed to match the new display hierarchy. Append at the destination's end; this is reparenting, not sibling reordering.

## Admission and preserved facts

Require an existing open moved node, its actual direct parent equal to `from`, and an existing open containment-capable destination. Root O/C containers, repository-owning roots and validator-owned shared containers cannot be moved by this verb. A destination in the moved node's subtree is a cycle refusal. A direct source or destination that is a roadmap requires the roadmap/axis owning operation: `node move` cannot bypass axis membership or silently invent a row. Other roadmap references and cell refs remain references to the same stable node.

**Proposed ownership boundary for review:** `node move` preserves the repository owner. A different destination repository refuses as `repository-change`; it is not a source-code/issue/attribution migration. Cross-repository transfer needs an explicit contract for repo-qualified source evidence and historical attribution before that separate effect is enabled. This limitation is named, not a claim that cross-repo migration is solved.

The move does not change task state, acceptance criteria, evidence generation, source revision, explicit responsible, required flag, leases, attempts, dispatch state or raw usage pointers. It neither settles nor revives any node. Closed descendants remain closed under the same IDs and immutable history records. Current containment and historical as-of containment must stay distinguishable.

For this guard, `effective-private(n)` is the OR of the node's private marker and those of its containment ancestors; an absent/false marker does not override a true ancestor. Effective responsible is the existing nearest explicit responsible up containment. An execution needs protection while it has a valid live lease OR a recorded launch/dispatch whose terminal outcome has not been reconciled, including lease expiry, missing contact and a pending stop. Silence or a deadline never proves terminal execution. These predicates must be derived from existing lease/ACTIVE indexes, not a second stored worker status; absent required observations yield unavailable.

**Proposed inherited-context guard:** if the move would change effective responsible for an active/uncertain attempt anywhere in its reached subtree, refuse with the affected IDs; an ordinary explicit assignment/reconciliation must precede a different responsibility context. A move which leaves that context unchanged may move working tasks: it does not cancel, redeliver or duplicate their work. A move may not reduce effective privacy of any reached node. Preserve existing inherited privacy explicitly before a public destination is used; the move itself never grants declassification authority. Increasing privacy is allowed and invalidates affected public projections. Absent historical records needed to prove these guards are an unavailable refusal, not guessed public/inactive state.

## One mutation envelope

Add one new structure variant with requester fields in fixed order: `:verb` (`:node-move`), `:from`, `:under`, `:reason`. The subject is the moved node. Add a paired `:reparent` scope event on the same subject, own fields `:from`, `:under`, `:reason`. Integration must add `:reparent` to the closed scope-kind registry, fixed-order serializer, required-set delta table, replay validator and undo table together. Older schema readers refuse it; no partial registry update or unknown-kind fallback is valid. Serialize the structure event first and scope event second using the existing canonical payload rules. A caller whose `from` and `under` are equal has the structure event only; that shape is determined by caller fields, never by mutable state. No existing verb or event-field order changes. Engine `:before` is outside the request digest and has fixed fields `:from-children` and `:under-children` (ordered direct-child ID lists), `:from-required` and `:under-required` (ordered direct required sets), `:from-scope` and `:under-scope` (integer revisions), plus `:context` rows sorted by affected ID, each `(:node ID :private BOOLEAN :responsible NAME-OR-ABSENT :execution-refs (ID...))`. `:after` records the same shape at acceptance. Full direct lists are bounded by the existing candidate/envelope limits; refuse oversize rather than truncate. There is no transitive descendant set stored in the preimage. Historical dependency/closure data retains its existing indexes.

The reparent delta atomically detaches from source children and appends to destination children. If the node belongs to the source required set, remove it there; at the destination its unchanged required flag decides membership. Do not encode this as `node remove` plus `node add`: remove settles into terminal removed history and add would reuse an ID. Do not mark the moved task discovered or completed globally. Parent-local reporting records transfer-out/transfer-in as such, so a coordinator can distinguish redistribution from new work. Increment each affected parent's scope revision once, the moved subject once, and invalidate ancestor counts/views. Common ancestors are updated once with the net delta. Required-set validation folds this reparent event for both named parents; no hand-edit or hidden set rewrite.

Global |O|, current |C| and W membership remain unchanged. Update only source/destination ancestor open counters and affected ownership/category/subtree/view indexes. Historical closure rows, event-time repo attribution, usage and previous baselines are immutable. Current subtree queries use the revised containment, historical queries use their captured revision. Required closed descendants are resolved through bounded indexes, never by loading all C. No constant-time claim for a structural change; bounded reached-graph visits and propagation are measured.

## Outcomes, retries and undo

Validate the complete candidate and journal the whole envelope before success; a failed precondition accepts neither half. Same request/id/payload returns its existing disposition; changed payload refuses. Lookup a prior durable disposition before checking the now-changed parent, so a lost reply does not turn successful retry into a misleading source-parent conflict. A fresh `from == under` request which names the actual parent leaves sibling order unchanged but still journals its typed structure event as the accepted receipt. It advances the accepted-event revision, with no scope event, no membership/index/counter change and a real event id. Same-id replay returns that receipt after later work; it never re-evaluates the no-op as a fresh move. Unknown prior disposition after a retention gap is the existing explicit dedup refusal.

Proposed success is `NODE OK id=<event-id> request=<id> node=<id> rev=<n> pushed=<rev|-> effect=<moved|unchanged> from=<id> under=<id> emitted=<bytes>`. A refusal is `NODE FAIL node=<id> code=<parent-conflict|cycle|repository-change|roadmap-operation-required|active-context-change|privacy-reduction|unavailable>: <escaped-reason>`, in addition to unchanged generic stale/request/validation refusals. No private metadata appears in reasons. No new success is inferred from a disconnected caller. Both output additions require the final common schema update before lock.

Undo-plan shows both parents and the captured before/after data at a revision. Before compensation, compare current ordered parent children/required lists and scope revisions exactly with the stored after image, and re-evaluate the context guards against the current execution indexes. Refuse if the moved node is no longer open or any comparison/guard fails. The compensator restores the exact before ordering and required sets in one validated envelope; recorded old scope revision numbers are guards, never values to write backwards. Undo itself appends new scope revisions. It restores containment only: metadata and execution facts are not overwritten from the context witness. An intervening sibling reorder therefore causes an explicit conflict, not an attempt to guess an insertion position. It never rewrites old events or moves already-closed root work back to O. Redo applies the same current-state checks. Dry-run remains a revision-bound plan through the existing planning contract, never an unjournaled mutation.

## Required witnesses

1. Moving a required subtree subtracts/adds parent-local counts while global O/W and every task state remain unchanged; common-ancestor net counts are stable.
2. Same-parent no-op preserves sibling order; lost-reply retry produces one envelope; different-payload reuse refuses; every failure leaves both parents unchanged.
3. Cycle, wrong source, repository root/shared-container, cross-repo and direct-roadmap-parent attempts refuse with the relevant identity.
4. Working subtree with unchanged context retains exactly the same lease/attempt/usage. Changed inherited responsibility on uncertain work or reduced privacy refuses; increased privacy removes affected rows from public renders.
5. Closed descendants and captured old roadmap/as-of queries retain original evidence and closure history; current references still resolve the moved stable IDs. Missing necessary archive data refuses honestly.
6. Kill before/after journal acceptance and during clip/recovery exposes neither two parents nor no parent. Undo restores original order; intervening reparent/sibling/privacy changes cause conflict instead of overwriting later work.
7. Scale unrelated O and C while holding reached subtree and touched ancestors fixed: no whole-work-set scan, no global W reconstruction; report visits, pages and allocations. Large affected subgraphs still obey command/frame/operation bounds.

Review decisions are the same-repository ownership boundary, inherited-context guard, new paired reparent kind and parent-local transfer accounting, plus exact undo preimage encoding in the final wire/persistence schema. These are proposals for Rowan/Emma to accept or revise before lock.
