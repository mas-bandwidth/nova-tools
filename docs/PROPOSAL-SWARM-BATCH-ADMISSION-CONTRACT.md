No v1 receipt wire format has shipped; the retained drafting revision is not a wire schema version.

Its independent delta review cleared the live-owner retry clarification; that cold review is not an approval of this portable revision. Maintainer and independent reviewer dispositions must name the resulting exact proposal revision. Prior dispositions do not approve this text, and the existing crash/durability and build gates remain required.

## Smallest proposed implementation boundary

Add only the opt-in CLI path, admission encoding/snapshot/locking/publication/reconciliation helpers, and typed optional Sidecar correlation. Keep legacy Add, dispatcher, cancellation, profiles and accounting behavior unchanged. Existing prompt wrapping and batch flag parsing remain authoritative for their existing meanings; this contract adds no deadline validation or token-parser cleanup. A bounded new helper can be package-local; a cross-project filesystem abstraction is unnecessary.

This boundary supports durable admission records and conservative idempotent recovery. It does **not** promise automatic recovery of every interrupted publishing card, an atomic task/sidecar move, or durability of the dispatcher's later state transitions. The existing unresolved clauses already allow this conservative behavior; this is a boundary clarification, not a new objection to those clauses. A stronger guarantee needs the separately scoped transition repair described below; it is not silently included here.

## Proposed exact v1 wire contract

Use UTF-8 JSON, no BOM, compact encoding followed by exactly one LF. Every schema-defined object key is present (no omitempty); null is used only where explicitly permitted below. Object members are serialized in ascending ASCII key order. Arrays preserve their defined order. Strings use JSON escaping as Go encoding/json Marshal with its default HTML escaping: quotes/backslash/control bytes escaped, `<`, `>`, `&`, U+2028/U+2029 escaped; other valid UTF-8 remains literal. Integers use unsigned base-10 JSON integer spelling without signs, fractions, exponents or leading zeroes, except Sidecar RC which retains the existing format. Hashes are 64 lowercase hex SHA256 of exact persisted bytes including the LF for JSON records; prompt hashes cover exact bytes, no implicit LF. No self-hash field occurs in a hashed record.

A receipt decoder must reject invalid UTF-8, duplicate keys at any depth, unknown/missing keys, wrong types, invalid nulls, duplicate array identities, invalid scalar ranges and trailing material. Decode, validate, and require byte-for-byte equality with canonical re-encoding. Do not use ordinary json.Unmarshal alone: duplicate keys and unknown fields otherwise have permissive behavior. No extensibility bag, implicit migration, PR264 encoding compatibility, floating point or unordered map semantics. Unknown schema versions refuse.

The complete v1 object member sets (names inside parentheses are nested schemas, not serialized tags):

- `pool.json`: `canonical_path` (UTF-8 absolute path), `device` (canonical decimal string), `inode` (canonical decimal string), `platform` (`darwin-apfs-v1` for the proposed bench target), `schema` (`nova-swarm-admission-pool-v1`).
- `intent.json`: `batch_id` (string), `cards` (Card array), `parameters` (Parameters), `pool_sha256` (hash of pool.json), `schema` (`nova-swarm-admission-intent-v1`), `source_directory` (normalized locator), `submission` (original ASCII identifier), `template` (Template or null).
- Card: `admitted_bytes` (integer), `admitted_sha256` (hash), `job_id` (string), `key` (filename string), `raw_bytes` (integer), `raw_sha256` (hash). Key is the exact source basename; there is no second potentially inconsistent filename field. Snapshot path is derived as `prompts/<job_id>.task`, never a caller-supplied path.
- Parameters: `deadline` (exact batch string, including empty), `files` (positive integer), `label` (exact UTF-8 string), `max_input` (nonnegative integer), `tokens` (nonnegative integer), `unmetered` (boolean). Metered tokens are positive; unmetered requires tokens=0. CLI spellings that parse to the same validated integer are equivalent. No deadline validation, parsing or rewriting is introduced at admission. Current batch does not apply add's ParseDuration validation. At runtime taskDeadline uses a positive parsed task duration or falls back to the worker default (supervise.go:365-369); retain that behavior. Token values come from the current tokens/parseInt helper, including its fmt.Sscanf parsing; this is not a stricter token-argv grammar. The wire stores the resulting integer and unmetered flag.
- Template: `name` (existing selected task-template name), `prefix_sha256` (SHA256 of WrapTemplate(name,files,nil)), `wrapper_version` (`swarm-wrap-v1`). This version fixes the existing trailing-LF algorithm at templates.go:163-180. Future wrapper semantics need a new version. Ordinary replay recomputes identity and admitted hashes; resume never calls the wrapper. With no selected template, template=null and raw/admitted hashes and lengths must match.
- Outcome: `card_index` (null for reserve/close; required integer 0..len(cards)-1 for publishing/terminal/reconcile), `cards` (OutcomeCard array), `intent_sha256` (hash), `kind` (`reserve`, `publishing`, `terminal`, `reconcile`, or `close`), `previous_sha256` (prior written outcome hash, null only at revision 1), `reservation` (Reservation), `revision` (1..1024), `schema` (`nova-swarm-admission-outcome-v1`).
- OutcomeCard: `key`, `job_id` (must equal corresponding intent Card), `status` (`unattempted`, `accepted`, `refused`, `unresolved`), `reason` (Reason or null). All cards appear once in intent order. Reason: `code` (closed enum below), `detail` (valid UTF-8 whose canonical JSON string payload, excluding its surrounding quotes, is at most 1024 encoded bytes). Success/unattempted uses null; refused/unresolved requires a reason.
- Reservation: `first` (its reserve revision), `last` (inclusive highest reserved slot, <=1024), `reconcile` (sorted unique card-index array), `publish` (sorted unique card-index array), `active` (card index or null), `closed` (boolean). Arrays may overlap; each index is 0..len(cards)-1. `last-first+1 = len(reconcile)+2*len(publish)+2`. The reserve itself occupies first. Its first/last/reconcile/publish values are immutable through that reservation's close; every revision repeats them exactly. active and closed change only as specified below. Written history, including card_index, determines consumed allowances; no mutable counters or inferred changed-row identity substitute for it.
- Closed reason codes: `write_before_task`, `publication_uncertain`, `evidence_missing`, `evidence_conflict`, `evidence_unreadable`, `evidence_moving`, `synchronization_failed`. Only refused+write_before_task permits retry; it requires affirmative proof that this invocation did not enter the task publication operation, no earlier uncertain publication, and no conflicting job evidence. Codes are mechanical classification, not judgments about task execution.

Validate these closed revision transitions in addition to scalar/member validation:

- `reserve` occurs only at revision 1 or immediately after a close; first equals its revision, active=null, closed=false, card_index=null. Cards are identical to the previous outcome, or implicit all-unattempted with null reasons at revision 1. The fixed plan reserves one reconciliation per reconcile index and one publishing/terminal pair per publish index, plus reserve/close. All indexes must name this intent's cards.
- `publishing` requires active=null and closed=false. card_index must be an unconsumed publish index whose card is currently unattempted or has a still-valid refused/write_before_task permission. Set active=card_index; leave all card rows unchanged. This consumes that publishing index and any prior refusal permission for that card. One index cannot begin a second phase in this reservation.
- `terminal` requires a preceding active phase in the same reservation and card_index=active. It consumes that phase's one terminal allowance, clears active, and changes only that card's status/reason. The new status is accepted, refused or unresolved; refused/write_before_task requires affirmative nonpublication proof for **this** phase, not an earlier phase. A terminal with the same refused status/reason still consumes the allowance and establishes a new witness only if this phase's proof supports it. No second terminal is valid for that phase.
- `reconcile` requires active=null, closed=false and an unconsumed reconcile index equal to card_index. It consumes that index even when its card row is unchanged; only that row may change. An accepted card stays accepted with null reason. An unresolved card may only become accepted on sufficient matching proof or remain unresolved; it never becomes refused/unattempted or eligible to publish. An unattempted/refused card may become accepted on sufficient matching proof, become unresolved on ambiguous evidence, or remain unchanged. Reconciliation never creates a new refused/write_before_task permission.
- `close` requires active=null and closed=false; card_index=null; cards and the fixed reservation plan remain unchanged. Only closed becomes true. Its revision is within the originally reserved range; it consumes the close allowance and releases only the unwritten trailing suffix. No later revision may use that reservation. A new reserve starts at close revision+1, with a fresh plan.

Every non-reserve revision is within its original reserved range. No kind can alter another card, any intent/card mapping, an immutable plan member or an already-consumed allowance. Accepted cards are never eligible to publish. Publishing eligibility for a refused card requires its latest terminal outcome to be refused/write_before_task **and no later publishing phase for that card**. While that card is active, any retained refused status/reason is historical only. A later durable publishing phase consumes the old permission even if no task write is subsequently observed. Recovery must follow the active-phase rule rather than revive a historical permission. A terminal written during normal execution or crash recovery uses the same terminal allowance; recovery introduces no new outcome kind or slot.

Number files `outcomes/0001.json` through `1024.json`. They form a contiguous written sequence: the next reservation starts after the last written close, reusing only its unwritten suffix. No separate mutable latest pointer is required. Validate the complete bounded chain and transition history, not only the highest-looking filename. Unexpected numbered files, holes, invalid chains, extra current-owner reservations or corrupt immutable files refuse; never overwrite them. Unnumbered publisher temporaries matching `outcome-*.tmp` (verified as regular non-symlink files) left by an interrupted publisher are unlinked under the lock during recovery and are never outcome chain members; any other unnumbered or unexpected file in `outcomes/` refuses. An intent with no outcomes has an implicit all-unattempted state. A completed submission means a valid **closed** all-accepted outcome. All-accepted with an interrupted open reservation still needs closure using its reservation and is not zero-write replay yet.

Receipt metadata files obey the proposed 1 MiB limits after canonical encoding, including the trailing LF. Before reserving a plan, compute a conservative complete-record upper bound for every planned revision: preserve unchanged rows at their actual encoded lengths, budget each possibly changed reason at its 1024-byte escaped-payload maximum plus JSON framing and the longest allowed reason-code/status spelling, and include all keys, card indexes, plan arrays, hashes, revision numbers and punctuation. Refuse before job/sidecar writes if any bound exceeds 1 MiB; check each actual encoded record before publication as well. Do not estimate encoded size from raw UTF-8 length: the selected escaping can expand one raw byte to six bytes. For generated reason detail that exceeds its escaped-payload limit, retain the longest leading sequence of complete Unicode scalar values that fits after appending the literal ASCII marker `[truncated]`, including the marker within the same 1024-byte payload budget; apply the canonical escaping when computing that prefix. The decoder rejects an over-budget detail rather than truncating retained input. Filenames, card keys and prompt bytes are never truncated. The existing card/prompt limits and this encoded reason bound keep preflight finite. Outcomes do not embed prompts or unbounded diagnostics. Responses use existing bounded-output conventions plus the proposal's 8 KiB cap.

Sidecar adds optional typed `admission` with exactly `card_key` and `intent_sha256`. Existing JSON formatting need not become canonical. Compare the typed immutable projection: ID, Batch, Label, Template, Files, Tokens, Unmetered, Deadline, MaxInput and the proposed admission object. These existing fields are all actually present in Sidecar (pool.go:99-116), and batch assigns MaxInput: window (main.go:431). MaxInput persists as max_input when nonzero; omission decodes to zero, which means no caller-specified prompt-byte window (main.go:230-235). The admitted prompt hash/length lives in the intent and is verified against task bytes; it is not an existing Sidecar field. Ignore evolving runtime/verdict fields for admission matching. Require exact prompt bytes/hash and length. A copied correlation on a retry is provenance only; ID and From distinguish that attempt, so it cannot satisfy the original mapping.

## Proposed path, membership and pool binding

The intended first rollout target is the current Darwin/arm64 benches on local APFS. Linux-only would not satisfy that goal. The retained 2026-09-14 capability observation reports Darwin 25.6.0 arm64; this does not establish any other bench's OS, filesystem or durability. This contract proposes `darwin-apfs-v1`, pending the targeted witnesses below. Other OS/filesystem combinations remain unsupported for opt-in receipts until separately validated; legacy behavior and cross-platform builds/tests remain supported. CI must exercise explicit unsupported refusal, not quietly select an easier supported backend.

On Darwin open the existing pool directory and obtain its path with F_GETPATH on that descriptor; require an absolute valid-UTF-8 result, then Clean it without case-folding or Unicode normalization. Reopen the returned path and require its fstat identity to equal the held descriptor. Record that descriptor-derived pathname, not a caller's spelling. F_GETPATH is documented as descriptor-to-path resolution; no untested claim about all firmlink aliases or case spellings is made. Repeated invocations must produce the same path and identity or refuse. Case/firmlink aliases that produce another kernel path refuse rather than migrate. Obtain the ordinary source locator the same way; resume never accesses it. EvalSymlinks alone does not settle Darwin case/firmlink spelling.

Record fstat st_dev as its unsigned 32-bit bit pattern rendered in canonical decimal and st_ino as unsigned 64-bit decimal, together with platform=`darwin-apfs-v1`. Both describe the opened directory. This is an object identity check, not a globally unique/cryptographic identity; inode reuse is not claimed impossible. Do not require st_gen: Apple's stat manual says it is only available to the super-user. A changed device number, inode or canonical path refuses without migration, including after remount/reboot. Require fstatfs on the descriptor to report f_fstypename=`apfs` and MNT_LOCAL; verify admission and state directories are on the same device. Neither those values nor the architecture prove hardware flush behavior. No adjacent/private bench inspection is needed.

The retained read-only platform evidence includes the observed host's installed `man 2 fcntl`, `fsync`, `link`, `stat`, `statfs`; Apple's [fsync manual](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/fsync.2.html); and [XNU fsync_common](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/vfs/vfs_syscalls.c#L8879), which dispatches the vnode to VNOP_FSYNC without an ordinary-file-only guard. Apple's [F_FULLFSYNC dispatch](https://github.com/apple-oss-distributions/xnu/blob/f6217f891ac0bb64f3d375211650a4c1ff8ca1ea/bsd/kern/kern_descrip.c#L3861) delegates to the filesystem ioctl. This public XNU revision is a source pin, not asserted to match the running kernel. The APFS implementation and physical-power-loss behavior were not verified by that evidence; generic VFS dispatch is not proof that directory metadata persisted.

Create and sync admissions and pool.json before a submission; serialize first initialization with a persistent admissions initialization lock, and publish pool.json no-replace. On an existing binding, validate exact canonical bytes and fstat identity, never rewrite it. Keep the submission lock at a stable `admissions/<sha256(submission)>/lock` inode; take nonblocking flock with zero wait for a bounded busy reply. A newly acquired lock proves absence of another compliant holder on the supported single-host filesystem; PID timestamps are not proof. Refuse inaccessible/replaced/ambiguous lock objects. The submission directory and its parent creation are synced before committing intent.

Task basenames are valid UTF-8, nonempty, <=255 bytes, not dot/dot-dot and contain no slash or NUL. No Unicode normalization or case folding occurs. Sort exact UTF-8 bytes; admit every direct entry or refuse the entire capture if any entry is nonregular/symlink. Raw prompt bytes may be arbitrary bytes. Capture through bounded regular-file descriptors, compare directory membership and each file's identity/size/mtime/ctime before/after capture, and compare the opened directory identity. Any detected change refuses. These are detection checks, not a claim of a filesystem-wide atomic snapshot or detection of every possible ABA edit. Recheck input/card/count/total limits after wrapping. Ordinary replay compares every immutable captured field except newly generated IDs: load existing IDs before comparison and never generate replacement IDs for an existing submission.

For a new intent use existing NewID and validate generated IDs are safe basenames, distinct from each other and the batch ID; allow at most eight attempts per generated ID, then refuse before immutable intent publication if distinctness still fails. Existing ID randomness is not a uniqueness proof: collision checks and no-replace publication remain required. Preflight all five state directories for conflicting preassigned task/sidecar paths; a later collision still stops unresolved.

## Publication, synchronization and recovery contract

Implement a publication helper returning whether the final-name operation was entered, whether it succeeded, and whether durability synchronization succeeded. Do not flatten these into one error that callers interpret as nonpublication. For Darwin/APFS propose this precise sequence: create an unpredictable exclusive regular temporary in its final directory and keep its descriptor open; write all bytes and check file fsync; os.Link(temp, final) for atomic no-replace; fsync the containing directory; then fcntl(F_FULLFSYNC) on the still-open regular-file descriptor; unlink the temporary; fsync the directory again and F_FULLFSYNC the retained descriptor before checked Close. Initialization directory/parent synchronization uses a retained regular initialization-lock descriptor on the same device for the full-sync request after directory fsync. No F_FULLFSYNC-on-directory support is assumed. Any failed required call refuses before task publication where possible, otherwise records/reports unresolved. A planned platform witness exercises the corresponding descriptor-relative hard-link, directory-fsync and regular-file-F_FULLFSYNC sequence on the target bench (planned subset of witness 2). Preliminary platform probes used linkat rather than Go os.Link and did not test receipt initialization or crash recovery; this remains a proposed APFS contract, not a measured durability result. Darwin link(2) documents atomic directory-entry creation and EEXIST when the destination exists; use that existing bus-style hard-link primitive rather than adding rename variants. No fallback to replacing rename, direct final-path writes or check-then-create. The retained installed Darwin fcntl manual states F_FULLFSYNC drains prior fsynced I/O on the same device; F_BARRIERFSYNC supplies ordering without promising persistence on return and is not a substitute. Apple also describes persistence as best-effort under sudden power loss in [Reducing disk writes](https://developer.apple.com/documentation/xcode/reducing-disk-writes). Accordingly, the contract is successful OS-requested synchronization on a verified supported bench, never an absolute physical-media guarantee. The task temp must never end in `.task`; sidecar temp must never have a discoverable task filename. Filesystem/primitive eligibility and directory-sync capability are checked in the admission namespace before job writes; later I/O errors remain possible and are handled by actual publication point.

Publish/sync prompt snapshots first and immutable intent last as the completeness marker. A crash before intent is complete permits no jobs. Leftover snapshots without intent are incomplete infrastructure and refuse; no new cleanup/restart command is added. Verify all snapshots before ordinary continuation or resume. Sync each new directory's parent and each file's immediate containing directory; file Sync alone is insufficient.

Reserve the whole R+2P+2 plan and sync its outcome before any sidecar/job operation. For each eligible card: persist/sync publishing; publish/sync the matching sidecar no-replace, or reuse/sync it under the retry rule below; publish task no-replace as above; persist/sync terminal accepted only after successful required admission synchronization. Stop at first failure and leave later cards unattempted. A synchronization error after entering dispatchable publication is unresolved even if the task can currently be read. Before entering task publication, this live owner may record refused+write_before_task if it knows no earlier task operation occurred and finds no conflicting evidence. Never remove a published sidecar to simulate rollback.

After a process crash, an active publishing phase plus a sidecar-only job is **unresolved**, not proof of an unpublished stage: the old process may have linked the task and a dispatcher may have moved it. Same for no job paths, task-only files, unreadable/conflicting observations, or uncertain directory moves. Do not retry that card. For a fresh live-owner retry, check the latest terminal refused+write_before_task witness and absence of a later publishing phase when deciding eligibility to start the new phase. The witness must have been persisted by its owner before entering that phase's task-publication operation. For sidecar reuse, verify the exact intended retained sidecar and absence of conflicting evidence before starting the new publishing phase; persist/sync that phase, then its same uninterrupted live owner may reuse and synchronize the verified sidecar without overwriting or republishing it and continue to the task operation. Entering this new phase consumes the old witness. A replacement owner recovering the new phase can never reuse that older witness to publish: sufficient matching evidence establishes acceptance, otherwise the phase is unresolved. If the affirmative pre-task witness is unavailable at the eligibility check, the existing proposal's permissive 'may complete' clause does not apply.

Reconciliation enumerates pending, running, done, failed **and aborted**. Stable complete exact matching task/sidecar evidence can establish historical acceptance; revalidate files/directory observations and stop unresolved on a detected move rather than treating a multi-path walk as atomic. A valid already-accepted receipt remains historical admission evidence after reclaim or later job changes; replay never republishes it. Current report/usage bytes alone are insufficient for promotion to accepted. No retained runtime ledger is added.

An interrupted reservation is recovered before any fresh publication. At most one active card exists; write kind=terminal with card_index equal to that active card, using its remaining terminal allowance to record accepted or unresolved, then one close slot. Older refusal reasons never authorize another task publication in this recovery. If there is no active card, close with the next remaining slot. Untouched planned cards remain unchanged. Existing complete but not yet synced immutable records can be verified and synchronized under the lock before use; malformed/partial/colliding records refuse. Do not overwrite a slot or allocate outside the reservation to explain its failure. Exhaustion, corrupt reservation or unprovable budget refuses new job writes. No new outcomes are needed to report completed closed replay.

## Source-backed recovery limit and bounded repair

The existing text already classifies ambiguous reads and missing evidence as unresolved, so conservative non-retry is not a newly found defect. The remaining interpretive limit concerns publication durability and the broad dispatcher-observation acceptance wording: `Pool.Claim` at pool.go:261-269 moves the task before the sidecar, ignores sidecar errors and synchronizes neither state directory. The producer can link pending/J.task; the dispatcher can move it to running/J.task before the producer syncs pending. Syncing pending does not synchronize running. A process can also crash between the two renames, leaving a task and sidecar in different states. Therefore this admission-only design cannot prove a durable, colocated runnable job survives every host crash, nor ensure a dispatcher recovering later always obtains the complete intended sidecar. Repeated scans cannot repair that proof.

The smallest follow-up is to make the already-conservative promise precise: 'A task first becomes discoverable only after its intended sidecar has been published and synchronized in pending. Receipts are durable admission evidence; subsequent legacy dispatcher transitions are not made atomic or power-loss durable by this feature. Unprovable interrupted publication is unresolved and never blindly resubmitted.' This retains useful filename/ID replay and conservative recovery with the existing runtime. The acceptance row 'never sees task without sidecar' must mean initial pending publication, not all later recovery states.

If maintainers require the stronger interpretation, build remains blocked for that interpretation. A bounded follow-up must make opt-in job claim/move recoverable and synchronize both state directories, and ensure claim recovery refuses/restores missing admission sidecar metadata before launch. This is a targeted dispatcher transition change, not a general scheduler; it still needs exact revision review and witnesses. It cannot be fixed by changing receipt encoding or merely adding producer fsync calls. Do not silently land that extension under this contract.
