# schemas/

The schema definitions of the records nova's tools exchange, and the rules for the Go
generated from them. The schema compiler turns a `.schema` file into Go; the Go is
committed; `make schemawire-check` proves the committed Go is what the pinned compiler
writes today.

No area is here yet. The first generated package lands with the first area.

## The home rule

- **A type both repositories read lives once, here.** nova-tools and nova-sprint both
  read it, so its definition is `schemas/<area>/` in nova-tools and its Go is generated
  into `pkg/<area>wire/`. nova-sprint imports `pkg/<area>wire` through its existing
  nova-tools require; it keeps no copy of the definition and no generated copy.
- **A type only one repository reads lives beside its consumer**, in that repository,
  under the same rules.
- One area is one directory: `schemas/<area>/` holds its `.schema` files, the
  `tables.baseline` of its tables (`schema tables-baseline --update --reason "first
  baseline" schemas/<area>`; without one, `schema check` only prints a notice that
  evolution is unguarded) and, for a fixed table, its `schema.lock`. Both are committed
  beside the definition before the first edit to it (the next build otherwise refuses
  every existing fixed image as `layout_newer`).
- One area generates one package: `pkg/<area>wire/`. Every `.go` file in it is generated
  except `generate.go`, which is hand-written and holds the package doc and the pin. The
  package is a package like any other: it gets its row in `internal/docs/catalog.go` and
  a `make map`.
- Generated Go is committed and never edited by hand. Edit the `.schema` and run
  `go generate`. A generated file carries Go's standard header
  (`// Code generated ... DO NOT EDIT.` before the package clause), and the line linters
  in `internal/ci` skip it by that header; `make schemawire-check` is its check.
- Generated table Go imports only the standard library: no new `require`, no `replace`,
  and the compiler is never in the build graph.

## The pin

Each generated package's `generate.go` is this, and only this, with the package doc
saying which `.schema` files it is generated from:

```go
// Package <area>wire is ... generated by the schema compiler from
// schemas/<area>/. Every other .go file here is generated: edit the .schema and
// run go generate ./pkg/<area>wire, never the output.
package <area>wire

//go:generate go run github.com/mas-bandwidth/schema/v2/cmd/schema@<pseudo-version> generate --lang go --out . ../../schemas/<area>
```

The pin line's exact form is

```
//go:generate go run github.com/mas-bandwidth/schema/v2/cmd/schema@<pseudo-version> generate --lang go --out . <schemas dir>
```

- `<pseudo-version>` is the Go pseudo-version of one exact schema commit, never a branch
  and never `@latest`. The commit the two tracers verified end to end is
  `4d9941fbc7fd420b560739e48256d5b5e2892cdc`, pseudo-version
  `v2.5.1-0.20261014163537-4d9941fbc7fd`.
- `<schemas dir>` is the area's directory relative to the package:
  `../../schemas/<area>` from `pkg/<area>wire/`.
- `go run <module>@<version>` needs no `go get` and changes nothing in `go.mod` or
  `go.sum`, so it works under `GOFLAGS=-mod=readonly`. A cold module cache fetches and
  builds the compiler once; a warm run takes seconds.
- Every `generate.go` in this repository names the same pseudo-version: one compiler
  writes the whole tree.

## The check

```
make schemawire-check
```

runs `go generate` in every `pkg/*wire` package that holds a `generate.go`, then
`git diff --exit-code -- pkg schemas`, and refuses a generated file left uncommitted.
It exits 0 only when the committed Go is exactly what the pinned compiler writes from
the committed definitions. With no generated package yet it says so and exits 0. A
`pkg/*wire` package with no `generate.go` (`pkg/sprintwire`) is hand-written and is not
regenerated.

## The bump recipe

A bump moves every pin to one new schema commit, in one commit of its own.

1. Choose the schema commit and read its pseudo-version:
   `go list -m -json github.com/mas-bandwidth/schema/v2@<commit>` (the `Version` field).
2. Replace the pseudo-version in every `pkg/*wire/generate.go`; no other line changes.
3. Regenerate: `go generate ./pkg/<area>wire` for each package.
4. For each area, run the compiler's `check` over `schemas/<area>/` with the new pin
   (`go run github.com/mas-bandwidth/schema/v2/cmd/schema@<pseudo-version> check
   schemas/<area>`) and read every line it prints; a `layout_newer`, a lock refusal or a
   baseline refusal stops the bump.
5. Read the diff of the generated Go. A change in a refusal's name, a bound or a wire
   byte is a behaviour change and is named in the commit message.
6. Test the packages that import the regenerated ones (`nova-ci local` runs the unit
   tier CI runs for the diff), then `make schemawire-check`, which passes on the new
   output once it is committed.
7. Commit the pins and the regenerated Go together, and say in the pull request which
   schema commits the bump spans. Any friction met goes into the pull request's
   "Schema improvements wanted" section, to be fixed in the schema standard first and
   then in its Go.
