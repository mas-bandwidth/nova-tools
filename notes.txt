CARD-8057 / nova-tools #524 — beat lease on `wait` exit, honoured by `nova-wake awake`

Issue (verbatim, from the card):
  Tool and command: nova-wake awake (config bus=, window=300) while Rowan's duty
  child was mid-cycle between two foreground waits.
  Verbatim output: FRIEND rowan asleep age=472 source=bus-cursor (Johnny, whose
  wait is a background process, reads awake source=bus-beat age=563 then).
  Expected: a line whose duty process is alive reads awake. The beat should carry
  a lease: wait writes BEAT with until=<stamp> = now + --beat-lease (default 10
  min) on entry and on every tick and on exit; awake treats a beat whose until is
  in the future as awake source=bus-beat, and a harness cycle that is working
  (not waiting) is inside the lease. Test: TestAwakeHonoursBeatLease,
  TestWaitWritesLeaseOnExit.

Investigation:
  The two named tests ALREADY exist on origin/main and ALREADY pass. They were
  added by commit 271a316 "nova-bus wait writes a beat lease (until=) on entry,
  tick and exit; nova-wake awake honours it, so a working duty cycle reads awake
  (#524) (#535)" (2026-09-15 14:13), together with the code change and the
  docs/SPEC-WAKE.md and docs/SPEC.md updates. The #524 fix is therefore fully
  present at origin/main (af82d73): there is no code left to change.

  Code paths read whole:
    - cmd/nova-wake/main.go cmdAwake (lines ~346-431) reads from-<name>/CURSOR
      via git log (cursorTime) and from-<name>/BEAT from its own working-tree
      content (beatTime); the switch at ~384-419 already has
      `case haveBeat && until > 0 && until > now: source = "bus-beat"; awake`.
    - cmd/nova-bus/main.go cmdWait (~2245-2393) writes the entry beat with
      until=now+--beat-lease; waitLoop (~2443-2613) writes the beat (until=now
      +lease) at the top of every poll and lands it on every exit path via
      landBeat(); --beat-lease defaults to 10m (defaultBeatLease, line 2417).
    - internal/bus/cursor.go WriteBeat (~446-455) serialises the lease
      `until=<RFC3339Nano>`.

  Red test (reconstructed pre-fix, against the parent of 271a316): the awake
  switch had no `until` branch, so a beat whose stamp was older than the cursor
  but whose lease was still in the future fell through to the cursor case and
  printed the wrong line. TestAwakeHonoursBeatLease's failure would read:

      FRIEND rowan asleep age=472 source=bus-cursor
      AWAKE OK friends=1 awake=0 asleep=1 unknown=0 window=300

  (expected "FRIEND rowan awake age=500 source=bus-beat"; this is exactly the
  issue's own verbatim failing line, "asleep age=472 source=bus-cursor".)

  Green (current main, verified):
      $ go test ./cmd/nova-wake/ -run TestAwake -count=1   -> ok
      $ go test ./cmd/nova-bus/ -run 'TestWaitWritesLeaseOnExit' -count=1 -> ok
    The awake side prints:
      FRIEND rowan awake age=500 source=bus-beat
      AWAKE OK friends=1 awake=1 asleep=0 unknown=0 window=300

  The one genuine remaining gap was the docs: docs/CLI.md's `nova-wake awake`
  section still described only source `bus-cursor` and never the BEAT lease or
  the `source=bus-beat` line the binary now prints. That section is updated here
  to match the binary (and docs/SPEC-WAKE.md, which was already correct).
