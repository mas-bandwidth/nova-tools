The issue, verbatim (the card, on commit a041498 the day #455 landed)
----------------------------------------------------------------------
Help pinned (before #494/#496):
  nova-tokens sum     --out <dir> --month <YYYY-MM> [--max <n>]
no --swarm-root, no --day, and --out for the second sum form is the LEDGER FILE, not a directory.

Worse: --out a directory returned, exit 2:
  SUM REFUSED: --out /tmp/johnny-sum-out: rename /tmp/johnny-sum-out.tmp /tmp/johnny-sum-out: file exists
With a file (ledger.tsv) the same flags returned exit 0:
  SUM OK day=2026-09-15 models=0 cards=0 in=0 out=0 usd=0.0000

Expected: Help names --swarm-root and --day; --out a directory refuses by name (file vs directory), not by the OS rename error.

Smallest fix: one usage line for swarm-root mode; refuse --out that is an existing directory before the tmp rename. Test: help mentions --swarm-root; --out a dir exits 2 naming directory vs file.

The smallest change (the fix)
------------------------------
In cmd/nova-tokens/main.go the usage block at line 53 needs the --swarm-root continuation aligned to the verb column (2-space indent, 22-space continuation, exactly as the existing report/sources bug already does):
  -                       --swarm-root <dir> --day <YYYY-MM-DD> --out <ledger.tsv>

In cmd/nova-tokens/sumswarm.go writeLedger, refuse --out that is an existing directory before os.Rename gets that bad "file exists":
  + if fi, err := os.Stat(path); err == nil && fi.IsDir() {
  +     return fmt.Errorf("--out is a directory; it must be a file, the ledger path (<ledger>.tsv), not a directory")
  + }

Nothing else changes -- no other binary output line moves.

The SPEC, byte for byte with what the binary now prints
-------------------------------------------------------
Binary, help banner, lines 52-53 of cmd/nova-tokens/main.go:
  nova-tokens sum     --out <dir> --month <YYYY-MM> [--max <n>]
                      --swarm-root <dir> --day <YYYY-MM-DD> --out <ledger.tsv>

docs/SPEC-TOKENS.md, lines 446-462 ("The verbs" block). The SPEC used the same verb-only block (no leading 2-space indent, 20-space continuation) and only listed the month-sum form for `sum`. Adding the same continuation as the binary:
  nova-tokens sum     --out <dir> --month <YYYY-MM> [--max <n>]
                      --swarm-root <dir> --day <YYYY-MM-DD> --out <ledger.tsv>

That brings the SPEC verb block in step with what the binary prints on `nova-tokens help` (the existing drift between SPEC (0 leading) and binary (2 leading) on this block predates this card and is unchanged).

docs/CLI.md has no usage block for nova-tokens; the section is prose that names every verb and the things a first run gets wrong. No byte-for-byte update needed.
