# CARD-8049: nova-review --reuse rejects its generated packet (issue #614)

## Issue
When `st.Base` is a branch name like "main" (not a SHA), the packet header writes `base=main`,
but the parser (`parsePacketFirstLine`) requires `base` to be a 40-character SHA. This causes
the generated packet to fail its own `--reuse` validation.

## Red test output (verbatim)
```
--- FAIL: TestPacketBaseIsSHAWhenLaneBaseIsBranchName (0.26s)
    main_test.go:1084: cannot parse first packet header: invalid base field "main": must be 40-character sha
FAIL
FAIL	github.com/mas-bandwidth/nova-tools/cmd/nova-review	0.262s
FAIL
```

Failing line: `main_test.go:1084: cannot parse first packet header: invalid base field "main": must be 40-character sha`

Needs fix at: `cmd/nova-review/main.go:311` (Base field in assembleBody header)
Also at: `cmd/nova-review/main.go:214` (packetID computation uses branch name)
And: `cmd/nova-review/main.go:220` (reuse validation compares hdr.Base vs branch name)

## Root cause
In `packet()`, `base` starts as `st.Base` (e.g., "main"), and `baseSHA` is resolved to the actual SHA.
When there's no prior read, `base` remains the branch name while `baseSHA` is the SHA. The packet
header uses `base` (the branch name) for the `Base` field, but the parser requires a 40-char SHA.

## Fix
Use `baseSHA` instead of `base` for:
1. The `rangeText` computation (line 211) — uses SHA short form for valid range format
2. The `packetID` computation (line 214) — ensures ID matches header
3. The reuse validation at line 220 (`hdr.Base` vs `baseSHA`) — ensures match
4. The `Base` field in packet header assembly (line 311) — ensures header is parseable

## Green test output (after fix)
```
ok  	github.com/mas-bandwidth/nova-tools/cmd/nova-review	2.165s
```
