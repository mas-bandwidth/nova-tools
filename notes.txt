CARD-8098 / issue #194 (retained report item P6-F15): internal/oneline/audit does not
model indexed format arguments, and reports them as the wrong defect.

Red test (before the fix), verbatim:
  --- FAIL: TestVerbsOfModelsIndexedArguments (0.00s)
      audit_test.go:27: verbsOf("%[2]s %[1]d") = "[[", want "ds"
      audit_test.go:27: verbsOf("%[1]q") = "[", want "q"
      audit_test.go:27: verbsOf("%[2]d") = "[", want "\x00d"
  FAIL
  FAIL	github.com/mas-bandwidth/nova-tools/internal/oneline/audit	0.002s
  FAIL

Root cause: verbsOf read the '[' of Go's explicit argument index (%[2]s) as the verb
itself, so a correctly-indexed format was classified verb-by-verb as `%[` and every
argument it held was reported as a raw print needing an escape -- the wrong defect, and
the one bug that turns a correct format into a false positive.

Fix (smallest change):
  - internal/oneline/audit/audit.go verbsOf: honour %[n] (and its 1-based index),
    return verbs indexed BY ARGUMENT POSITION (0 = no directive reads that argument)
    plus the directive count, so the classifier pairs each verb with the argument it
    formats even when directives reorder; a leftover argument no directive names is
    skipped rather than classified.
  - internal/oneline/audit/audit.go PrintedArguments: pair verbs[i] by position,
    skip unreferenced arguments, and guard count with the directive count.

Docs: no change. This is the source-level tripwire, not a binary; no command's printed
line changes, so docs/CLI.md and every SPEC are byte-for-byte as before. No indexed
format exists in the tree yet, so no existing diagnostic or output line moved.

Verifier run: `go vet ./internal/oneline/audit/` clean; the audit tests of every cmd/*
binary still pass unchanged (all ok).
