CARD-8067 — nova-tools issue #465 — nova-swarm native: models on a configured provider
(ollama, inception, zen ids) fail at once with "Unexpected server error" because the
harness config is not carried into the job

THE ISSUE (verbatim, its own words): "nova-swarm native --model ollama/north-mini-code-32k
... exits rc=1 in 0.9 s with the harness printing {\"name\":\"UnknownError\",\"data\":
{\"message\":\"Unexpected server error\"}} ... Cause: the clean environment of #400 gives
the harness a job-local XDG config that carries auth.json (--auth) but not opencode.json, so
every configured provider is unknown." Smallest fix demanded: "native --config <opencode.json>
(default: none) copies the file beside the carried auth file with mode 0600 and prints
config=<sha8> on NATIVE OK; refuses with one line if the file names a provider whose key is
absent from --auth (name the provider, never the key). Test: TestNativeCarriesProviderConfig
(a fake harness asserts the file is present in its XDG config dir). Sequence test:
TestFriendSequenceLocalModelCard."
