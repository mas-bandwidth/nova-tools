Interpretation: the issue is a token-efficiency iteration on `nova-bus wait`.
Today a wait return prints the whole INBOX frame (SCOPE / OPEN / OK) beside
WAIT OK, ~200 tokens per wake. The fix adds `--quiet-beats`: when the change
since the cursor is ONLY beat and/or cursor (state) files — no note — the wait
returns with a single WAIT line (WAIT OK new=0) and no INBOX frame.

A default wait still ignores beat/cursor-only changes (they are not notes, so
r.New stays 0 and it keeps blocking); --quiet-beats opts into the cheap
presence wake. Existing tests are unaffected because none passes the new flag.
