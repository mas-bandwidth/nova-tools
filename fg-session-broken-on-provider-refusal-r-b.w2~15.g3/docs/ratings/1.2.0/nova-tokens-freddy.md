# nova-tokens READ and USE rating, nova-tools 1.2.0

Rater: Claude Opus 5.5 in Claude Code, a sprint worker on a friend's re-rate card
Build: e26adab23ab1
READ: 7/10
USE: 7/10

No v1.2.0 tag exists on the forge yet, so this rates the release candidate at the head of sprint/mechanical-2026-10-02. `nova-tokens version` prints `nova-tokens v1.0.1-0.20261006143828-e26adab23ab1 linux/amd64 go1.26.6`. Built and run on a Linux bench machine, in a scratch directory made for the trial; no live store, no server. Every verb ran: fold, check, sum, sources, report (local mode, with and without `--note` and `--dry-run`), session, profiles, ledger `--dry-run`, and ledger against a closed port to see its failure. The Redis summary mode of report was not run, because it needs a store.

## Reasons

READ. The banner answers what the tool is in its first line, then how it works, a usage block for all nine verbs, the exit table, the environment rule, the dash rule, the shrink rule, the overlap rule, a ten-line setup and six example lines. Every rule an AI needs to trust a number is there in plain words: a dash is not a zero, exit 1 still writes, a day that would shrink is refused, two sources of one provider sharing message ids are refused. Every verb answers `-h` with its usage excerpt, its example, an `effect:` line that says what it writes, and its flags. That is the right shape.

What keeps READ at 7. The banner is about 160 lines (cmd/nova-tokens/main.go:49 to main.go:203) and the reader must finish it before the first command, because the first-run instructions sit at line 50 but the lines they point at sit at line 170. Several sentences in it are not true or do not parse. `--timeout is the one flag with a default` (main.go:105), while `--weights` defaults to `1,1.25,0.1,5` and session's `--day` defaults to every stamped day; the 1.1.0 rating named this and it is still there. The report mode line (main.go:64) says the same thing three ways in one sentence: "giving both --who and --redis selects the store mode (--redis wins); a mix of --who and --redis prints the store summary". The bare-verb refusal says "sources is the one that only looks" (main.go:249) when sum, check and profiles also only look, and docs/CLI.md:1743 repeats it. Every `-h` ends with the whole seven-line exit paragraph, including `version -h`, whose verb can fail none of those ways. `report -h` lists `--bus` and `--swarm`, which the report usage line does not name. `session -h` says `--role` books the row as `<model>/<role>` but not that the role also replaces the repo cell, which only the spec (docs/SPEC-TOKENS.md:489) says. `--timeout <int>` in `-h` does not show its default. The docs drift from the binary: docs/CLI.md:1730 says the help has "one setup command" (it has ten lines) and that the environment has "two exceptions" (the banner names three); docs/USAGE.md:186 still says "there are no defaults and no environment variables"; README.md:54 still calls the commands 1.0.0 and installs `@v1.0.0`. docs/CLI.md:1726 is one 2,631-character paragraph, about the same size as the 2,642-character one the 1.1.0 rating named.

USE. The setup and all six example lines ran as printed and each exited 0 with a typed line: `TOKENS OK`, `CHECK OK`, `SUM OK`, `SOURCES OK`, `REPORT OK`. The safety rules hold when tested. Two `--claude` sources over copies of one transcript were refused before anything was written (`TOKENS REFUSED: two declared sources fed the same 1 message ids (claude:a and claude:b)`), which fixes the 1.1.0 rating's top finding. Making the transcript unreadable, then deleting it, left the day file byte-unchanged with four `TOKENS SHRANK` lines and exit 1, and `--dry-run` printed the same plan with `dry_run=true`. A second fold that declared only some of a row's sources was `TOKENS PARTIAL`, not a quiet overwrite. `check` on an empty `--out` is `CHECK FAILED`, not a green over nothing, and `--strict` and `--through` named the gaps and the stale end. `sum --max 1` printed a `SUM MORE` line with the command that shows the rest. Refusals name every missing flag in one run.

What keeps USE at 7. The banner's own first run double-counts. The setup copies the transcript to `./session.jsonl`, the example folds the transcript, then runs `session --claude-session ./session.jsonl --out ./out`, which adds the same message (id `example-1`) a second time as a `claude-session` row on repo `unattributed`. `check` then says `CHECK OK` and `sum` says `SUM TOTAL input=1624` for a day that spent 812, against the banner's promise that "check and sum never see a doubled day". The overlap refusal works between two `--claude` flags but not between fold and session, which merge into one day file. `report` with an unreadable declared source prints `REPORT OK` and exits 1, and its `--json` says `"status":"failed"`, so the text line and the JSON disagree. `sum` over an `--out` with no day file is `SUM OK days=0` exit 0, and `profiles` over an empty root is `PROFILES OK models=0` exit 0, while `check` calls the same emptiness a failure. The 1.1.0 machine-interface findings are still there: `--json` gives one fact two types (sum's `"input":"812"` and `"turns":"1"` are strings beside `"days":1`, fold's source item has `"files":"1"`, session's are all numbers); missing-flag and bad-value refusals point at `nova-tokens help` instead of the verb's `-h`; `report --dry-run` puts `dry_run=true` on stderr, so a caller capturing stdout never sees it; `version --json` says `got 1` without naming the flag; and the `REPORT OK` line still carries `at=` and `build=` twice, the second pair inside an unquoted `subject=` with spaces. The overlap refusal's remedy, `run: nova-tokens fold ... without --claude b`, cannot be pasted. session's `TOKENS DAY` line says `day=` where fold's says `date=`.

A ten needs: the overlap rule across fold and session so the banner's own example cannot double a day; one status word per exit; one JSON type per fact; every refusal pointing at the verb's `-h`; a banner whose first run comes before its rules; and docs that say what the binary does.

## Good, keep

The overlap rule now refuses two declared sources that share message ids before any file is written, naming both labels and the count. The shrink rule held under an unreadable and then a deleted transcript: the file was left byte-unchanged and each type was named with what the file said and what the sources say now. `--dry-run` is the real run's plan, refusals included. `check` cannot go green over an empty directory, and `--strict`, `--no-spend` and `--through` turn gaps into findings only when asked. A dash is never a zero, in the day file, in sum and in report's `usd=`. The verbs now live in their own files: main.go is 696 lines, down from 1,563, and fold is cmd/nova-tokens/fold.go.
