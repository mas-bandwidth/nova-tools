# Account route certification

DSHAccountRoute is a bounded companion to FriendSetupLifecycle. The truth remains the owned public route patch and existing RUN/PROFILE binding; the model introduces no receipt or index. Its 22 finite variables occupy a few hundred bytes per state. Two route epochs cover a successful setup followed by a newer failed proof attempt.

Read-only planning changes no configuration or durable proof. Explicit apply initializes absent static configuration, writes the exact account provider/model route, completes native route schema validation without extra overlays, then rechecks the exact effective route before publishing a PROFILE bound to that RUN. A static-only PROFILE or matching patch alone cannot skip schema validation. A newer attempt invalidates the older PROFILE for current use, even when the file remains on disk. Reuse and local inspection require the current account certificate and a fresh exact effective route check. Inspection acceptance means local route metadata passed; it does not activate a daemon or prove authentication.

Authentication remains unknown and provider-turn remains not_checked. Implicit model routing, API key substitution, inferred authentication, publication before successful schema validation, overlay acceptance, drift between schema and publication, stale inspection, and static-certificate reuse each have a distinct reversed invariant case. Three reversed reachability cases require fresh setup inspection, certified reuse, and refusal after a newer failed epoch. Correct controls include absent, static-only, and already certified initial states.

Native actions abstract the existing owned durable setup runner. This model does not repeat process-group, lock, launch-gate, or file atomicity proofs from FriendSetupLifecycle. Schema success is a public validation result, not an authentication or paid provider request. Outside route drift remains possible after publication; inspection checks the route again. The bounded model alone does not prove the Go implementation or an installed helper.

The source bridge is setup_dsh_init.go and setup_dsh_route.go: static initialization precedes the public route write; canonical ReadSetupProfile requires a current RUN and exact full SetupOptions; account-route-schema validates the native schema; effective-account-route inspects the exact patch and absence of effective overlays before publication/use. Source tests must distinguish a matching failed patch from a certified epoch, old static selection from account selection, native schema failure from publication, and effective route drift from reuse. No joined runtime trace is claimed by the model cases. Actual native RUN receipt projection remains in the separate generic lifecycle evidence.

Run the dshaccountroute group with tlacheck on a serialized Linux bench and a private Java temporary directory. Measured RUNS rows follow the source freeze; no result is claimed until recorded.

Publication combines the final effective-route read with the publication decision as one bounded action. An external edit after that read is not made atomic by this abstraction; subsequent local inspection checks again. The source audit is a prepublication validation, not a filesystem-wide exclusion theorem.
